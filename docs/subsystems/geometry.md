# geometry (domain)

**Purpose.** The cluster geometry format and its builder (docs/plan/04-renderer.md §4.3, ADR-0005). The cluster is the universal unit of rasterization, streaming, and acceleration-structure construction, so its layout is a contract shared by the content build, the mesh-shader and software-raster paths, the residency manager, and the acceleration-structure builder. This module owns that layout and the CPU-side builder over meshoptimizer.

**Format (v1).** `ClusterDesc` (32 bytes, GPU-mirrored): vertex and triangle offsets and counts plus a bounding sphere. `ClusterMesh` holds the descriptors, cluster-ordered vertex positions (source vertices shared between clusters are duplicated, and `vertex_source` remembers where each came from), a parallel `VertexAttributes` stream (8 bytes per vertex: an octahedral normal in two snorm16, a UV in two half floats; `encode_normal_oct`/`decode_normal_oct`, `encode_half2`/`decode_half2`), and one packed `u32` per triangle holding three 8-bit local indices. Both builders take an optional `AttributeSource` (normals and UVs indexed like the source positions); missing normals are computed area-weighted from the faces (`compute_vertex_normals`), missing UVs are zero, and `fill_cluster_attributes` maps them through `vertex_source`, which also gives every LOD level its attributes because clusterlod keeps original vertices. Limits: at most 255 vertices and 512 triangles per cluster by the format; the builder default is 64 vertices and 124 triangles, which fits one mesh-shader workgroup.

**Builder.** `build_clusters` runs `meshopt_buildMeshlets`, `meshopt_optimizeMeshlet`, and `meshopt_computeMeshletBounds`, then lays the result out in the format above. `validate_clusters` checks the invariants tests rely on: ranges and limits, every source triangle present exactly once (by sorted corner triple), every vertex inside its cluster's sphere.

**LOD DAG.** `build_cluster_lod` (`cluster_lod.h`) runs meshoptimizer's reference cluster LOD builder (`demo/clusterlod.h`: clusterize, partition clusters into groups, simplify each group, repeat until one cluster remains) and lays every level out in the shared format, level 0 first. Each cluster carries a `ClusterLodDesc` (48 bytes, GPU-mirrored) with two spheres and two errors: `own` is the bound of the group the cluster was simplified from (error 0 for original geometry) and `parent` the bound of its own group's simplified output (infinite when the group could not be simplified further). A view-dependent cut is one test per cluster with no hierarchy traversal: render when the projected own error is at or under the threshold and the projected parent error is over it. Errors are monotonic along every DAG path, so exactly one cluster per path passes for any threshold and the cut is crack-free by construction. `lod_selects`, `select_lod`, and `projected_error` are the CPU reference for the GPU pass in `domain/gfx/shaders/cluster_cull.slang` (error / max(distance - radius, znear) * cot(fov/2) * height / 2, in pixels). A 129×129 heightfield (32,768 triangles) becomes 727 clusters in 10 levels (341 leaves down to 1) in about 200 ms; engine-view's 257×257 terrain (131,072 triangles) takes 860 ms for 2,898 clusters in 12 levels.

**Not yet.** Per-cluster 16-bit position quantization, tangents, normal cones for cluster backface culling, attribute-aware simplification, the per-level BVH clusterlod can build over groups (the flat cut is one thread per cluster, which is fine until scenes reach millions of clusters), fixed-size pages ordered by DAG locality, and precomputed cluster-AS inputs.

**Public API.** `domain/geometry/cluster.h`: `ClusterDesc`, `VertexAttributes`, `AttributeSource`, `ClusterBuildOptions`, `ClusterMesh`, `build_clusters`, `fill_cluster_attributes`, `compute_vertex_normals`, `encode_normal_oct`, `decode_normal_oct`, `encode_half2`, `decode_half2`, `validate_clusters`. `domain/geometry/cluster_lod.h`: `ClusterLodDesc`, `ClusterLodOptions`, `ClusterLodMesh`, `build_cluster_lod`, `LodView`, `projected_error`, `lod_selects`, `select_lod`, `select_lod_raw`, `validate_cluster_lod`.

**Depends on.** `base`, `containers`, `math`; meshoptimizer v1.2 (MIT, third_party/LICENSES.md).

**Testing.** `tools/dev.ps1 test -Filter geometry`: grids at the default and at tight limits, a single triangle, rejected inputs, packing helpers, the size tables; attribute encoders round-trip normals to 2e-4 and UVs to a thousandth, computed normals of a flat grid, and attributes following `vertex_source` in both builders; for the DAG, a terrain that validates (level 0 covers the source exactly once, own error never exceeds parent error, raw cuts are never empty and never grow with the threshold), each level smaller than the last, view-dependent cuts that coarsen with distance (full detail up close, a fraction of the triangles far away), the RT configuration, and rejected input. The gfx mesh-shader and cull tests consume the format on the GPU.

**Performance notes.** The builder is a content-build step, not a frame-loop one. The GPU reads `ClusterDesc` and the packed triangle words directly through device addresses; positions are 12-byte floats until quantization lands, which will cut cluster vertex bandwidth by half.
