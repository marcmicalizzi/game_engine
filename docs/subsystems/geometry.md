# geometry (domain)

**Purpose.** The cluster geometry format and its builder (docs/plan/04-renderer.md §4.3, ADR-0005). The cluster is the universal unit of rasterization, streaming, and acceleration-structure construction, so its layout is a contract shared by the content build, the mesh-shader and software-raster paths, the residency manager, and the acceleration-structure builder. This module owns that layout and the CPU-side builder over meshoptimizer.

**Format (v1).** `ClusterDesc` (48 bytes, GPU-mirrored): vertex and triangle offsets and counts, a bounding sphere, and a normal cone for backface culling in meshoptimizer's form (an apex as three floats and one `u32` packing the axis as three snorm8 and the cutoff as a snorm8; `encode_cone`/`decode_cone`, `NormalCone`). A cluster is entirely backfacing when `dot(normalize(cone_apex - camera), axis) >= cutoff`, which `cluster_backfacing` evaluates on the packed values exactly as the GPU pass does; a cutoff of 1 (`k_cone_none`) marks a cluster that is never culled, either because its normals spread too far or because the mesh is two-sided (`normal_cones = false` in either builder's options). Winding is the convention: counter-clockwise seen from outside is the front, the same rule the rasterizer uses. `ClusterMesh` holds the descriptors, cluster-ordered vertex positions (source vertices shared between clusters are duplicated, and `vertex_source` remembers where each came from), a parallel `VertexAttributes` stream (8 bytes per vertex: an octahedral normal in two snorm16, a UV in two half floats; `encode_normal_oct`/`decode_normal_oct`, `encode_half2`/`decode_half2`), and one packed `u32` per triangle holding three 8-bit local indices.

**Quantized positions.** Positions also exist on one 16-bit grid per mesh: `quantized` (three `u16` per vertex, cluster-ordered, parallel to `vertices`) with `quant_origin` at the AABB minimum of `vertices` and `quant_scale` = the largest AABB extent / 65535, so q = round((p − origin) / step) clamped to 0..65535 per axis and a degenerate mesh keeps step 1. `quantize_positions` fills all three; every builder calls it last, so a merged mesh gets one grid over all of its parts rather than one grid per part. `dequantize_position` is the CPU reference for the shaders' `load_position`, and `validate_clusters` checks every vertex is within half a step (a 20-unit terrain quantizes to a 3.05e-4 step, a unit mesh to 1.53e-5, a thousand-unit mesh to 0.0153). **Six bytes of position per vertex instead of twelve** on the GPU: the mesh-shader, vertex, and software rasterizers and the material resolve all read this stream (`gfx::MeshDesc`), so the float `vertices` are uploaded only where the acceleration structure builders need them. The stream is padded with one zero to an even `u16` count so a shader may read the last triple as two whole 32-bit words. Welded meshes stay crack-free: every cluster's copy of a shared source vertex quantizes the same float position on the same mesh-wide grid, so the copies land on the same integer triple and a seam's two sides move by exactly the same amount. Both builders take an optional `AttributeSource` (normals and UVs indexed like the source positions); missing normals are computed area-weighted from the faces (`compute_vertex_normals`), missing UVs are zero, and `fill_cluster_attributes` maps them through `vertex_source`, which also gives every LOD level its attributes because clusterlod keeps original vertices. Limits: at most 255 vertices and 512 triangles per cluster by the format; the builder default is 64 vertices and 124 triangles, which fits one mesh-shader workgroup.

**Builder.** `weld_vertices` comes first when the source is an exported file: it merges vertices whose position, normal, and UV are bit-identical and drops unreferenced ones (meshoptimizer's multi-stream remap), because exporters write unindexed or seam-split meshes and the 64-vertex cluster limit then caps clusters at 21 triangles with no shared edges for the LOD builder to collapse (Suzanne: 11,808 vertices become 2,012 and 188 leaf clusters become 42; the SciFiHelmet: 70,074 become 14,085). Vertices that differ in any attribute stay apart, so seams keep their normals and UVs. `build_clusters` runs `meshopt_buildMeshlets`, `meshopt_optimizeMeshlet`, and `meshopt_computeMeshletBounds`, then lays the result out in the format above; the LOD builder computes the same meshlet bounds on each cluster's local indices because clusterlod's own bounds carry no cone. `validate_clusters` checks the invariants tests rely on: ranges and limits, every source triangle present exactly once (by sorted corner triple), every vertex inside its cluster's sphere, and every non-degenerate face normal inside its cluster's cone (within the half-angle whose sine is the cutoff, with slack for the snorm8 packing).

**LOD DAG.** `build_cluster_lod` (`cluster_lod.h`) runs meshoptimizer's reference cluster LOD builder (`demo/clusterlod.h`: clusterize, partition clusters into groups, simplify each group, repeat until one cluster remains) and lays every level out in the shared format, level 0 first. Each cluster carries a `ClusterLodDesc` (48 bytes, GPU-mirrored) with two spheres and two errors: `own` is the bound of the group the cluster was simplified from (error 0 for original geometry) and `parent` the bound of its own group's simplified output (infinite when the group could not be simplified further). A view-dependent cut is one test per cluster with no hierarchy traversal: render when the projected own error is at or under the threshold and the projected parent error is over it. Errors are monotonic along every DAG path, so exactly one cluster per path passes for any threshold and the cut is crack-free by construction. `lod_selects`, `select_lod`, and `projected_error` are the CPU reference for the GPU pass in `domain/gfx/shaders/cluster_cull.slang` (error / max(distance - radius, znear) * cot(fov/2) * height / 2, in pixels). A 129×129 heightfield (32,768 triangles) becomes 727 clusters in 10 levels (341 leaves down to 1) in about 200 ms; engine-view's 257×257 terrain (131,072 triangles) takes 860 ms for 2,898 clusters in 12 levels. `merge_cluster_lod` joins DAGs built over parts of one mesh into one (streams concatenated, offsets and group indices shifted, level counts added, every level-0 cluster first) and reports which part each cluster came from; engine-view builds one DAG per glTF primitive so that every cluster has a single material, at the price of clustering and simplifying each material's triangles on their own.

**Cluster file.** `cluster_file.h` is the `.clusters` container `engine-content build` writes and the renderer loads instead of importing glTF and clustering at startup (docs/plan/07-content-pipeline.md §7.3): one `ClusterLodMesh`, a material index per cluster, the materials as a 64-byte GPU-shaped record (`ClusterFileMaterial`: base color, metallic, roughness, base-color and normal image slots, and 32 bytes of zero padding for the fields that follow), and the image paths those slots name, as the source gave them (an embedded image keeps its slot with an empty path). The layout is a 32-byte header — magic `CLST`, version, flags, section count, total bytes, content hash — then a table of `{kind, element_size, element_count, offset}` records, then the payloads, each at a 16-byte aligned offset from the start of the file. Little-endian, no pointers, every section an array of one fixed-size element that the reader and the writer move with `memcpy`, so a mapped file is already the bytes the GPU wants. The kinds (1 clusters, 2 lod, 3 vertices, 4 attributes, 5 triangles, 6 vertex_source, 7 level_cluster_counts, 8 cluster_material, 9 materials, 10 image_paths, 11 strings, 12 scalars, 13 quantized positions as `u16` triples, with the grid origin and step in the scalars record) are fixed and append-only, and **a reader skips a section whose kind it does not know**, so a file written by a newer build still loads as long as the sections this build requires are present; removing a required kind or changing an element's layout is a version bump. Everything that can be wrong is refused with its own message and leaves the output empty: a truncated file, the wrong magic, an unsupported version, a section that runs past the end, a content hash that does not match, a missing required section, or counts that do not agree. The hash (`core/hash`'s `hash_bytes`) covers every byte after the header, so it pins the section table as well as the payloads, and `cluster_file_hash` computes the same value from a `ClusterFileData` in memory: that is the identity the derived-data cache addresses a built mesh by. Writes go through `io::write_file_atomic`, so a reader sees the old bytes or the new ones and never a mix. Suzanne is 167 KB (88 clusters in 7 levels), the FlightHelmet 4.2 MB (2,348 clusters in 10 levels).

**Not yet.** Quantized positions for the acceleration structure builders (`gfx/acceleration.h`, `gfx/cluster_acceleration.h` and engine-view's `--raster rt` still read the float `vertices`, which is why both streams are kept; the builders take a vertex format, so this is a format change, not a shader change), per-cluster grids finer than the mesh-wide one, tangents, attribute-aware simplification, the per-level BVH clusterlod can build over groups (the flat cut is one thread per cluster, which is fine until scenes reach millions of clusters), fixed-size pages ordered by DAG locality, and precomputed cluster-AS inputs.

**Depends on.** `base`, `containers`, `math`, `hash` (the container's content hash), `io` (atomic writes and reads); meshoptimizer v1.2 (MIT, third_party/LICENSES.md).

**Testing.** `tools/dev.ps1 test -Filter geometry`: grids at the default and at tight limits, a single triangle, rejected inputs, packing helpers, the size tables; attribute encoders round-trip normals to 2e-4 and UVs to a thousandth, computed normals of a flat grid, and attributes following `vertex_source` in both builders; cone packing round-trips with the cutoff rounded up, a 2,208-triangle sphere gives 80% of its clusters a cone, a camera at four radii finds 20% to 60% of them backfacing (never one facing it, always one on the far side), the center sees the back of nearly all of them, cones switch off, and a cone pointed inward fails validation; welding folds an unindexed grid's 384 corners back to its 81 vertices with every corner still on its position, keeps a corner with a different normal apart, and drops an unreferenced vertex; quantization gives a unit grid a 1.53e-5 step and a 3.05e-5 one to a sphere, both within half a step everywhere, the same grid a thousand units across a 0.0153 step, an even `u16` count no larger than 3 per vertex plus one, identical integer triples for every copy of a shared vertex, and a degenerate mesh the identity grid; for the DAG, a terrain that validates (level 0 covers the source exactly once, own error never exceeds parent error, raw cuts are never empty and never grow with the threshold), each level smaller than the last, view-dependent cuts that coarsen with distance (full detail up close, a fraction of the triangles far away), the RT configuration, rejected input, and two terrains merged into one mesh that validates against the shifted source indices, keeps its leaves first, names each cluster's part, cuts to the union of the parts' cuts, and carries one grid coarser than either part's over the whole thing. For the container, a terrain DAG wrapped with two materials and two image paths is written, read back, and compared array by array (and the result revalidated), reading the same bytes from memory gives what reading the file gives, the header's hash is the one `cluster_file_hash` computes, every payload offset is 16-byte aligned and inside the file, a section of an unknown kind inserted by the test is skipped, and a truncated file, a wrong magic, an unsupported version, a section moved past the end, a flipped payload byte, and a required section renamed away each fail with their own sentence and an empty result. The size table pins the header, the section record, the scalars, and `ClusterFileMaterial`, which are the format itself. The gfx mesh-shader and cull tests consume the format on the GPU, and `tools/dev.ps1 test -Filter engine_content` builds a container end to end.

**Performance notes.** The builder is a content-build step, not a frame-loop one. The GPU reads `ClusterDesc`, the packed triangle words, and the quantized positions directly through device addresses; the 16-bit grid halves position bandwidth and footprint (6 bytes a vertex instead of 12) at a cost of under two thousandths of a pixel at 320×240 on a 20-unit terrain.
