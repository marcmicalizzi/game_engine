# content_class

**Layer:** foundation. **Not a capability**: no `ENGINE_WITH_` switch and in every configuration, `ENGINE_MINIMAL` included, because a build switch is what [ADR-0033](../adr/0033-content-classes-and-view-policies.md) forbids as the mechanism of a view policy ([ADR-0073](../adr/0073-classes-travel-with-derived-data-and-policies-are-the-operators.md) decision 9). Its dependencies are `base`, `containers`, `hash`, `json`, `schema` and `schemas`, none of them a capability. Roadmap C61; the design and the rows that build on it are [content classes](../content-classes.md).

## Purpose

The vocabulary of content classes and view policies, and **the one decision every output calls**: given what a mesh is classified as and the policy of the view it is being instantiated for, admit it, omit it, or put a proxy in its place. Nothing calls it yet. The content build (C62), the record and the store (C63), `load_scene` (C64), the hosts (C65) and the refusals (C66) are the callers, and each calls this function rather than a test of its own, so that a policy means the same thing at every one of the twenty-four exits.

## Owned data

- **`ContentClasses`**: a level per category, sixteen bytes, one byte per category indexed by the category's place in a `Categories` table. All zeros is `none` everywhere, which is what an asset that declares nothing has. It is dense rather than a list of (category, level) pairs because a join of two dense values cannot overflow and a decision is a loop over a fixed size; the price is the limit below.
- **`ViewPolicy`**: a cap and a `Substitution` per category, thirty-two bytes. Zero-initialized it is every category capped at `none` with `omit`, which is what ADR-0033 decision 2 says a category a policy does not mention gets, so a policy read from a file starts there and only the categories it names are set.
- **`Decision`**: the outcome (`admit`, `omit`, `proxy`) and the category, level and cap that decided it, four bytes. A refusal later reports those three; it never needs anything about the content itself.
- **`Categories`**: the engine's three ladders compiled in, `nudity` (`none`, `partial`, `full`), `sexual` (`none`, `suggestive`, `explicit`), `violence` (`none`, `mild`, `graphic`), at indexes 0, 1, 2, then a game's categories from its `engine.content.ContentCategoriesFile`. Names live only here; a value holds indexes.
- **`ViewPolicies`**: the operator's named policies from an `engine.content.ViewPoliciesFile`, with `agent-default` compiled in first. Each `NamedPolicy` holds its resolved `ViewPolicy` and, in `by_name`, every cap the file gave a category that is not the engine's, by name (`NamedCap`), because a host learns a game's category only when data brings it.
- **`DecisionTable`**: the table a loaded scene keeps (C64's `SceneData::decisions`): the policy it was made under, and every distinct class it decided with its `Decision` (`DecisionEntry`, twenty bytes). It starts with the all-`none` class admitted and only grows, so its length is its generation.

The file shapes are schema types in `schemas/provenance.schema` (`ContentClasses` and `MaterialContentClasses` for a sidecar's `content_classes`, `ContentCategory` and `ContentCategoriesFile`, `ViewPolicyCap`, `ViewPolicy` and `ViewPoliciesFile`). None of them is a document record (`@kind(record)`), so no protocol method can make one in a document.

**Limits, stated**: at most `k_max_categories` (16) categories in all, the engine's three included, and at most 255 levels to a ladder. A categories file that would pass either is refused with the number in the reason.

## Invariants

- **`decide` is pure, total and allocation-free.** Within every cap it admits. Otherwise it omits if any category above its cap is substituted by `omit`, and puts a proxy in place only when every category above its cap says `proxy`: `omit` is the stricter, and wins whatever the order. A level past a ladder's top is above every cap.
- **An all-`none` class is one branch.** `decide` tests the sixteen bytes first and returns before it looks at the policy.
- **`join` is the per-category maximum**, so a thing built from several inputs is at least as classified as each.
- **`narrow` never widens.** Per category it takes the lower cap and the stricter substitution, so a narrowed policy admits nothing either input refused and omits whatever either would omit. A per-call narrowing (C65) is this function with the caller's effective policy.
- **A category neither table defines is refused** when a sidecar's classes are read (`read_classes`), because a level that cannot be ordered cannot be capped. **A level a ladder does not have is read as its highest**: an unknown level fails closed. **A class declared per material is the asset's too**: `read_classes` validates every material's levels like the asset's and joins them into its output, because v0 decides per mesh, and hands back each material's own (`MaterialClass`) for the part-wise substitution of C11 and C12. **A class that cannot be read is never `none`**: every refusal of `read_classes` writes `unreadable(categories)`, every category the table knows at its ladder's top, into its output, so a caller that ignores the answer still fails closed. **A key given twice is refused**, in a sidecar, a categories file and a policies file, anywhere in the text: every reader here parses with `core/json`'s strict mode (`refuse_duplicate_keys`) and names the key and its line, because the parser's ordinary rule, the last one wins, would let a text merge or a tool's append declare a class or a cap and silently lose it. `read_sidecar_classes` is the one reader of a sidecar's text.
- **A game's ladder starts at `none`**, because absent means `none` (ADR-0033 decision 1). A game cannot redefine an engine category: its name is already taken, and the file is refused.
- **A policies file that is wrong is refused whole**, the set unchanged, with the reason: a policy with no name, a name given twice, a category name outside `[a-z0-9_]` (or `levels`, `materials`) or capped twice in one policy, an engine category's cap its ladder does not have, a substitution that is not one of ADR-0033's four names, and `cover` or `obscure at capture`, which are not built until the character work (C11, C12) builds slots and section masks ([content classes](../content-classes.md#what-decided-at-instantiation-means)). Unknown fields and a value of the wrong type (a number or an object for a cap) are refused too.
- **A policy caps a game's category by name.** A host is given no categories file and learns a game's category from the data that carries it, so a policies file read at its start names categories it has not met. An engine category's cap is checked at the read; any other is kept as a `NamedCap` and applied by `resolve(named, categories)` once the table holds the category: its cap's level, or `none` with `omit` when the ladder lacks that level. The page says only "`none`" for that case; the module takes `omit` with it, because a cap naming a level the operator's category does not have is a cap nobody meant, and the stricter reading of the whole of it is the one that cannot widen. A misspelt category is never met and stays `none` with `omit`. A resolution clears every game category before it applies the caps, so a policy resolved against one table and then another keeps nothing of the first. **The caller resolves after every ladder it learns and before it decides a class naming the new category** (`ViewPolicies::resolve`), and no class can name a category before its ladder is in the table, because the class is read against that table.
- **The class hash is over names.** `class_hash` writes a length-prefixed canonical text, every category above `none` in the class or a material sorted by name with its whole ladder, then the class's (category, level) names, then every classified material by name with its pairs, and hashes it with `core/hash`'s `hash_bytes`, the family `cluster_cache_key` already mixes with. So a game that reorders its categories keeps the hash, one that renames a level or reorders a ladder changes it, and the same text gives the same bytes on every toolchain. **It is zero when nothing is classified**, so a cache key that mixes it in only when it is not zero keeps every unclassified source's key; it is never zero otherwise. The engine categories' ladders are written too, though they are compiled in: the rule is then one, and a change to a compiled-in ladder moves the key, as it should.
- **A scene's decisions are compared outcome for outcome.** `same_decisions(table, policy, from)` is true when `policy` decides every entry from `from` on as the table did. "Within the cap" is not the test, because a caller whose policy omits would receive the box the scene drew, and a wider caller a picture missing what it may see. A capture checks from 0 before its first frame and from that check's generation after its last.
- **`wider_than(policy, base)` is `narrow(policy, base) != policy`**: a cap above `base`'s, or `proxy` where `base` omits, counts, even in a category no content names.
- **`agent-default` is never redefined by a file**, wider or narrower. The design compiles it in as the policy every host runs unless its operator says otherwise, and as the one a credentialed connection falls back to rather than the host's own ([content classes](../content-classes.md#where-a-policy-lives-and-what-keeps-it-from-a-client)); a file that could redefine it would move that fail-closed floor silently, so the name is reserved and a file naming it is refused as a duplicate. The design does not address the case in words; this is the reading that keeps its fallback where it says it is. An operator who wants more for an agent names a policy of their own.

## `agent-default`

Its caps are ADR-0033 decision 7's: `nudity: none`, `sexual: none`, `violence: mild`, every game category `none`. **What it puts in place of content above a cap is the owner's decision of 2026-11-18** (ADR-0073, question 2, "Box, as proposed"): `proxy` for `nudity` and `sexual`, so that an agent's picture keeps the framing, silhouette and place of a thing as a plain box at its bounds, and `omit` for `violence` (`k_agent_default_substitutions`, one per engine category). **A game's category is `omit`** (`k_agent_default_game_substitution`): the owner's answer named the engine's three, a game's category is one nobody has judged a box to be harmless for, and `omit` is the stricter of the two answers. The module was built with `omit` everywhere until the answer came. The test "agent-default is ADR-0033 decision 7's caps and the owner's substitutions" pins the two constants, the policy they build, and what it decides for one class in each category.

## What its second leg mended and added

A review of the module and of the design found three faults in the readers built here, and the design's second pass ([content classes](../content-classes.md), revised 2026-11-18) needed vocabulary the module did not have. Both are C61's second leg, CPU only. **Built 2026-11-18**: written first without a compiler and then built, in `msvc-debug`, `msvc-minimal` and `msvc-no-ecs`; every test named below passes in each, driverless (the module opens no device).

**The three faults, each with the test that fails before its mend:**

1. **Mended: a class declared per material was never read** (test "a class declared per material is read and joined into the asset's"). `read_classes` looped over `declared.levels` and ignores `materials`, so `{"materials": {"m0": {"levels": {"fixture_glow": "bright"}}}}` reads as `none` and `decide` admits it. The mend validates every material's levels exactly like the asset's, joins them into the asset's class (v0 decides per mesh), and gives the per-material values as a second output for C11 and C12. Tests: a class only under `materials` decides `omit` under `agent-default`; an unknown category under `materials` is refused; a material's level unknown to its ladder reads as the top.
2. **Mended: a refused read left its output untouched** (tests "the unreadable class is every known category at its top" and the read_classes case's refusal), and the test "untouched" pins it, so a caller that starts from `ContentClasses{}` and ignores the answer admits the asset. The mend writes **the unreadable class** into the output on every refusal: every category the table knows at its ladder's top (`content_class::unreadable(categories)`, also what the load uses for a sidecar it cannot read). Tests: the "untouched" pin becomes "unreadable"; a refused read decides `omit` under `agent-default`.
3. **Mended: a duplicate key kept the last value** (test "a key given twice is refused in a sidecar, a categories file and a policies file"; `core/json`'s "the strict mode refuses a key given twice, naming it"). The JSON parser's `insert_or_assign` resolves `{"levels": {"fixture_glow": "bright", "fixture_glow": "none"}}` to `none`, and a policy's `"cap"` given twice to its second. The mend gives `core/json` a strict mode that refuses a duplicate key, naming it (its default unchanged, so no other reader moves), and every reader in this module uses it. Tests: a sidecar, a categories file and a policies file, each with a key given twice, refused naming the key; `core/json`'s own tests keep the default and test the mode.

**The vocabulary the second pass needs, each with its test:**

- **One sidecar reader of both forms**, `read_sidecar_classes`: the schema's form (`levels`, `materials`) and the generation tools' flat map (category to level, read as `levels`); a mix of the two refused; `levels` and `materials` reserved as category names. Test "a sidecar's classes are read in both forms": each form read; the tools' flat map at `none` reads as `none`; a mix, a level of the wrong type and a `content_classes` that is not an object refused.
- **Category names are `[a-z0-9_]`**, in a categories file, in a policies file and in data (`Categories::valid_name`). Test "category names are [a-z0-9_], and ladders are learned from data": `Nudity`, `nudity `, a name with a tab, `levels`, `materials` and the empty name refused.
- **Ladders that arrive with data** (`Categories::learn`). A host's table learns a game category and its ladder from the data that names it; the same ladder again is accepted; another ladder for a known name, or another ladder for an engine category, is refused, which makes that data's class unreadable; a seventeenth category is refused. Same test, one case each.
- **A policy caps by name** (`NamedCap`, `resolve`, `ViewPolicies::resolve`; the invariant above). Test "a policy caps a game's category by name, resolved when its ladder arrives": a policy capping `fixture_glow` read with no categories file and resolved when the ladder arrives; a cap naming a level the ladder lacks resolving to `none` with `omit`; a game category the policy does not name, learned after the read, staying `none` (the review's "a policies file read before a game's categories are added"); resolution idempotent and, against a second table, leaving nothing of the first; a misspelt category narrowing. The policies file's refusals keep an engine category's unknown cap.
- **The canonical class hash** the cache keys mix in (`class_hash`). Test "the class hash is over names, and nothing classified has none": the same class at other indexes hashes the same; a renamed level, a reordered ladder and another level each change it; nothing classified is zero, with or without neutral materials; materials count by name in any order. Two values are pinned, taken on MSVC at v3 from the hash's first build, so that a change to the form or to `hash_bytes` is seen; the form is text and `hash_bytes` reads little-endian words, so GCC and Clang must give the same.
- **The decision table** (`DecisionTable`, `same_decisions`). Test "the decision table, and same_decisions outcome for outcome": the first entry and the table's growth; true under the table's own policy and under one that differs only where nothing was met; false under one that omits where the table proxied and under a wider one; the second check over new entries only.
- **`wider_than`**. Test "wider_than agent-default": `agent-default` is not wider than itself, nor the narrowest policy, nor a lower cap; a higher cap, a game cap and `proxy` where `agent-default` omits are; no policy narrowed by `agent-default` is wider than it, over 500 random policies.

**The cases the review found uncovered**, added in the same leg: exactly sixteen categories accepted and a second `add` repeating the first refused, a 255-level ladder accepted and a 256-level one refused, and a number for a level refused in a categories file and in both of a sidecar's forms (test "the limits, exactly at them and one past"); a number and an object for a cap in a policies file (the policies test's refusals); `decide(c, p).outcome == admit` exactly when `within(c, p)` over 4000 random classes and policies with levels and caps up to 255, a refusal naming a category above its cap whose substitution is the outcome (test "decide admits exactly what within holds"); and `narrow` of a policy with every category at its top (test "narrowing a policy with every category at its top").

## Public API

`foundation/content_class/content_class.h`: `ContentClasses`, `is_none`, `join`; `Substitution`, `ViewPolicy`, `within`, `narrow`; `Outcome`, `Decision`, `decide`; `k_agent_default_name`, `k_agent_default_substitutions`, `k_agent_default_game_substitution`, `agent_default`, `wider_than`; `DecisionEntry`, `DecisionTable` (`decide`, `policy`, `size`, `at`), `same_decisions`; `Categories` (`add`, `add_json`, `valid_name`, `learn`, `find`, `name`, `level`, `level_name`, `top`); `unreadable`; `MaterialClass`, `read_classes`, `read_sidecar_classes`; `class_hash`; `NamedCap`, `NamedPolicy`, `resolve`, `ViewPolicies` (`read`, `read_json`, `resolve`, `find`, `at`).

Nothing in the tree reads a categories file or a policies file at run time yet, no host has a flag for one, and no policies file is committed: the tests write theirs as strings.

## What it costs

Where nothing is classified, which is every asset this repository has: sixteen zero bytes a mesh and one test. The bench `engine_content_class_bench` has two rows over 4096 meshes against `agent-default`: `content_class.decide.none` and `content_class.decide.classified`. In `msvc-debug` on 2026-11-18 they measured 262 us and 403 us a pass (about 64 ns and 98 ns a mesh), with other processes using 54% of the CPU and another row holding the GPU lock, so both are upper bounds from an unoptimized build; the test "deciding where nothing is classified costs a branch" prints the same per-mesh figure. After the second leg, the same build later that day: 468 us and 653 us a pass (about 114 ns and 159 ns a mesh), and the test 121 ns a mesh, with other processes using 100% of the CPU and another row holding the GPU lock: upper bounds again, and the second leg changed nothing `decide` runs. A release measurement on a quiet machine belongs with C64's load-time measurement, where the decision's share of a scene's load is the number that matters.

## How to test

`tools/dev.ps1 test -Filter content_class`. The tests open nothing and need no device. Every fixture is neutral: a made-up game category `fixture_glow` (`none`, `dim`, `bright`) and the engine's three categories as names only. They cover the engine's ladders; `agent-default`'s values; `decide`'s table of cases (within the cap, above it under `omit` and under `proxy`, `omit` over `proxy`, a game's category beside the engine's, a level past a ladder's top, a category the policy does not name); `read_classes` refusing an unknown category and reading an unknown level as the top, and leaving the unreadable class on every refusal; a class per material; a key given twice in each file; both sidecar forms; names and learned ladders; `join`; a property test that narrowing never widens, over 2000 random pairs of policies, and one that `decide` admits exactly what `within` holds, over 4000 with levels up to 255; the limits exactly at them and one past; each malformation of a categories file and of a policies file, each refused whole with its reason; caps by name; the class hash; the decision table and `same_decisions`; `wider_than`; and the timed all-`none` decision. The second leg's cases are listed above, each by its test's name.
