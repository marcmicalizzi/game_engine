# window (foundation)

**Purpose.** OS windows, input events (keyboard, mouse, gamepads), and the two pieces of Vulkan glue a window system owns: the instance extensions a surface needs and surface creation. SDL3 (ADR-0012, zlib) sits underneath, statically linked with video, events, and gamepads only; nothing outside this module includes SDL. Headless machines keep working: `init()` reports failure and callers run without a window, which is how the CI runners and `engine-host` behave. This module stays raw — the binding table and the per-tick state a game reads are `foundation/input`'s, and it deliberately does not depend on this one.

**API.** `window::init()` starts the video subsystem (false with the reason on a machine without a display) and then the gamepad subsystem, whose failure is logged rather than returned: a machine with no joystick driver still gets a window. `Window::create(WindowDesc)` opens a resizable, high-DPI-aware window; `pixel_width()/pixel_height()` are the framebuffer size, refreshed on every `Resized` event. `poll(Event&)` pulls one event at a time: `Quit`, `CloseRequested`, `Resized`, focus, `KeyDown/KeyUp` (a small `Key` enum for the common keys plus the raw scancode), mouse move, buttons, and wheel. `Window::vulkan_instance_extensions()` feeds `gfx::DeviceOptions::instance_extensions`; `create_vulkan_surface(instance)` and `destroy_vulkan_surface` bracket a `gfx::Swapchain`. Vulkan handle types are forward-declared the way SDL does it, so the header depends on neither SDL nor the Vulkan headers.

**Gamepads.** `poll()` also reports `GamepadConnected`, `GamepadDisconnected`, `GamepadButtonDown`, `GamepadButtonUp`, and `GamepadAxis`. `Event::gamepad` is this module's own slot id, `0..k_max_gamepads-1` (8), handed out lowest free first and released on disconnect — not SDL's instance id, which grows for the life of the process and would make a replay depend on the order pads were plugged in. `GamepadButton` is the standard layout named by position rather than by label (`South` is Xbox A, PlayStation cross, Nintendo B), plus the dpad, shoulders, sticks, `Back`/`Guide`/`Start`, and `LeftTrigger`/`RightTrigger` for the pads whose triggers click digitally (SDL routes the GameCube's there); anything else maps to `Unknown` and is dropped. `GamepadAxis` is the two sticks and the two triggers, normalized to -1..1 and 0..1 in `Event::value`, keeping SDL's sign convention (+x right, +y **down**, so a stick pushed forward reads negative). `gamepad_button_name`, `gamepad_axis_name`, `gamepad_name(slot)`, and `gamepad_connected(slot)` are for logs and tools. Gamepad events carry no window, so they go to whichever window is polling; the slot table is process-wide and `shutdown()` closes every pad. **The enumerator values of `GamepadButton` and `GamepadAxis` are part of the input log format** (docs/subsystems/input.md): append to them, never reorder or renumber.

**Build.** `cmake/EngineGraphics.cmake` fetches SDL `release-3.4.16` (`ENGINE_SDL_TAG`) and builds it static with audio, render, GPU, camera, and sensor subsystems off; joystick and haptics stay on for gamepads, and `init()` calls `SDL_InitSubSystem(SDL_INIT_GAMEPAD)` after the video subsystem. On Linux SDL needs the X11 or Wayland development headers at build time (the libraries themselves are loaded at run time), and refuses to configure without them; the CI workflow installs them. A headless server build can set `SDL_UNIX_CONSOLE_BUILD=ON` to skip that check, and `init()` then fails cleanly at run time.

**Depends on.** `base`, `containers`, `log`; SDL3 (third_party/LICENSES.md).

**Testing.** `tools/dev.ps1 test -Filter window`: creates a hidden window, checks the pixel size, the surface extension list, event draining, rename, destroy, and shutdown; records a skip on machines without a display. The drain also covers the gamepad path, since SDL reports every pad already plugged in as an arrival during `init()`: each one must come through with a slot below `k_max_gamepads` and an open handle behind it, every button must map to something other than `Unknown`, every axis value must be in range, untouched slots must read as empty, and `shutdown()` must close them all. A machine with no pad (CI, and the machine this was written on) simply records that and checks the empty slots. A second case needs neither a display nor a pad: it pins the numbering of both enums and checks that every enumerator has a name of its own. `domain/gfx`'s swapchain test and `engine-view`'s end-to-end test open real windows.

**Not yet.** Rumble and haptics (the SDL subsystem is built in, nothing calls it), pads beyond `k_max_gamepads`, and the non-standard buttons — paddles, the touchpad, `Misc1` — which are dropped rather than reported. Text input and IME, clipboard, multiple windows and per-output presentation for surround (docs/plan/04-renderer.md §4.8), and cursor capture for first-person controls.

**Performance notes.** Event polling is a few microseconds per frame. SDL's static library adds about a minute to a cold CI build.
