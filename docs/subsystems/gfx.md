# gfx (domain)

**Purpose.** The RHI (docs/plan/04-renderer.md, ADR-0006): a thin, API-neutral layer over Vulkan 1.3/1.4 that the render graph and every renderer system build on. Phase 1 starts here with device discovery: enumerate the physical devices the loader exposes with the properties needed to choose a device and a capability tier, so experiment E2 (cluster acceleration structures on the development GPU) has data before any rendering code exists.

**Today.** Device discovery and creation, resources, one-shot submission, frames in flight, render graph v0 with raster passes, bindless resources, the first mesh-shader pipeline drawing the cluster geometry format, a swapchain, and image capture.

`enumerate_adapters()` creates a throwaway Vulkan 1.3 instance, fills one `AdapterInfo` per physical device (name, vendor, ids, type, API version, driver name and info, device-local memory, queue families, and presence of each extension in `extensions_of_interest()`), assigns a tier (`raster`, `rt` with acceleration structures and ray-tracing pipelines, `rt-cluster` when `VK_NV_cluster_acceleration_structure` is present), sorts discrete devices first and by memory, and destroys the instance. `gpu.adapters` exposes the same through the protocol, so `engine-cli gpu.adapters` reports a machine's capabilities in the schema-typed form.

**Device.** `Device::create()` builds the instance (validation layer when installed and requested, debug messenger routed into the log under `gfx.validation`), matches the chosen adapter, picks queue families (graphics+compute; a compute-only family for async compute and a transfer-only family when the device has them, otherwise aliases), and creates the logical device with the feature chain the renderer relies on. Required, or creation fails: Vulkan 1.3 dynamic rendering, synchronization2, maintenance4; 1.2 buffer device address, descriptor indexing with runtime arrays and partial binding, timeline semaphores, scalar block layout, host query reset, draw indirect count; multi-draw indirect. Optional, enabled when offered and reported in `DeviceFeatures`: mesh shaders, acceleration structures with ray-tracing pipelines and ray queries, `VK_NV_cluster_acceleration_structure`, descriptor buffers, `VK_EXT_memory_decompression`. A VMA allocator with buffer-device-address support and a transient command pool complete the device. On the RTX 5090 every optional feature enables.

`domain/gfx/vulkan.h` is the Vulkan-facing surface for gfx internals, the render graph, and tests: `Handles`, `BufferResource` and `ImageResource` through VMA (`create_buffer` with persistent mapping for host-visible buffers and a device address on request, `create_image_2d`), `submit_immediate` (record, submit on the graphics queue, wait), and `image_barrier` (synchronization2). Nothing above the RHI includes it.

**Shaders.** `engine_shaders(NAME <name> SOURCES <file.slang>...)` (`cmake/EngineShaders.cmake`) fetches the pinned Slang release (`ENGINE_SLANG_VERSION`, prebuilt Windows and Linux binaries, Apache-2.0 with LLVM exception) and compiles every `.slang` to SPIR-V 1.6 at build time with entry point names preserved, then embeds the bytes as a 4-byte-aligned `engine::shaders::k_<stem>_spirv` array in `<shaders/<stem>.spv.h>` on the INTERFACE target `engine_shaders_<name>`. Shader sources live beside the code that owns them (`domain/gfx/shaders/` for the RHI). `create_shader_module` and `create_compute_pipeline` turn embedded SPIR-V into pipelines. Runtime loading through the VFS, a hash-keyed cache, and Slang modules with link-time specialization arrive with the renderer's shader library (ADR-0008).

**Frames.** `FrameContext` (`frame.h`) runs N frames in flight: one transient command pool per slot, GPU progress on a timeline semaphore (frame k signals value k+1), `begin_frame()` blocking only when the GPU is N frames behind, and `defer_destroy()` for buffers and images the GPU may still read, freed when the slot is recycled. Presentation and multi-queue submission arrive with the swapchain and async compute.

**Render graph v0.** `RenderGraph` (`render_graph.h`): passes declare the resources they read and write with an `Access` (compute read/write, sampled read, transfer read/write, color or depth attachment); the graph validates that every read has a producer, allocates one physical resource per transient (no aliasing yet), derives every synchronization2 barrier and image layout transition from the transitions between declared accesses (read-after-read only widens the recorded stage mask), and records barriers plus pass bodies in declaration order. Pass bodies are stored in an arena and must be trivially destructible, so they capture by reference or pointer. Imported resources carry their last state in and report their final layout out, so consecutive graphs chain exactly. `stats()` counts passes, transients, barriers, and layout transitions, and the tests pin those counts. Later: aliasing, async-compute scheduling, raster passes through dynamic rendering, and a persistent graph cache.

**Raster passes.** A `PassKind::Raster` pass declares `color_attachment`/`depth_attachment` (load operation and clear value) instead of plain writes; the graph creates whole-image views for attachment images at compile, begins dynamic rendering with those attachments, sets a full-extent viewport and scissor, runs the body, and ends rendering. `create_graphics_pipeline` builds a dynamic-rendering pipeline with no vertex input (geometry is pulled through device addresses or generated), dynamic viewport and scissor, one color attachment, optional depth with reversed-Z greater-or-equal by default. `triangle.slang` draws the first pixels from the vertex index alone.

**Mesh shaders.** `create_mesh_pipeline` (`MeshPipelineDesc` in `vulkan.h`) builds a dynamic-rendering pipeline from an optional task stage, a mesh stage, and a fragment stage; it fails cleanly when `DeviceFeatures::mesh_shader` is false. `cluster_mesh.slang` is the cluster path from docs/plan/04-renderer.md §4.3 in its first form: one 128-thread workgroup per `geometry::ClusterDesc`, positions and packed local-index triangles pulled through push-constant device addresses, a `view_proj` transform, and a visibility ID per pixel (cluster index in the high 24 bits, triangle index in the low 8) written to an `R32_UINT` attachment. The mesh stage writes `SV_PrimitiveID` per primitive because the fragment stage reads an undefined value otherwise; the cluster index rides a flat per-vertex attribute until per-primitive attributes are wired. Task shaders, cluster culling, LOD selection, and the software-raster path for small clusters (experiment E1) build on this.

**Presentation.** `Swapchain` (`swapchain.h`) sits on a surface the window system created (`window::Window::create_vulkan_surface`; the device must have been created with `DeviceOptions::instance_extensions` from `window::Window::vulkan_instance_extensions()`, and `DeviceFeatures::presentation` reports VK_KHR_swapchain). It picks B8G8R8A8_UNORM when offered, FIFO for vsync and MAILBOX then IMMEDIATE otherwise, three images, and TRANSFER_SRC usage when the surface allows it so captures can read presented frames. Binary semaphores are paired the safe way: one acquire semaphore per frame slot (`FrameContext::acquire_semaphore()`, reusable because `begin_frame()` waited for the frame that last waited on it) and one render-finished semaphore per swapchain image (`Swapchain::render_finished(index)`). `FrameContext::end_frame(PresentSync)` waits on the acquire at color output and signals render-finished alongside the timeline; `Swapchain::present` waits on it. `acquire()` and `present()` return `PresentStatus::OutOfDate` on resize or minimize and `resize()` recreates the chain through `oldSwapchain`. `RenderGraph::set_final_layout(image, PRESENT_SRC_KHR)` makes the graph append the transition after the last pass, so a presented frame is one imported image and one call.

**Viewport convention.** Raster passes set a negative-height viewport, flipping Vulkan's y-down framebuffer to the y-up clip space `core/math` produces; counter-clockwise triangles in y-up space are the front faces, and the raster test's triangle covers the bottom-left half.

**Capture.** `capture_image` (`capture.h`) copies any 8-bit RGBA/BGRA, R32, D32, or float RGBA image into host memory with an immediate submission and puts it back in the layout it was found in; `capture_to_rgba8` swizzles BGRA to RGBA for `image::write_png`. It is the same readback the tests use, so what a test checks is what a screenshot shows; `engine-view --capture` writes one.

**Shader library.** `ShaderLibrary` (`shader_library.h`) hands out shaders by name. Embedded SPIR-V (`add_embedded`, the shipping path) and the build's `shaders/manifest.json` (`load_manifest`, written by `engine_write_shader_manifest()` with each shader's source, SPIR-V path, and slangc arguments) feed the same table; a manifest entry shadows an embedded one, and a manifest shader whose SPIR-V is missing or older than its source is compiled through the pinned slangc on first use. `poll_changes()` recompiles and reloads the shaders whose sources changed since they were loaded and names them, so callers rebuild the affected pipelines; a save that fails to compile keeps the previous version and reports slangc's diagnostics once. Reflection (`reflect_spirv`) comes from a small SPIR-V walk rather than the compiler: entry points with stages and workgroup sizes, descriptor bindings with set, binding, type, and count (0 for unbounded arrays), and the push-constant block size (unpadded, so 92 for `cluster_mesh` where the C++ mirror is 96). The library works without a device for tools and tests, which is how CI covers the slangc round trip on machines without a GPU. `engine-view` uses it and recompiles `cluster_mesh.slang` while running.

**The scene: instances of meshes.** A frame draws a GPU-resident scene (docs/plan/04-renderer.md §4.2): every mesh of it lives in one set of global buffers — clusters, LOD descriptors, triangles, attributes, quantized positions, and the float positions the acceleration structure builders read — with the offsets baked into each `geometry::ClusterDesc` by `geometry::merge_cluster_meshes`. `MeshDesc` (`cluster_cull.h`, 32 bytes) says which range of the cluster array a mesh owns (`first_cluster`, `cluster_count`) and which 16-bit position grid its vertices are on, because each mesh keeps its own through the merge. `InstanceDesc` (96 bytes) places one mesh: a world matrix, a `material_base` added to the cluster's material index, the prefix sum `first_pair`, the largest axis scale `scale_max`, and a flag saying whether the scale is uniform.

The unit of work is the **pair** (instance, cluster). Instance *i* owns its mesh's clusters starting at `first_pair`, so the whole scene is `pair_count` pairs and the cull dispatch covers exactly that many threads; thread *t* finds its instance by binary search over `first_pair` (the instances are in order, and a per-instance culling BVH is a later optimization — this flat enumeration is one load and a handful of compares). Every test then runs in the instance's frame: the bounding sphere's centre goes through the world matrix and its radius times `scale_max`, the LOD spheres and both errors likewise, the occlusion test uses the transformed sphere, and the normal cone is tested only where the scale is uniform, since a non-uniform scale shears a cone open. Survivors append a `uint2 {instance, cluster}` to the visible list.

**The visibility id is a cut entry.** The 64-bit word is `depth << 32 | (visible_index << 8 | triangle)`, where `visible_index` is the entry's index in the frame's visible list — 24 bits, so 16 million pairs. The three rasterizers read `visible[i]` for the instance's world matrix and the mesh's grid and transform positions to world before the view projection; the resolve reads `visible[id >> 8]` to recover the pair, decodes the positions through that mesh's grid, transforms them by the world matrix and the normal by the cofactor matrix of its upper-left 3×3 (the adjugate transpose, which is the inverse transpose up to a positive factor, so normalizing afterwards makes the division unnecessary and a uniform scale needs no special case), and looks up `cluster_material[cluster] + instance.material_base`. A null visible list means `{0, i}`, which is what a direct draw of one mesh's leaves wants. Every draw of a frame appends to its own run of one list — occlusion pass 1, occlusion pass 2, the software rasterizer — and carries the run's base index in `ClusterDrawParams::visible_offset`, so one id space and one array serve the whole frame however many draws filled it. Because an id names a cut entry rather than a cluster, two different cuts of the same scene put the same triangle under different ids, and a comparison between two cuts compares the (instance, cluster, triangle) the ids lead to.

The shaders mirror `ClusterDesc`, `VertexAttributes`, `MeshDesc`, and `InstanceDesc` once, in `shaders/scene.slang`, together with `load_position`, the visible-list lookup, the binary search, and the normal transform; a shader that includes it names it in the `DEPENDS` of its `engine_shaders()`, as they do for `brdf.slang`.

**Cluster culling and LOD selection.** `cluster_cull.slang` runs one thread per pair: a sphere test against the frustum planes, a backface test on the cluster's normal cone when `CullParams::cone_cull` is set (meshoptimizer's apex form on the snorm8 packing in `geometry::ClusterDesc::cone`, the same arithmetic as `geometry::cluster_backfacing`), then the DAG cut test on the two error bounds of `geometry::ClusterLodDesc` (projected own error at or under the threshold, projected parent error over it, the same formula as `geometry::lod_selects`). Survivors append their `{instance, cluster}` pair to a visible list through an atomic that is also the x component of the indirect draw arguments, so `vkCmdDrawMeshTasksIndirectEXT` follows the cull with no CPU round trip; the mesh shader reads its pair through that list when `MeshParams::visible` is set. `CullParams` (`cluster_cull.h`, 400 bytes, read through a device address so the frustum fits) carries the planes from `frustum_from_view_proj`, the camera, the projection scale and threshold, enable flags, the scene (the instance and mesh arrays, the instance count, and the pair count), and the buffer addresses; the RHI never includes the geometry module. The render graph gained `Access::IndirectRead` and `Access::MeshRead` so the fill, cull, indirect draw, and readback chain is barriered from declared accesses like everything else. Measured on the Khronos samples at a 1 px threshold (SciFiHelmet, Suzanne, Corset), the cones remove 0 to 5% of the clusters the LOD cut selects: simplified clusters spread their normals wide and thin parts face both ways, so the cone is a cheap always-on test rather than a win; the cone test's sphere, at 37%, is the upper bound for compact closed geometry, and occlusion culling is where the clusters go.

**Visibility buffer, two rasterizers (experiment E1).** The cull pass also splits survivors by projected cluster diameter (`CullParams::raster`: everything hardware, everything software, or split at a pixel size) into two lists with their own indirect arguments. The hardware path is the mesh shader with `fs_visibility`, an attachment-less raster pass (`PassBuilder::render_area`) whose fragments fold reversed-Z depth and the visibility id into one 64-bit word and take the nearest with a 64-bit atomic max on a storage buffer (`DeviceFeatures::buffer_int64_atomics`). The software path is `cluster_sw_raster.slang`: one 128-thread workgroup per cluster from the software list (`vkCmdDispatchIndirect`), vertices transformed to pixel space in shared memory, one thread per triangle walking its bounding box with edge functions and writing the same words the same way; triangles with a vertex behind the camera or a bounding box over 64×64 pixels are skipped, since such clusters belong to the hardware path. `ClusterDrawParams` (128 bytes, the largest push block the renderer allows) is the shared push-constant block of all three rasterizers. `Access::FragmentRead` and `Access::FragmentReadWrite` cover fragment-shader storage traffic in the graph.

**Quantized positions.** Both rasterizers and the resolve read positions off one 16-bit grid per mesh instead of float triples: **6 bytes per vertex instead of 12**. `MeshDesc` (`cluster_cull.h`, 32 bytes, GPU-mirrored, read through a device address) carries the grid (`geometry::ClusterMeshPart::quant_origin` and `quant_scale` in a `float4`), the address of the scene-wide `quantized` stream, and the mesh's range of the cluster array; `ClusterDrawParams::mesh` and `ResolveParams::mesh` are arrays of it, indexed by an instance's mesh id. `shaders/scene.slang` holds `MeshDesc` and a `load_position` helper that reads the three `u16` at `3 * vertex` out of the 32-bit words containing them, the way it holds `ClusterDesc` and `InstanceDesc`; the CPU pads the stream to an even `u16` count so the last word read is in bounds. Error is bounded by half a grid step, which on engine-view's 20-unit terrain moves a vertex by under 0.002 px at 320×240 (the CPU check in the vertex path test), and the existing pixel comparisons pass with their tolerances untouched. `clas_records.slang` and the acceleration structure builders still read the float positions, so a mesh that is ray traced uploads both streams.

**GPU timers.** `GpuTimer` (`gpu_timer.h`): one timestamp query pool per frame slot, `begin_frame` reads the slot's completed results and resets from the host, `begin`/`end` bracket zones at ALL_COMMANDS, `results()`/`ms(name)` report the last completed frame. engine-view reports per-pass milliseconds through it.

**Two-pass occlusion culling.** `hiz_build.slang` builds a Hi-Z pyramid of the farthest depth from the visibility buffer (mip 0 copies the depth word, empty pixels are 0, every further mip is the minimum of its 2×2 sources, sizes round up so nothing is skipped), laid out back to back in one buffer by `hiz_layout()`. The cull pass gains `CullParams::pass`, `hiz`, `prev_flags`, and `flags`: pass 1 considers the clusters drawn last frame and tests them against last frame's Hi-Z, pass 2 considers everything pass 1 did not draw and tests it against the Hi-Z rebuilt from pass 1's depth, both mark what they draw, and the Hi-Z is rebuilt once more after pass 2 for the next frame. The test projects the eight corners of the sphere's box to a screen rectangle, picks the mip whose texels are at least a quarter of it (a footprint of at most 5×5 texels, which culls far more than a 2×2 footprint at coarser mips), and rejects the cluster when its nearest point is farther than every Hi-Z texel it touches; anything touching the near plane stays visible. Occlusion culling never changes the picture: the test draws a terrain behind a wall with and without it and gets the same visibility buffer while drawing 53 clusters instead of 100.

**Material resolve.** `visibility_resolve.slang` is the first material pass (`visibility_resolve.h`: `ResolveParams`, 208 bytes read through a device address; `ResolveMaterial`, 64 bytes; `ResolveLight`, 64 bytes; `ResolveMode`; `k_no_texture`). For every covered pixel the id's visible entry and triangle lead back through the visible list (`ResolveParams::visible`) to the (instance, cluster) pair and so to the triangle's three vertices, off the 16-bit grid of that instance's mesh (`ResolveParams::mesh`) and through that instance's world matrix, exactly as the rasterizer moved them; screen-space barycentrics against the pixel center, made perspective-correct through the vertices' clip-space w, reconstruct the surface position and interpolate the per-vertex normal and UV from `geometry::VertexAttributes` (the triangle plane gives a flat, two-sided normal when a mesh has no attributes). A material table indexed by the cluster's material index plus the instance's `material_base` (`ResolveMaterial`, 64 bytes) supplies albedo and roughness, emissive and metallic, and three optional textures sampled through the bindless set with one sampler slot and one UV scale: `albedo_texture` multiplies the albedo, `metallic_roughness_texture` multiplies the roughness and metallic factors by the texture's G and B (glTF's packing), and `normal_texture` perturbs the shading normal.

**The tangent frame** is solved per pixel from the hit triangle's own data, because nothing upstream carries tangents: its three positions go through the instance's world matrix like the ones the reconstruction interpolated, so the frame is in the same space as the normal it perturbs, and the two edge vectors and the two UV deltas give `dp1 = T du1 + B dv1` and `dp2 = T du2 + B dv2`, which invert to a tangent and a bitangent, and those are Gram-Schmidt orthonormalized against the interpolated shading normal, so the frame is orthonormal and keeps the UV parameterization's handedness (a mirrored island gets a mirrored bitangent, which is what a map authored on it expects). A triangle with no attributes or a degenerate UV area has no frame, and the normal is then left alone rather than perturbed by a frame the shader invented. The map's bytes are UNORM, remapped to −1..1; `normal_scale` multiplies the tangential xy before the vector is renormalized, so a scale of 0 gives the interpolated normal back exactly. The perturbed normal goes into the BSDF and into the sky hemisphere's elevation term; nothing else in the lighting changes, and the `normals` debug view still shows the interpolated normal, before any map. Normal and metallic-roughness textures are **data, not color**, so they are uploaded `R8G8B8A8_UNORM` while base color goes up `R8G8B8A8_SRGB`.

**The lighting model** is physically based and lives in `shaders/brdf.slang`, a file with no bindings and no entry points that the reference path tracer will include unchanged (docs/plan/04-renderer.md §4.3, "Materials"): Cook-Torrance with a GGX/Trowbridge-Reitz normal distribution, Smith height-correlated visibility (Heitz 2014), Schlick's Fresnel with F0 = lerp(0.04, albedo, metallic), and a Lambert diffuse lobe scaled by (1 − metallic) and (1 − F). Perceptual roughness is clamped to 0.045 so a mirror's highlight stays finite, and alpha is its square. The resolve evaluates it for the directional sun (`ResolveParams::sun`, direction and intensity) and for `light_count` analytic lights at `ResolveParams::lights` (`ResolveLight`, 64 bytes: position and radius of influence, linear color and intensity, spot direction and type, cosines of the inner and outer cone). A light's falloff is inverse square windowed to zero at its radius with Karis' `(1 − (d/r)⁴)²`, so a light contributes exactly nothing beyond its radius and culling by radius cannot change the picture; a spot multiplies that by a smoothed cone. The sky hemisphere is the whole indirect term until the lighting passes of §4.2 step 5 exist: the diffuse albedo takes 15% to 35% of the sky color by normal elevation, and a Fresnel-weighted sliver of it at the view angle keeps metals, which have no diffuse lobe, from going black. Emissive adds, and the result goes through a 1/2.2 display gamma onto the UNORM swapchain (tone mapping is a later pass). `engine_shaders(... DEPENDS shaders/brdf.slang)` puts the included file in the dependencies of every slangc command of that group, so editing it rebuilds the shaders that include it; `ShaderLibrary`'s hot reload, though, watches only each shader's own source, so a running `engine-view` picks a `brdf.slang` edit up when the including file is saved too. Debug modes show cluster colors, triangle shading, depth, normals, or UVs. `upload_image_2d` (`vulkan.h`) creates a sampled texture from host pixels.

The tests pin the model against a second implementation rather than against numbers written by hand: `tests/brdf_reference.h` evaluates the same BSDF, the same falloff, the same hemisphere, the same tangent frame and normal-map perturbation (`tangent_frame`, `map_normal`), and the same gamma on the CPU in double precision, and reconstructs the shaded point as the camera ray through the pixel center. The shading test renders one quad through eight materials (roughness 0.05, 0.3, 0.7, 1.0 at metallic 0 and 1) under a 24° sun and a point light and finds every center pixel and an off-center pixel exactly equal to the reference on the RTX 5090 (0 of 255, tolerance 2); it also checks the normals mode against the plane normal, that a point light 30 units away with a radius of 5 leaves the picture byte-identical to no light at all, and that a white dielectric at roughness 1 under a head-on unit sun reflects 0.3087606 — (1 − 0.04)/π of diffuse plus (1/π)(1/4)(0.04) of GGX — which is 149 of 255 after the gamma. The attributes test tilts the quad's vertex normals 45°, checks the shading and the normals view follow them rather than the plane, and samples a 2×2 checker texture by UV, comparing each quadrant against the reference shaded with that texel as its albedo. A second case puts the two data maps on a flat quad: a 2×2 metallic-roughness map whose quadrants are a rough dielectric, a smooth dielectric, a rough metal, and a smooth metal, each quadrant equal to the reference shaded with that texel's roughness and metallic (0 of 255 on the RTX 5090), and a constant normal map tilted 45° about the tangent axis, whose center pixel equals the reference shaded with the normal the frame and the map produce (0 of 255) and differs from the unmapped render by 24 of 255; the same map at `normal_scale` 0 leaves the picture byte-identical to no normal map at all.

**Baseline tier: the vertex-shader cluster path.** GPUs without mesh shaders (Maxwell, Pascal, integrated parts) draw the same clusters into the same visibility buffer through `cluster_vertex.slang`: one instance per visible cluster and a fixed vertex count of three times the cluster triangle capacity (`ClusterDrawParams::triangles_per_cluster`), the vertex shader mapping `SV_VertexID` to a local triangle and corner, pulling positions through device addresses as the mesh shader does, and collapsing the vertices of triangles past the cluster's count so they never rasterize. The cull pass counts survivors into the instance count of a `vkCmdDrawIndirect` block instead of the mesh-task group count (`CullParams::count_index` = 1, arguments prefilled `{vertex_count, 0, 0, 0}`), and `Access::VertexRead` covers the vertex stage's read of the visible list. Occlusion culling, LOD selection, and the resolve are unchanged. The vertex path test draws a terrain's leaf clusters through both paths and finds the visibility buffers identical to the pixel, and the indirect draw equal to the direct one.

**Acceleration structures and ray queries.** `acceleration.h` is the ray tracing side of docs/plan/04-renderer.md §4.4 on the first-class path (VK_KHR_acceleration_structure, the fallback the plan keeps whatever experiment E2 decides). A bottom-level structure takes one geometry per visible cluster (`ClusterGeometry`: float3 positions and 16-bit local indices, which `expand_packed_triangles` widens from the cluster format's packed bytes) and a scene builds one per instance, so a hit's GeometryIndex plus `RayVisibilityParams::instance_base` names the visible entry and PrimitiveIndex the triangle, the same pair the rasterizer writes; `create_blas`/`build_blas`, `create_tlas`/`write_instances`/`build_tlas`, `create_scratch` (aligned to the device's minimum), `acceleration_build_barrier`, and `destroy_acceleration_structure` split object creation and size queries from the recorded builds so builds batch and scratch is reused. Top-level structures live in the bindless set (binding 3, see below) because a shader cannot trace against a device address. `ray_visibility.slang` (`ray_visibility.h`: `RayVisibilityParams`, 176 bytes via address) shoots one ray per pixel center through the same view-projection as the rasterizer with a `RayQuery` and writes the visibility buffer's 64-bit word (the cluster path needs no remap at all, since a CLAS record carries its own base geometry index), so the RT and raster pictures compare word for word. The ray query test builds a terrain's LOD cut both ways and finds identical coverage on 12,306 pixels, 17 shared-edge pixels naming the other triangle, and depth agreeing to 1.4e-6; tracing the 24-cluster cut costs 9 µs at 320×240 on the RTX 5090 against 5 µs of rasterization.

**Cluster acceleration structures (experiment E2, ADR-0025).** `cluster_acceleration.h` is the NVIDIA path (`VK_NV_cluster_acceleration_structure`, `DeviceFeatures::cluster_acceleration_structure`): `create_cluster_set` sizes storage for up to N cluster acceleration structures and `build_cluster_set` builds them in one indirect command from a device array of per-cluster records (`ClusterBuildInput` written by `write_cluster_build_records`: float3 positions, tightly packed 8-bit indices from `pack_cluster_indices`, the cluster id as `ClusterID` and as the base geometry index) whose count may itself be a device address, so the frame's GPU-selected cut can build without a round trip; the driver packs the structures into one buffer and writes each one's address and size to host-visible arrays. `create_cluster_blas`/`build_cluster_blas` make a cluster bottom-level structure over those addresses, and its address goes into a standard `TlasInstance`, so the top-level structure and `ray_visibility.slang` are shared with the KHR path. Ray queries traverse cluster structures from a compute pipeline with no opt-in.

Per frame, from the GPU's own cut, over a scene: `clas_records.slang` (`ClusterRecordParams`) turns the cull pass's visible list and count into the build records in three small passes, because a scene builds **one cluster bottom-level structure per instance** and an instance's records therefore have to be contiguous while the cull's atomics leave the list in whatever order they produced. `records_main` buckets each visible entry into its instance's slice of a pair-indexed scratch array (slot = `first_pair` plus a per-instance atomic); `ranges_main` prefix-sums the per-instance counts into the dense bases, writes the total the CLAS build reads from the device, and writes one 16-byte bottom-level record per instance over that instance's run of CLAS addresses; `emit_main`, one thread per pair slot, moves the bucketed entries down into the dense records array and writes the 64-byte build record there, with the **visible entry as the record's cluster id and base geometry index** so a hit's GeometryIndex is the same word the rasterizer would have written. Then one `build_cluster_set` over the dense array, one `build_cluster_blas_indirect` per instance (each with its own record, passed as `record_address`; they share the scratch, so a barrier separates them), and one top-level build with an instance per scene instance whose transform is the world matrix and whose custom index is the instance. Every bottom-level structure is built to an explicit destination, so its address is known at creation and the instance records are written once a frame on the host; the render graph orders it all through `Access::AccelerationBuildRead`/`AccelerationBuildWrite` (the build stage) and `Access::RayQueryRead` (the traversal), so the builds, the trace, and the resolve are barriered from declared accesses like every other pass. The records test asserts the shader's bytes equal `write_cluster_build_records`' for the same clusters, and `engine-view --raster rt` runs the whole chain every frame. The comparison test builds a terrain cut both ways: pixel-identical pictures, 2.9× to 3.3× less memory (about 14 bytes per triangle against 62), 1.2× to 2.6× faster builds, the same trace time (docs/experiments/e2-cluster-acceleration.md).

**Bindless (ADR-0023).** `BindlessSet` (`bindless.h`) owns one global descriptor set with unbounded, partially bound, update-after-bind arrays (sampled images at binding 0, storage images at 1, samplers at 2, and on devices with `DeviceFeatures::acceleration_structure` acceleration structures at 3; `has_acceleration_structures()` says whether the binding exists), capacities clamped to the device's update-after-bind limits, a free list per array, and deferred slot release keyed on the frame timeline (`release_*` with the value of the last frame that could read the slot, `recycle(completed)` once per frame). `pipeline_layout()` is set 0 plus a push-constant block for all stages, so every pipeline shares one layout shape. Buffers never enter the set: shaders receive device addresses and use Slang pointers (`uint* data = (uint*)params.address`). Helpers create views and samplers.

**No SDK required.** The Vulkan headers and volk come through FetchContent (`cmake/EngineGraphics.cmake`, tag `vulkan-sdk-1.4.357.0`); volk loads the driver's loader library at run time. Without a loader, or with a loader but no driver behind it (GitHub-hosted runners have exactly that), `enumerate_adapters` returns false with a message saying which, and everything else keeps working. `vulkan_available()` answers only the loader question. The SDK arrives with validation layers and shader tooling.

**Invariants (tested).** Every adapter has a name, a `1.x.y` API version, every extension of interest reported present or absent, at least one queue family (a graphics one unless the device is a CPU implementation), and a tier from the fixed set; the list is sorted discrete-first. On a machine without a usable Vulkan driver the function fails cleanly with a message naming the missing piece.

**Extensions of interest.** Acceleration structures, ray-tracing pipelines, ray queries, position fetch, RT maintenance, mesh shaders, NVIDIA cluster and partitioned acceleration structures, EXT and NV memory decompression, descriptor buffers, fragment shading rate and density map, swapchain, shader objects, cooperative matrices. Names rather than header macros, so an older header still compiles and reports an extension absent.

**Testing.** `tools/dev.ps1 test -Filter gfx`. Adapter enumeration prints every adapter and extension it finds, so a CI log or a `ctest -V` run on a new machine is a capability report. Device tests create a device, check that every enabled optional feature was advertised, clear an offscreen image and read it back pixel by pixel, and round-trip bytes through a device-local buffer with a device address. The compute test dispatches the embedded `fill.slang` over a storage buffer with push constants and checks every word, including that the tail past `count` stays untouched. Frame tests run six frames through two slots and watch VMA's allocation count to prove deferred destruction happens on recycle. Render graph tests chain `fill` into `scale` through a transient buffer (two buffer barriers, no image barriers), clear and copy images across a transient and an imported image (four layout transitions, layouts visible to pass bodies match), and reject a read with no producer. Bindless tests upload a texture, sample it by index through a sampler by index into a storage image by index (slot 1 of each array, with decoys in slot 0), read the result back pixel-exact, release and recycle slots against the timeline, and write a buffer through its device address from a Slang pointer. The raster test draws a triangle into a transient color attachment through the graph and checks every pixel: exactly the bottom-left half is covered with the pushed color, the rest keeps the clear. The mesh-shader test builds a 512-triangle grid into clusters with `domain/geometry`, uploads them behind device addresses, draws one workgroup per cluster into a visibility-ID target, and checks that every covered pixel names a valid cluster and triangle, nothing outside the grid is touched, and all 512 triangles appear. The capture test draws the triangle into an imported image left in PRESENT_SRC_KHR through `set_final_layout`, captures it, converts to RGBA8, checks the same pixels, encodes a PNG, and captures a depth image. The swapchain test opens a real window, presents six frames of clears, resizes, presents again, and captures the presented image; it skips without a display. Shader library tests reflect every shipped shader (stages, workgroup sizes, bindings, push sizes), load the same shader embedded and from the build manifest and check the hashes match, then compile a temporary shader with slangc, edit it, reload it, and break it. The cull test builds a terrain's LOD DAG, runs the cull pass against a camera, and checks that the survivors equal the CPU reference set exactly, that the indirect mesh draw of the cut covers the same pixels as drawing every leaf cluster (23 pixels of 14,000 differ along silhouettes), that every drawn pixel names a survivor, and that a camera looking away culls everything. The visibility test rasterizes every leaf cluster of a terrain through both paths into two buffers and compares them: identical coverage on about 21,000 pixels, the same triangle on 99.85% of them, depth agreeing to under a thousandth, no false ids, and the resolve painting exactly the covered pixels; it also reports both paths' GPU time. The occlusion test runs a reference single pass and three two-pass frames over a terrain behind a wall: frame 0 draws the reference set in pass 2, later frames draw about half of it, the pictures name the same surface everywhere (an id names a cut entry, so the words themselves differ between two cuts), and the Hi-Z pyramid matches a CPU recomputation mip by mip. The cone test draws a closed sphere through the vertex path with the cone test off and on: the survivors equal the CPU reference exactly (15 of 24 clusters), every pixel the culled draw covers names the same triangle as the full draw, and no pixel is lost. The ray query test builds a bottom-level structure with one geometry per cluster of a terrain's LOD cut and a one-instance top-level structure, draws the same cut through the vertex path, traces one ray per pixel, and compares the two visibility buffers word for word (identical coverage, under 1% of covered pixels naming the other triangle of a shared edge, depth within 2e-3), reporting both GPU times. The cluster acceleration structure test does the same for the cluster path at two scales (an 85-cluster frame cut and all 1,357 leaves of the default terrain), requires the two ray-traced pictures to be identical to 0.1% and both to match the rasterizer, and reports build times, trace times, and memory per path. The scene test puts two meshes (a terrain and a sphere, each on its own grid) and five instances (one three times bigger, one scaled unevenly, one turned a quarter turn, one hidden behind the big sphere) through the whole frame: the GPU's 76 surviving pairs of 506 equal a CPU reference that repeats every test in the instance's frame, the mesh and vertex paths write identical words, every instance puts pixels on the screen, a KHR bottom-level structure per instance traces a picture that differs from the rasterized one on 2 pixels of 13,154 with 17 naming the neighbouring triangle, and two-pass occlusion culling drops the hidden instance's 3 pairs while every covered pixel keeps the same surface. All of them skip with the reason on machines without a usable driver.

**Next.** A per-instance culling BVH over cluster groups (the pair enumeration is flat, which is one thread per (instance, cluster) and fine until scenes reach millions of pairs), transform updates instead of a static instance buffer, lighting through the ray-traced visibility, and cluster templates for deforming geometry. On the ray path, two instances of one mesh build their own copies of the same cluster acceleration structures, because a record's base geometry index has to be the visible entry; cluster templates are the answer. The per-instance bottom-level builds are recorded one after another with a barrier between them because they share one scratch buffer; a scratch per instance, or the extension's multi-structure form, would overlap them. Running the vertex path on the Maxwell and Pascal machines once they are reachable, quantized positions for the acceleration structure builders too (they take a vertex format; the rasterizers already read the 16-bit grid), cheaper Hi-Z and resolve passes at surround resolutions, and the experiment E2 spike on cluster acceleration structures.
