# gfx (domain)

**Purpose.** The RHI (docs/plan/04-renderer.md, ADR-0006): a thin, API-neutral layer over Vulkan 1.3/1.4 that the render graph and every renderer system build on. Phase 1 starts here with device discovery: enumerate the physical devices the loader exposes with the properties needed to choose a device and a capability tier, so experiment E2 (cluster acceleration structures on the development GPU) has data before any rendering code exists.

**Today.** Device discovery and creation, resources, one-shot submission, frames in flight, render graph v0 with raster passes, bindless resources, the first mesh-shader pipeline drawing the cluster geometry format, a swapchain, and image capture.

`enumerate_adapters()` creates a throwaway Vulkan 1.3 instance, fills one `AdapterInfo` per physical device (name, vendor, ids, type, API version, driver name and info, device-local memory, queue families, and presence of each extension in `extensions_of_interest()`), assigns a tier (`raster`, `rt` with acceleration structures and ray-tracing pipelines, `rt-cluster` when `VK_NV_cluster_acceleration_structure` is present), sorts discrete devices first and by memory, and destroys the instance. `gpu.adapters` exposes the same through the protocol, so `engine-cli gpu.adapters` reports a machine's capabilities in the schema-typed form.

**Device.** `Device::create()` builds the instance (validation layer when installed and requested, debug messenger routed into the log under `gfx.validation`), matches the chosen adapter, picks queue families (graphics+compute; a compute-only family for async compute and a transfer-only family when the device has them, otherwise aliases), and creates the logical device with the feature chain the renderer relies on. Required, or creation fails: Vulkan 1.3 dynamic rendering, synchronization2, maintenance4; 1.2 buffer device address, descriptor indexing with runtime arrays and partial binding, timeline semaphores, scalar block layout, host query reset, draw indirect count; multi-draw indirect. Optional, enabled when offered and reported in `DeviceFeatures`: mesh shaders, acceleration structures with ray-tracing pipelines and ray queries, `VK_NV_cluster_acceleration_structure`, descriptor buffers, `VK_EXT_memory_decompression`. A VMA allocator with buffer-device-address support and a transient command pool complete the device. On the RTX 5090 every optional feature enables.

`domain/gfx/vulkan.h` is the Vulkan-facing surface for gfx internals, the render graph, and tests: `Handles`, `BufferResource` and `ImageResource` through VMA (`create_buffer` with persistent mapping for host-visible buffers and a device address on request, `create_image_2d`), `submit_immediate` (record, submit on the graphics queue, wait), and `image_barrier` (synchronization2). Nothing above the RHI includes it.

**Shaders.** `engine_shaders(NAME <name> SOURCES <file.slang>...)` (`cmake/EngineShaders.cmake`) fetches the pinned Slang release (`ENGINE_SLANG_VERSION`, prebuilt Windows and Linux binaries, Apache-2.0 with LLVM exception) and compiles every `.slang` to SPIR-V 1.6 at build time with entry point names preserved, then embeds the bytes as a 4-byte-aligned `engine::shaders::k_<stem>_spirv` array in `<shaders/<stem>.spv.h>` on the INTERFACE target `engine_shaders_<name>`. Shader sources live beside the code that owns them (`domain/gfx/shaders/` for the RHI). `create_shader_module` and `create_compute_pipeline` turn embedded SPIR-V into pipelines. Runtime loading through the VFS, a hash-keyed cache, and Slang modules with link-time specialization arrive with the renderer's shader library (ADR-0008).

**Frames.** `FrameContext` (`frame.h`) runs N frames in flight: one transient command pool per slot, GPU progress on a timeline semaphore (frame k signals value k+1), `begin_frame()` blocking only when the GPU is N frames behind, and `defer_destroy()` for buffers and images the GPU may still read, freed when the slot is recycled. Presentation and multi-queue submission arrive with the swapchain and async compute.

**Render graph v0.** `RenderGraph` (`render_graph.h`): passes declare the resources they read and write with an `Access` (compute read/write, sampled read, transfer read/write, color or depth attachment); the graph validates that every read has a producer, allocates one physical resource per transient (no aliasing yet), derives every synchronization2 barrier and image layout transition from the transitions between declared accesses (read-after-read only widens the recorded stage mask), and records barriers plus pass bodies in declaration order. Pass bodies are stored in an arena and must be trivially destructible, so they capture by reference or pointer. Imported resources carry their last state in and report their final layout out, so consecutive graphs chain exactly. `stats()` counts passes, transients, barriers, and layout transitions, and the tests pin those counts. Later: aliasing, async-compute scheduling, raster passes through dynamic rendering, and a persistent graph cache.

**Raster passes.** A `PassKind::Raster` pass declares `color_attachment`/`depth_attachment` (load operation and clear value) instead of plain writes; the graph creates whole-image views for attachment images at compile, begins dynamic rendering with those attachments, sets a full-extent viewport and scissor, runs the body, and ends rendering. `create_graphics_pipeline` builds a dynamic-rendering pipeline with no vertex input (geometry is pulled through device addresses or generated), dynamic viewport and scissor, one color attachment, optional depth with reversed-Z greater-or-equal by default. `triangle.slang` draws the first pixels from the vertex index alone.

**Mesh shaders.** `create_mesh_pipeline` (`MeshPipelineDesc` in `vulkan.h`) builds a dynamic-rendering pipeline from an optional task stage, a mesh stage, and a fragment stage; it fails cleanly when `DeviceFeatures::mesh_shader` is false. `cluster_mesh.slang` is the cluster path from docs/plan/04-renderer.md §4.3 in its first form: one 128-thread workgroup per `geometry::ClusterDesc`, positions and packed local-index triangles pulled through push-constant device addresses, a `view_proj` transform, and a visibility ID per pixel (cluster index in the high 24 bits, triangle index in the low 8) written to an `R32_UINT` attachment. The mesh stage writes `SV_PrimitiveID` per primitive because the fragment stage reads an undefined value otherwise; the cluster index rides a flat per-vertex attribute until per-primitive attributes are wired. Task shaders, cluster culling, LOD selection, and the software-raster path for small clusters (experiment E1) build on this.

**Presentation.** `Swapchain` (`swapchain.h`) sits on a surface the window system created (`window::Window::create_vulkan_surface`; the device must have been created with `DeviceOptions::instance_extensions` from `window::Window::vulkan_instance_extensions()`, and `DeviceFeatures::presentation` reports VK_KHR_swapchain). It picks B8G8R8A8_UNORM when offered, FIFO for vsync and MAILBOX then IMMEDIATE otherwise, three images, and TRANSFER_SRC usage when the surface allows it so captures can read presented frames. Binary semaphores are paired the safe way: one acquire semaphore per frame slot (`FrameContext::acquire_semaphore()`, reusable because `begin_frame()` waited for the frame that last waited on it) and one render-finished semaphore per swapchain image (`Swapchain::render_finished(index)`). `FrameContext::end_frame(PresentSync)` waits on the acquire at color output and signals render-finished alongside the timeline; `Swapchain::present` waits on it. `acquire()` and `present()` return `PresentStatus::OutOfDate` on resize or minimize and `resize()` recreates the chain through `oldSwapchain`. `RenderGraph::set_final_layout(image, PRESENT_SRC_KHR)` makes the graph append the transition after the last pass, so a presented frame is one imported image and one call.

**Viewport convention.** Raster passes set a negative-height viewport, flipping Vulkan's y-down framebuffer to the y-up clip space `core/math` produces; counter-clockwise triangles in y-up space are the front faces, and the raster test's triangle covers the bottom-left half.

**Capture.** `capture_image` (`capture.h`) copies any 8-bit RGBA/BGRA, R32, D32, or float RGBA image into host memory with an immediate submission and puts it back in the layout it was found in; `capture_to_rgba8` swizzles BGRA to RGBA for `image::write_png`. It is the same readback the tests use, so what a test checks is what a screenshot shows; `engine-view --capture` writes one.

**Shader library.** `ShaderLibrary` (`shader_library.h`) hands out shaders by name. Embedded SPIR-V (`add_embedded`, the shipping path) and the build's `shaders/manifest.json` (`load_manifest`, written by `engine_write_shader_manifest()` with each shader's source, SPIR-V path, and slangc arguments) feed the same table; a manifest entry shadows an embedded one, and a manifest shader whose SPIR-V is missing or older than its source is compiled through the pinned slangc on first use. `poll_changes()` recompiles and reloads the shaders whose sources changed since they were loaded and names them, so callers rebuild the affected pipelines; a save that fails to compile keeps the previous version and reports slangc's diagnostics once. Reflection (`reflect_spirv`) comes from a small SPIR-V walk rather than the compiler: entry points with stages and workgroup sizes, descriptor bindings with set, binding, type, and count (0 for unbounded arrays), and the push-constant block size (unpadded, so 92 for `cluster_mesh` where the C++ mirror is 96). The library works without a device for tools and tests, which is how CI covers the slangc round trip on machines without a GPU. `engine-view` uses it and recompiles `cluster_mesh.slang` while running.

**Bindless (ADR-0023).** `BindlessSet` (`bindless.h`) owns one global descriptor set with three unbounded, partially bound, update-after-bind arrays (sampled images at binding 0, storage images at 1, samplers at 2), capacities clamped to the device's update-after-bind limits, a free list per array, and deferred slot release keyed on the frame timeline (`release_*` with the value of the last frame that could read the slot, `recycle(completed)` once per frame). `pipeline_layout()` is set 0 plus a push-constant block for all stages, so every pipeline shares one layout shape. Buffers never enter the set: shaders receive device addresses and use Slang pointers (`uint* data = (uint*)params.address`). Helpers create views and samplers.

**No SDK required.** The Vulkan headers and volk come through FetchContent (`cmake/EngineGraphics.cmake`, tag `vulkan-sdk-1.4.357.0`); volk loads the driver's loader library at run time. Without a loader, or with a loader but no driver behind it (GitHub-hosted runners have exactly that), `enumerate_adapters` returns false with a message saying which, and everything else keeps working. `vulkan_available()` answers only the loader question. The SDK arrives with validation layers and shader tooling.

**Invariants (tested).** Every adapter has a name, a `1.x.y` API version, every extension of interest reported present or absent, at least one queue family (a graphics one unless the device is a CPU implementation), and a tier from the fixed set; the list is sorted discrete-first. On a machine without a usable Vulkan driver the function fails cleanly with a message naming the missing piece.

**Extensions of interest.** Acceleration structures, ray-tracing pipelines, ray queries, position fetch, RT maintenance, mesh shaders, NVIDIA cluster and partitioned acceleration structures, EXT and NV memory decompression, descriptor buffers, fragment shading rate and density map, swapchain, shader objects, cooperative matrices. Names rather than header macros, so an older header still compiles and reports an extension absent.

**Testing.** `tools/dev.ps1 test -Filter gfx`. Adapter enumeration prints every adapter and extension it finds, so a CI log or a `ctest -V` run on a new machine is a capability report. Device tests create a device, check that every enabled optional feature was advertised, clear an offscreen image and read it back pixel by pixel, and round-trip bytes through a device-local buffer with a device address. The compute test dispatches the embedded `fill.slang` over a storage buffer with push constants and checks every word, including that the tail past `count` stays untouched. Frame tests run six frames through two slots and watch VMA's allocation count to prove deferred destruction happens on recycle. Render graph tests chain `fill` into `scale` through a transient buffer (two buffer barriers, no image barriers), clear and copy images across a transient and an imported image (four layout transitions, layouts visible to pass bodies match), and reject a read with no producer. Bindless tests upload a texture, sample it by index through a sampler by index into a storage image by index (slot 1 of each array, with decoys in slot 0), read the result back pixel-exact, release and recycle slots against the timeline, and write a buffer through its device address from a Slang pointer. The raster test draws a triangle into a transient color attachment through the graph and checks every pixel: exactly the bottom-left half is covered with the pushed color, the rest keeps the clear. The mesh-shader test builds a 512-triangle grid into clusters with `domain/geometry`, uploads them behind device addresses, draws one workgroup per cluster into a visibility-ID target, and checks that every covered pixel names a valid cluster and triangle, nothing outside the grid is touched, and all 512 triangles appear. The capture test draws the triangle into an imported image left in PRESENT_SRC_KHR through `set_final_layout`, captures it, converts to RGBA8, checks the same pixels, encodes a PNG, and captures a depth image. The swapchain test opens a real window, presents six frames of clears, resizes, presents again, and captures the presented image; it skips without a display. Shader library tests reflect every shipped shader (stages, workgroup sizes, bindings, push sizes), load the same shader embedded and from the build manifest and check the hashes match, then compile a temporary shader with slangc, edit it, reload it, and break it. All of them skip with the reason on machines without a usable driver.
