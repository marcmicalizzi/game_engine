# water (systems)

**Purpose.** Water surfaces in a scene — the oases of Desert Survival first ([plan 13 §13.1](../plan/13-reference-consumer-games.md#oases), "water with reflection and refraction"; roadmap S63, P8) and the "Fluids and water surfaces" row of the capability inventory ([plan 05 §5.15](../plan/05-simulation.md#515-capability-inventory)). A scene's `water` block (`engine.scene.WaterBody`) names bodies — a circle or a star-shaped polygon at a level — and each becomes **an opaque mesh with a water material**, drawn by the rasterizers like any instance and shaded by the material resolve's water branch; a walker wades in it and stops at the chest. At the renderer's `water_quality` high (the default since 2026-10-18) the water is **translucent by volume** — the ground under it seen through the surface, more and more obscured as it deepens ([below](#translucent-by-volume)); low is the opaque surface it was. It deliberately does not yet show anything under the surface but the ground, let anyone swim, float anything, or run a ripple simulation: the rest of stage 2, roadmap S86.

**Why this shape: opaque with a branch, not a forward pass.** The renderer is a visibility buffer: every surface is a triangle id in one 64-bit word per pixel, shaded once by the resolve, and the plan's forward and transparent pass (plan 04 §4.3 step 7) is not built. A water surface that is transparent needs that pass, a second depth, and an order — weeks of renderer for one material. But what the eye sees of a shallow pool is three things the resolve can evaluate at the pixel with what it already has: the **sky** reflected along the view (the sky's model is a function of a direction, `sky.slang`), the **sun's glitter** (the GGX lobe the resolve already evaluates, at a low roughness on a wave normal), and the **bottom's colour fading with depth** (which a vertex attribute can carry: the depth under every vertex is known when the mesh is built). So a body is a flat mesh in the visibility buffer, and a material class tells the resolve to shade it as water. Everything downstream is unchanged: the cull, the four rasterizers, the occlusion, the shadows (the surface receives the sun's shadow as any surface does; it also casts one, onto the ground under itself, which nobody sees), the LOD DAG and the ray path. What it costs is what opaque water cannot show — the rocks and the bottom's own texture under the surface, seen bent through it — which is refraction and needs the forward pass; S86 rows it.

**Why a capability, and how it reaches the renderer.** The renderer is not a capability and the water is (ADR-0027), so the renderer may not call it. The registration point is the scene-generator registry (ADR-0046): the capability registers the **placement generator `"water"`**, and the renderer's scene reader (`systems/renderer/src/scene_water.cpp`, one call in `read_scene_file`, after the placement entries and before the terrain, which stays the last mesh) hands it the block as `{"bodies": [...]}`. Its `expand` returns one mesh and one placement per body, in the block's order — mesh *k* and instance *k* are body *k*, the one contract the reader relies on. A build without the capability (`ENGINE_WITH_WATER=OFF`, `msvc-minimal`) refuses a scene with a `water` block with a sentence naming the switch; a scene without the block is read exactly as before, byte for byte. The **material** is the renderer's and gfx's, not the capability's: `gfx::k_material_water` is a class of the material table, `gfx::set_water_material` packs a body's numbers into it, and the resolve's branch is `domain/gfx/shaders/water.slang`.

**Owned data.** A body as read and checked (`water::Body`, `read_body`); its mesh (`build_mesh`) and the GLB file it is written to; its depth map (`build_depth_map`) and the `.depth` file beside the GLB ([below](#the-depth-map)); the depth at a point (`depth_at`). Nothing at run time: no state per tick, no GPU resource of its own (the renderer uploads the map).

## The block

`engine.scene.WaterBody` (schemas/scene.schema, `Scene.water`, scene version 8):

| Field | Default | Meaning |
|---|---|---|
| `name` | | what the mesh is called (`water/<name>`) |
| `level_m` | 0 | the surface's height, a world y (f64) |
| `shape` | | exactly one of `circle: {center, radius_m}`, `polygon: [worldpos...]` (x and z read; star-shaped from its centroid, in either winding) and `fill: {seed, max_extent_m = 500}` ([A body that fills](#a-body-that-fills), `WaterShape` version 2) |
| `shore_m` | 2 | how far in from the edge the surface fades from the bottom alone to reflecting; since S97 the edge is where the depth map's depth is zero, not the mesh's ([The shore](#the-shore)) |
| `shallow`, `deep` | pale green-blue, dark blue-green | linear RGB over a shallow bottom and where the bottom is gone |
| `depth_fade_m` | 3 | the depth at which the bottom has faded to `deep` |
| `wave_amplitude_m`, `wave_length_m` | 0.02, 2.5 | the largest wave; 0 amplitude is a mirror |
| `chop` | 0.5 | how far the shorter waves turn from the main direction, [0, 1] |
| `wind_follow` | true | the waves travel along the ground's wind (`GroundProvider::wind` at the scene's time) when it has one |
| `direction_deg` | 0 | otherwise, about +y from +x towards +z |
| `roughness` | 0.08 | the surface's GGX roughness, [0.02, 1] |
| `seed` | 1 | the waves' phases |
| `absorption` | 0.45, 0.065, 0.03 | the volume tier's: what the water absorbs per metre, linear RGB (clear fresh water: the red gone in two metres, the blue kept for thirty) |
| `scattering` | 0.03, 0.035, 0.04 | what it scatters per metre: the colour deep water tends to |
| `transmission` | 1 | the share of the bottom's light that reaches the surface beyond those, [0, 1] |
| `turbidity` | 0 | suspended sediment, ≥ 0: each unit adds scattering (0.9, 0.82, 0.68) and absorption (0.03, 0.06, 0.14) per metre |
| `open` | false | **open water**: the outline is the near shore of a sea that goes on past it to the horizon wherever the ground is below the level ([To the horizon](#to-the-horizon)); at most one body of a scene |
| `wind_m_s` | 0 | an open body's wind 10 m up, m/s, where the ground gives none: with a wind its waves are [the spectrum's](#the-spectrum); since version 5 **every body's swash**: a closed body's own wind raises the wave that runs up its shore ([The swash](#the-swash)) |
| `fetch_km` | 100 | how far that wind has blown over water, km: JONSWAP's fetch; a closed body's swash takes the smaller of this and the lake's own reach (its map's diagonal) |
| `wet_m` | 0.3 | **the wet band**: terrain within this height above the level, near the body, is darkened as wet ground is; 0 none ([The shore](#the-shore)) |
| `foam_m` | 0.6 | **the foam line**: how far in from the waterline foam runs up and back with the waves; 0 none. With a swash, the width scale of the foam riding the front (a quarter of it on the uprush, a tenth on the backwash's lace) |
| `tide_m` | 0 | **the tide**, an open body's: its still level rises and falls by this, metres, at M2's period (12.42 h) on the world clock; a closed body never reads it |
| `drain_s` | 20 | **how long the swash's wet sand takes to dry**, seconds: the wetness above the fringe decays as exp(−t / `drain_s`) since the front last left ([shore](../experiments/shore.md#the-swash)) |

The four optics are `WaterBody` version 2 (2026-10-18) and only the high tier reads them; `shallow`, `deep` and `depth_fade_m` are the low tier's alone. `open`, `wind_m_s` and `fetch_km` are version 3 (2026-10-31, roadmap S93); a closed body reads none of them. `wet_m` and `foam_m` are version 4 (2026-11-07, roadmap S97), read by every body; their defaults are the literature's ([shore](../experiments/shore.md)), so a scene written before them draws the band and the line. `tide_m` and `drain_s` are version 5 (2026-11-08, roadmap S94), and with it a closed body reads `wind_m_s` and `fetch_km` for its swash; a scene written before them has no wind on a closed body and no tide, and draws version 4's shore.

Checked when the scene is read; a body that cannot be drawn (no shape or both, a radius of 0, a polygon of two points or not star-shaped, a roughness or chop out of range, a negative absorption, scattering or turbidity, a transmission outside [0, 1]) refuses the file with a sentence naming the body, and so does a second open body (`water body "ocean" is open, and so is "sea": a scene has at most one open body, whose sea is one plane at its level`).

## The mesh

**Rings to a fan.** The outline is sampled every `spacing` metres along its edge — a circle at angles from a polynomial sine of the module's own (`water::sin_cos`, + − × ÷ only, so the points are the same bits on every toolchain), a polygon along each edge — and copies of that edge scaled towards the centre stand `spacing` apart along the ray through each sample, closed by a fan at the centre. Every ring has the edge's vertex count, so the strips between rings are quads with no stitching, and a vertex's distance from the edge is `(1 - t) |b|`: exact for a circle, and for a star-shaped polygon the distance along the ray from the centre, which is what the shore fade is drawn by. A grid clipped to the outline was the alternative; it puts slivers or snapped vertices along the shore, which is exactly where the fade needs clean triangles. The rings' cost is density near the centre (every ring has the edge's count), which the LOD DAG simplifies away.

**Spacing and budget.** `spacing = clamp(shore_m / 3, 0.25, 1)` m: three vertices across the shore fade. **A 20 m pool** with the default shore: 0.667 m, 95 samples a ring, 15 rings, **1,426 vertices and 2,755 triangles**; the oasis pool (shore 1.5 m, 0.5 m): 126 a ring, 20 rings, 2,521 vertices, 4,914 triangles, 111 clusters. A body whose mesh would pass `k_max_vertices` (65,536) has its spacing grown by a quarter until it fits — a 4 km lake is 45,136 vertices at 23.7 m — which the fade then draws coarser; no limit is hidden.

**What a vertex carries.** Positions are metres from the body's centre at height 0; the instance stands at the centre and the level (`SceneInstance::origin`, ADR-0053), unrotated. The normal is +y and every triangle is wound to face it (the mesh is built with normal cones on: a pool faces up). **The UV is (the distance from the edge, the depth under the vertex)**, metres: the depth is the level less the ground's surface under the vertex (`scene_gen::Ground::surface`, the provider's heights at the whole millimetre), clamped at zero where the ground stands above the water — the shore. The UV, not a vertex colour, because the glTF import carries `TEXCOORD_0` and no colours (AGENTS.md, glTF import), and the half-float UV holds a depth of a few metres to a millimetre.

**Stored through the derived-data cache.** The mesh is written as a GLB (positions, normals, `TEXCOORD_0`, one material named `water` whose base colour is `shallow`) under `water-<hash>.glb`, and its [depth map](#the-depth-map) beside it as `water-<hash>.depth`, where the hash is over the GLB's bytes and then the map's (`body_file_stem`; before 2026-10-19 the GLB's alone), in `<ddc>/water`, where `<ddc>` is **the host's derived-data root** (`--ddc`, `render.load`'s `ddc`: `scene_gen::Context::ddc`, [scene_gen](scene_gen.md#the-derived-data-root), 2026-10-18) — so a game repository's scenes write where its host keeps derived data, not into a `ddc/` of their own — and with no root named, `<repo>/ddc/water` found from the scene's directory, or `ddc/water/` beside a scene outside any checkout (T119; `water_scene_tests.cpp`, "the meshes go under the host's derived-data root"); a file already there under its name is the right one (the map is written first and the mesh last, so a mesh under its name means both are there), and the renderer's cluster cache builds and keys the `.clusters` from it like any mesh — by the GLB's bytes, so the rename cost no cluster build. The name is the bytes' hash, so it covers the body's parameters, the ground under it, `k_mesh_version` and `k_depth_map_version` alike. **The depth is the load's**: a body over migrating dunes keeps the depths of the moment the scene was read (the moving ground's `stand`, when a host has one) until it is read again.

**LOD.** The mesh is cluster geometry, so the DAG applies: far away a pool is a few clusters of large flat triangles. Their interpolated vertex depth is coarser, which is what a body with no depth map is shaded by; a body with one is shaded by the map at every distance, so the LOD cut changes the surface's triangles and not the bottom seen through them.

**The mesh moves** (roadmap S100, 2026-11-08; the models and the numbers are [the shore page](../experiments/shore.md#the-wave-as-height)). A body with a wind — a closed body's own `wind_m_s`, an open body's the wind its spectrum takes — or an open body with a `tide_m` is a **deformed instance** whose pool stage is `gfx::k_deform_stage_water` (`deform.slang`'s water branch, [renderer](renderer.md#the-flora-stage)): every vertex of the frame's cut is lifted by the body's **height function** `water_vertex_lift` (`domain/gfx/shaders/water_waves.slang`, no bindings, mirrored in double by `domain/gfx/tests/water_reference.h`) at its body-local point — its mesh-space position, the instance standing unrotated at the centre and the level, so no world position is read (ADR-0053) — and the frame's water clock. Offshore the height is the body's own waves (an open body's sixteen Gerstner waves' vertical displacement, a closed body's four sines at the material's amplitude); near the shore **the depth governs** the wind's peak wave (H_m0 and the peak period of [the swash](#the-swash)): it shoals by linear theory's coefficient (Green's law, H ~ d^−¼, in shallow water) until it breaks at H = 0.78 d (McCowan), is then the saturated bore 0.78 d to the shore, sharpens its crest as it nears breaking, shortens to the dispersion relation's wavelength at the local depth, and arrives at each place at the time the **arrival field** says — an eikonal solved on the depth map's grid at load (`gfx::water_arrival_field`), so its crests slow and bunch as they come in and bend round the depth's contours. The two cross over k₀d from 1 to 0.35. The surface is then in the visibility buffer: every rasterizer, the resolve's reconstruction and the ray path read the lifted positions through the pool (AGENTS.md, "A deformed instance's positions come out of the per-frame pool"), so R129's reflection rays and the shadow rays meet the water where it stands, and the waterline is where the surface meets the drawn ground, per pixel. **A body with no wind and no tide takes no deform record at all**: it is the rigid instance it was, the bytes S97 drew (`swash_scene_tests.cpp` checks the record; the deform chain test checks that the stage with no waves writes the identity deformer's pool word for word).

**What lost the device on the forest, and the scene that stood flat** (2026-11-09, batch 58). Stage A's binary lost the GPU device in the first frames of every run of the forest proof of concept with a lifted body (batch 57, five runs on v36; again on v37 after the rebase onto R141, `--shadows csm`, only the 0.3 m/s backwater lifted). The cause was the deform table's per-frame copies: a lifted body makes a scene without skinning keep them, and a water frame writes only the water's clock words into its slot's copy and then reads every record from it, while the streamed trees' growth made the table again but not the copies when only the part-pose table had outgrown its room — a tree record made then reached no copy, and the pool pass read it uninitialised. `make_deform_tables` now writes the copies it keeps along with the table ([renderer](renderer.md#the-flora-stage)); the same run is clean, and `lifted_tail_tests.cpp` holds every slot's copy to the table byte for byte after such a growth. The alpha-mask collision (R141) was the first suspect and was not the cause: it is fixed on its own row, and the device was still lost with it fixed. The second gap was found the first time the swash scene's GPU case ran: the pool pass exists only when the settings ask for it, and they did not for water, so a scene whose only moving thing was a windy body (that test's basin) stood flat; `resolve_settings` now asks for the pass for a body with a depth map and a wind or a tide (not in a streamed scene).

**What stage A costs and looks like on v37** (2026-11-09). Cost: R141's binary against stage A's, both msvc-release copied out of the checkout, the forest's engine-only flags with `--raster hw --shadows rt`, four views held 1.5 s each, three repeats, 1920 × 1080 and 3840 × 2160, others' CPU 21–34% (upper bounds): the pool pass +0.002 to +0.006 ms (0.18–0.45 ms in all), the resolve −0.17 ms (eastern-coast, 1080p) to +0.20 ms (lake-bank, 4K), the frame within ±0.2 ms. Pictures: main against stage A at 8 frames a second of the water clock (world rate 1.25, a capture every sixth frame), 6.5 s at shore-open, lake-bank and eastern-coast, on a scratch copy given the proof of concept's two requests (a 2.5 m/s wind on `mountain-lake-east-extension`, `fetch_km` 80 for `eastern-sea` — at 7 m/s a sea is fully developed by about 79 km under Pierson and Moskowitz, so a fetch cannot make its 5.5 s period longer; only a swell can, which is stage B's `swell_period_s`). What a viewer would still say is wrong, most visible first — stage B's order: (1) on the sea the uprush is a **slab**: a flat sheet that runs far up the beach with a hard, bevelled edge at its front, where a real swash thins to a film with a ragged lip; (2) its **foam** is one uniform opaque white band riding the front, where real swash foam is streaky, broken and left behind as the water drains (stage B's foam born at the break and decaying over seconds); (3) the front is now **ruler-straight** along the shore — the loops are gone, but so is any along-shore variation the eye expects from a spread sea; (4) on the lake **nothing visible changed**: a 2.5 m/s wind makes centimetre waves, so the waterline is still a hard line with a thin white foam stripe, and the ripples are the four sines' regular diagonal stripes, which read as a tiled pattern; (5) the **sheet over the sand** reads as tinted glass, with little sky in it and no sun's glint, where a wet film is the brightest thing on a beach towards the sun. No breaking crest is visible from the sea views' eye height: the train's height near the shore is drawn, but at a 5 s period and a metre of height the bore is not yet read as a wave arriving.

**The rim over the bank.** The swash runs up ground that stands above the still level, which a mesh ending at the outline cannot cover. So a ringed body with a wind (or a tide) grows **rim rings** past its outline, `spacing` apart along each sample's ray, outermost first, until every sample that is not deep water at the outline has met ground twice the wind's fetch-limited significant height (the Coastal Engineering Manual's growth law) plus the tide and 25 cm over the level — at most twelve rings and 60 m (`water::Mesh::rim`; the rings inside are the windless mesh's, vertex for vertex). Over the bank the stage puts a vertex on **the sheet's surface** where the swash's front covers it this instant — the ground plus the sheet's thickness, half the front's height over the ground up to a quarter of R and 2 cm — and **5 cm under the ground** where it does not (never higher than the front can reach, so a vertex under a cliff stands no wall up), which the depth test hides; the two regimes blend over 0.2 R + 5 cm of depth. The uprush is then a real sheet with thickness, the recession real, and the hard cutoff at the still level's contour gone. Its limits: **a body that fills grows no rim** (its mesh ends at the contour, and its swash above the level is still drawn on the ground's pixels); the rim's triangles are the ring spacing's, so a gully narrower than a ring step under the swash band can be bridged by a parked triangle; and **an open body's displacement fades to zero over its outline's first `fade_m`** (half the peak's deep-water wavelength, 2 to 30 m, by the vertex's edge distance) so its edge meets the flat plane past it — the sea's rectangle is the band where the shoaling and the breaking are drawn, and the plane beyond keeps its slope-only waves. **Only where the outline stands in deep water** (roadmap S102, `water_outline_fade`): until 2026-11-12 the fade was by the edge distance alone, and an outline drawn along a coast — which a sea's near shore is — took the height out of the surf exactly where it is seen from the beach, half of it 8.6 m off the waterline on the beach scene; in the shallows, where the train has taken over from the table, the lift is whole to the outline (and where an outline crosses the surf, at a sea polygon's ends along the shore, the lifted mesh no longer meets the flat plane: put those ends out of sight or in deep water). The spheres the cull tests are padded by the lift's reach (`InstanceDesc::bounds_padding`: the map's bank, the waves, the bore, R and the tide).

**What the mesh carries, and the rings at the outline** (roadmap S100 stage B, 2026-11-10; the counts and the derivations are [the shore page](../experiments/shore.md#the-shallows)). Stage A lifted every vertex by every wave, and a mesh whose vertices stand metres apart cannot draw a wave a metre long: each vertex took one sample of it, and the samples lay in rings because the mesh is rings — the faceted crests of a windy lake's shallows. Three things changed. **The lift is given the mesh's own spacing** (`gfx::WaterSurface::mesh_far_m`, `mesh_near_m`, `mesh_grade`, from the depth map's file): a wave of the table shorter than twice the spacing is left out of the displacement and one of four spacings is whole — the rule a pixel's footprint already applied to the normal — and the train is held against the spacing as it crosses the mesh, the rings' gap along the ray from the centre and the ring's own spacing across it. What the mesh leaves out the normal keeps: it is evaluated per pixel from the whole function, so the picture's waves do not depend on the mesh's cut. **The rings are closer together at the outline**: a body with a wind has its first gap a quarter of the bore's wavelength where its wind's wave breaks (T√(g H/0.78)/4, within [0.25 m, the spacing the body asked for] and never over the budget's spacing), and each gap inwards 1.15 times the one outside it until it is the budget's (`water::Mesh::near_spacing`, `grade`; the rim's gaps outwards the same, up to 24 rings and 60 m) — so a crest that comes in along the rings is geometry down to where it breaks, for a few rings more and no vertex more a ring. A 20 m pool under 8 m/s: gaps from 0.25 m to 0.667 m, 21 rings where the windless pool has 15, 3 of them rim (`water_tests.cpp`). A body with no wind is the bytes it was (one spacing, no grade). **The sheet's surface goes on under the ground**: past the swash's front the vertex is no longer parked 5 cm under at once but continues at the sheet's own slope (half the front's deficit, down to the same 5 cm; `water_sheet_surface`), so the mesh meets the ground along the front and at a grazing angle, where stage A's covered-to-parked triangle stood up as a kerb with a straight edge. **The field is read smoothly**: the depth and the arrival through a quadratic B-spline over nine texels (`water_field_at`), C1, where the bilinear read's gradient jumped at every texel's border and a crest turned a corner there (203 in 170 m of crest on the test's bay, none now). The field is four floats a texel since this stage — the depth, the arrival, the share of the body's fetch the wind has blown over to reach the texel ([the spectrum](#the-spectrum)), and a spare, which since S102 is the foreshore slope of the texel's own stretch of shore ([the swash](#the-swash)): 16 bytes a texel, 16 MB for a 1,024-texel map where stage A kept 8.

### The depth map

**Why.** Shading the bottom from the vertex depths shows the mesh. The depth interpolated across a triangle is the ground drawn as a piecewise-linear surface over the 1,426 samples of a 20 m pool's rings and fan, so the low tier's fade is Gouraud-shaded per triangle and the high tier's bottom (before 2026-10-19) was a plane per triangle, its slope lighting the sand and its run deciding where the refracted view landed. Looking down on the oasis at high, the owner saw concentric arcs across the pool and lighter triangles near the rim: the ring/fan topology in the picture. Dithering would not have helped: the output encode already dithers, and the facets were geometric. The surface is flat and its normal analytic, so nothing else of the water is faceted.

**What.** `build_depth_map` samples the ground at scene load, from the same `Ground::surface` the vertices sample, on a square grid over the body's bounding square (the edge ring's bounds, the square centred on them). Its spacing is **a quarter of the mesh's**: `size = clamp(ceil(side / (spacing / 4)) + 1, 64, 1024)` texels a side, then `texel_m = side / (size − 1)`, so the grid spans the square exactly. Each texel is the depth under its centre, level less ground, clamped at zero. Texels outside the outline are the bank there, so a refracted view that runs under the shore still finds ground. **The oasis pool**: spacing 0.5 m, so 161 texels a side at 0.125 m over its 20 m square; 51,874 bytes on disk and a 103,684-byte image (the device's allocation of it: 180,224). A 20 m pool at the default shore is 121 texels at 0.167 m. A puddle keeps the floor of 64; a 4 km lake at 23.7 m about 677 at 5.9 m. A body that would pass 1,024 is sampled coarser rather than refused.

**Format.** The file holds a 32-byte header — `EWDM`, the version (`k_depth_map_version`, 2), the size, `bank_max` (version 1: 0), the body-local (x, z) of texel (0, 0)'s centre, `texel_m` and `depth_max`, little-endian — then the texels as **16-bit unsigned, `(depth + bank_max) / (depth_max + bank_max) · 65535` rounded**, rows along +z. **Signed since version 2** (2026-11-08, roadmap S94): on the bank the depth is the ground's height above the level, negated, down to `−bank_max`, the highest bank in the square up to `max(2 m, 2 tide_m + 1 m)` (`k_depth_map_bank_min`), so the shore's slope is known on both sides of the waterline and the swash knows how high the bank stands; a hill beside a pool does not spend the 16 bits. `depth_max` is the body's own deepest texel: the oasis's 2.27 m with its bank keeps a few hundredths of a millimetre a step. A version-1 file reads with `bank_max` 0, as it did (`swash_tests.cpp`). `depth_map_depth` decodes a texel. What it costs: nothing in bytes (the header's reserved word took the bank); every body's map is new bytes, so every body's file name changes once and its cluster build is redone once. The renderer's scene reader (`scene_water.cpp`) reads it from beside the GLB into `SceneWater::depth`, mirroring the layout because the renderer may not call the capability (`water_scene_tests.cpp` holds the two readers to each other). A missing file, or one it cannot read, is no map, with a warning.

**On the GPU.** The GPU scene uploads the map as an **R8G8B8A8 UNORM** image: red is the 16-bit depth's high byte and green its low byte, decoded as `(r · 65280 + g · 255) / 65535 · (depth_max + bank_max) − bank_max` (`water_depth_signed`; the entry's `uv_offset.w` carries the range and `emissive.w` the bank since S94), and clamped at zero for everything that reads a depth under the water (`water_depth_sample`: the bottom, the march, the calm), which a map with no bank is to the bit. Why not R16 UNORM: the RHI's format list has no 16-bit single channel. Why not R32 float: linear filtering of it is optional in Vulkan. RGBA8 filters bilinearly on every device, and the decode is linear in red and green, so filtering the two bytes and recombining them is filtering the depth (to the filter's sub-texel weight precision, a step's fraction of the neighbours' difference). It is sampled through the scene's linear sampler at level 0, with the UV clamped half a texel inside the map, which is clamp-to-edge whatever the sampler's address mode. The material entry after the water's carries it (`gfx::set_water_depth_map`, `k_material_water_depth_map` on the water material): `albedo_texture` the image, `samplers_mr_normal` its sampler, `uv_offset` the map's UV at the body's centre, the UV a metre and `depth_max`, and `uv_transform.w` the half texel. That is the optics' entry at high and an entry of its own at low. The UV frame is body-local metres, computed in double on the CPU: no world position reaches the GPU. **A body with no map** packs nothing, and both tiers read the vertex depths and the triangle's plane as before.

## A body that fills

**Why** (roadmap S97; the grounding is [the shore page](../experiments/shore.md)). A still body's edge is the contour where its level meets the ground. A circle or a star-shaped polygon is the author's guess at that contour: wherever it falls short the water ends in a straight line on a submerged bank, and wherever it overhangs the mesh runs under the ground. A lake in a real hollow (the forest proof of concept's v31 lakes, drawn as polygons of hundreds of points) is rarely star-shaped from any point. So `shape.fill: {seed, max_extent_m}` asks the ground instead.

**The flood** (`fill_body`, `src/fill.cpp`). A square lattice about the seed at the body's spacing (`spacing_for`, the same third of `shore_m` the rings take), `max_extent_m` either way; the region is the nodes whose ground is below the level connected to the seed's node through their four neighbours — a connected component, found by a stack over integer indices, so no visiting order changes it. A seed whose ground stands at or above the level, or a flood that reaches the lattice's border, refuses the scene with a sentence naming the body (`water body "lake": its fill reaches its max_extent_m (500 m) from the seed: the level spills out of the hollow`). A flood whose mesh would pass `k_max_vertices` is run again with the spacing grown by a quarter, as the rings' is; a bound that would make the lattice wider than 4,097 nodes grows the spacing before the first flood. The body's centre, and its instance, is the seed (at the level).

**The region and its edge.** The flood keeps the region's square plus a node of margin (`FillRegion`): each node's value is the level less the ground where the node is in the region, and at most −1 mm where it is not (the bank, or **a hollow below the level the flood did not reach**, which so stays dry). The edge is where the bilinear value crosses zero; it is traced by marching squares (a cell's edge point on each lattice edge between an inside and an outside node, placed by the zero of the line between their values, kept a 64th of a cell off either node so no triangle is degenerate) and the segments chained into loops, then simplified by Douglas–Peucker to a quarter of the spacing (`loop_points`, `loop_starts`). A saddle cell is joined when its four values' mean is inside.

**The general mesher** (`build_fill_mesh`, called by `build_mesh` for a body that fills): a lattice mesh, not an ear-clipped polygon with holes. Every cell with any node inside contributes its inside polygon — the whole square, or the square clipped to the edge by the same marching-squares cut the trace takes — fanned, wound to face +y; a node's vertex and an edge point's are made on first use and shared by the cells that meet there, so the mesh is watertight and the edge's vertices are the trace's own points. Why the lattice over ear clipping: the trace's points already lie on the lattice, so the clip is exact with no triangulation of a polygon with interior rings (an island is just the cells that are out), the interior triangles are regular (the depth map and the waves never see slivers), and the cost is linear in the region. The UV is (the distance from the edge — a chamfer over the nodes, a cell straight and √2 a diagonal, from each node's nearest edge point along its lattice edges — and the depth under the vertex), as the rings' is; the depth map spans every vertex's bounds. **The paraboloid** (`fill_tests.cpp`: 2 m deep, meeting the level 10 m out): 0.667 m spacing, 698 nodes inside, 118 edge points, **816 vertices and 1,512 triangles**, the traced outline within 6 mm of the circle, the mesh's area within 1% of π·10², no vertex's ground more than 5 mm over the level, **1.8 ms** to flood, trace and mesh on MSVC debug.

**What reads it.** The renderer's reader hands the block to the generator, whose `expand` floods each fill body with the scene's ground (the moving ground's, as the mesh's depths are) before it meshes it; everything downstream — the GLB, the depth map, the cluster cache, the material — takes the mesh as it takes the rings. `inside_distance` and `depth_at` answer a flooded body by the region's bilinear value. **A body read without its flood** — `read_body` alone, which has no ground — answers `depth_at` with the ground below the level within its bound of the seed, which includes any other hollow in that square; a holder that has the ground calls `fill_body`, as engine-view's walker does (`Wading::attach`, over the scene's ground at its time), so it wades in the flooded region alone.

**Determinism.** The flood is integer; the values, the edge points, the chamfer and the simplification are f32 + − × ÷ and sqrt over the ground's heights, so the GLB is the same bytes twice and its hash is pinned (`fill_tests.cpp`, taken on MSVC). Circles and polygons go through the rings exactly as before: their GLBs and maps are the bytes they were (`water_tests.cpp`'s pinned hashes, unchanged).

**What stays.** The vertex depth stays in the mesh's UV.y and the GLB is the bytes it was. `depth_at`, which the walker wades by, is untouched, so every walk recording replays bit for bit. The map is the load's, like the mesh: a body over migrating dunes keeps the depths of the read.

## Shading

**The branch** (`domain/gfx/shaders/water.slang`, called as `water_pixel` from `visibility_resolve.slang` where the material carries `gfx::k_material_water`, in place of the BSDF; every other material takes the opaque path exactly as before, which the shading and attributes tests hold at 0 of 255). Per pixel:

- **The normal**: four directional sines over the **body-local point** — the reconstructed surface point less `instance_from_eye`, the instance's own place in the frame, so the waves belong to the body and never to the eye or a world coordinate (ADR-0053), and do not swim as the eye crosses cells. Wave *i* has the body's wavelength and amplitude times {1, 0.62, 0.38, 0.24} and {1, 0.55, 0.32, 0.18}, is turned from the main direction by `chop` × {0, 0.55, −0.8, 0.35} × 90°, starts at a phase hashed from the seed, and travels at the deep-water speed √(g k) **rounded to a whole number of cycles per 1024 s** (`k_water_period_s`), so the frame's clock may be reduced modulo the period in double (`gfx::water_clock`) with no jump at the wrap, and each term of the phase is reduced to a fraction of a cycle before it is added, so `cos` is asked a small angle. Only the slope is evaluated — the mesh stays flat. A wave shorter than twice the pixel's footprint (the larger of the reconstruction's position derivatives, as the ground's detail takes them) is faded out rather than aliased into sparkle, whole at four footprints; every wave dies over the last 0.25 m of depth, so the shore is calm.
- **A lifted body's normal** (S100): the gradient of the same height function the pool lifted its mesh by (`water_surface_normal`, `water_height`'s analytic gradient: the waves' slopes, the train's phase gradient from the arrival field and its height's change with the depth, by a millimetre's central difference), with the Gerstner crests' sharpening, the footprint's fade as above, faded flat over the swash's band and in from an open body's outline as the lift is (the open fade's own gradient and the shore-facing factor's are left out, a few percent of the slope where they change). So the normal is the surface's; the shading test's blocks, which set no surface, draw what they did.
- **Fresnel**: Schlick at water's F0 = ((1.33 − 1)/(1.33 + 1))² = 0.0201 on the wave normal and the view.
- **The reflection**: the sky's radiance along the view reflected off the wave normal, folded above the horizon (`sky_environment`: the scattered sky and the night's glow; never the sun's disc, which the glitter is), or the stand-in's clear colour (`ResolveParams::sky`) in a scene with no sky. **Where the device traces, the scene in front of that sky** (R129, 2026-11-08): one ray per water pixel along the same reflected view, what it meets shaded and seen through the air, the sky where it meets nothing — [Reflections of the scene](#reflections-of-the-scene).
- **The glitter**: the BSDF's own GGX lobe (`brdf_d_ggx`, `brdf_v_smith`, Schlick at F0) on the wave normal at the body's roughness, times the sun's irradiance as the opaque path takes it — through the air with a sky, and through the same shadow query on the flat surface, so a rock's shadow lies on the pool.
- **The bottom**: `shallow` fading to `deep` by the depth over `depth_fade_m` — the depth under the pixel sampled from the body's [depth map](#the-depth-map) since 2026-10-19 (the mesh's interpolated UV.y for a body without one, and before), which the waves' calm at the shore reads too — lit as a level surface by the sun (E/π) and the ambient of a level surface (the sky's harmonics, or the stand-in's hemisphere), darkened by `exp(−3 · slant / depth_fade_m)` where `slant = depth · (1/cos θt − 1)` is the extra path of the refracted view (θt by Snell at 1.33) — so looking straight down shows the authored colours and a grazing view sinks into the deep.
- **The shore**: `k = clamp(edge distance / shore_m, 0, 1)`; colour = bottom · (1 − F k) + (sky · F + glitter) · k, so the very edge is the bottom alone — wet sand — and the reflection comes in over the shore band. Then the resolve's aerial perspective and exposure, as for every surface.

**The clock.** `ResolveParams::water_time_s` (the block's last pad word) is the frame's world time — `FrameDesc::world_time_s`, real time scaled by the world rate, since 2026-10-20 (roadmap R88; [renderer](renderer.md#one-world-clock-and-the-days-length)): the waves run at real speed whatever the day's length, pause at a world rate of 0, and no longer freeze under a held sun; until then it was the ground's surface time plus `FrameDesc::sun_time_s`, the one clock the sky read, so a 60× day ran them at 60× — reduced modulo the period in double. The sun's glitter on them is the sun's place at the sky's hour and the waves' at the world's: a sixty-minute day draws the same waves a real day does at the same world time, and only the sun moves faster (`water_scene_tests.cpp`: with the sky held and the world 7.5 s on, every pixel that changes is the pool's). It is filled where the resolve's block is written, `scene_renderer.cpp` (since 3b92cd06, 2026-10-18; before it the waves stood still at their phase at time zero); a replay draws the same water either way.

**The reference** (`domain/gfx/tests/water_reference.h`, the branch again in double; `water_shading_tests.cpp`): a level quad with the water mesh's UVs under a known sun and the stand-in sky, five blocks — waves at two clocks and two roughnesses, a mirror, the shore — every fourth pixel of the middle half against the reference: **worst 1 of 255** on the RTX 5090's mesh path (2026-10-17), within the BSDF's 2. The clock moves the picture. The phase hash and the cycle rounding are integers and are mirrored exactly.

**What it costs** (`engine-view --benchmark` over a five-second path looking down on the pool, the water about 70% of a 1920 × 1080 frame, `msvc-debug`, RTX 5090, 2026-10-17, `machine_state` start: GPU 0%, others' CPU 6–10%; end: GPU 90–94% — this run's own): the resolve's median **0.178 ms with the water drawn as a plain dielectric (stage 1) and 0.189 ms with the branch**, +0.010 ms, about 7 ps a water pixel and 6% of the resolve. The footprint's derivatives and the four waves are most of it.

**The branch is in the water modules only.** `visibility_resolve.slang` compiles it under `RESOLVE_WATER`, which `visibility_resolve_water.slang` and `visibility_resolve_rt_water.slang` define before they include it; the plain and ray-traced modules every other scene draws with have no branch at all, and are the SPIR-V they were before the water. The renderer draws with a water module only when its scene has a water material (`GpuScene::has_water`; [renderer](renderer.md#materials)). Why: the frame budgets (ADR-0018). A fragment shader's registers are allocated for its largest path whether a pixel takes it or not, so the branch in the one resolve cost every pixel of every frame — `gpu_ms.resolve` on `erg-walk-surround3-rt`, a ray-traced surround frame with no water in it, went from 2.316 to 2.793 ms median and failed its budget (2026-10-18, on a quiet machine), while a 1080p frame *with* water had measured +0.010 ms. A change to the branch is measured on a frame without water as well as on one with it.

The material entry (`gfx::set_water_material`): `albedo` = shallow, roughness; `emissive` = 0; `uv_transform` = deep, `depth_fade_m`; `uv_offset` = amplitude, wavelength, chop, `shore_m`; `normal_scale`, `occlusion_strength` = the waves' direction (x, z); `sampler` = the seed; `flags` = `k_material_water`. Those are the slots an untextured material with no UV transform never reads, so every reader that is not the branch — the reference path tracer, the albedo view — sees an untextured dielectric of the shallow colour, the UVs passing through unscaled.

**What the low tier looks like** (the oasis pool's markers, `engine-view --marker-captures`, 2026-10-17). From the east shore with the sun behind (`east`), the pool reads as water: blue-green and dark over its 2.3 m middle, pale where the sand comes up through the shallows, a thin bright rim of wet sand at the edge, the waves a fine regular chop that catches the sky's paler blue at grazing; the near rocks stand at the shore. Looking down from nine metres (the cost path below) the sun's glitter is a scatter of bright crescents on the wave crests where the reflected view meets the sun, the bottom darkening from the shore to the middle. Low across the middle (`across`) the waves fill the foreground, lighter where they face the sky, under the far shore's rocks. What does not look right yet: four sines make a visibly regular pattern overhead, the waves stood still until the clock was wired (above; they move since), the rocks do not reflect (the sky's model has no geometry in it; a reflected rock needs the forward pass or a ray, S86), and nothing is seen through the surface — which the high tier, below, is.

## Reflections of the scene

Roadmap R129 (2026-11-08; the owner, 2026-11-07: "bodies of water we need to get the reflection in"; engine-needs v35 item 5, the lakes reflecting only the sky). Until then the branch reflected the sky alone, and the far shore, the forest and the mountain were not in the water.

**The ray** (`domain/gfx/shaders/water_reflect.slang`, `water_reflection`, called by the low tier's and the volume tier's surface in place of the sky they take — so the sea's plane, the channels and every body share it). One ray per water pixel from the reconstructed surface point lifted by `ray_offset` (the receiver's own grid, as a shadow ray leaves) along +y, in the view reflected off the **wave normal** (`water_reflected`, so the reflection ripples exactly as the sky's did), against the frame's top-level structure, out to `gfx::k_water_reflect_m` = 4 km — the far shore of a lake a few kilometres across; past it, and where the ray meets nothing, the sky stands as before. A reflected view within 1e-4 of the surface (`r.y`) takes the sky without a ray. What it meets is shaded by `shade_hit` (`hit_shade.slang`) and then seen through the air between the surface and the hit (the frame's aerial table along the ray, which is the eye's; the surface is metres from it). The result is what the Fresnel term takes; **the glitter is untouched**, and so is everything under the surface.

**What the ray meets: the shadow rays' structure, kept nearest.** It traces with the caster bit (`k_ray_mask_caster`), so it meets what a shadow ray meets and nothing the caster policy leaves untraced (grass in a forest is not in the water). Its query has no flag of its own: with the scene's masks a non-opaque candidate is decided as the shadow rays decide it — a masked pair by its mask at level 0, the opaque proxy's solid clusters, the two-state micromaps, any other non-opaque pair (a **caster**) as solid — and without them every candidate is forced opaque. Primary rays (`RAY_FLAG_CULL_NON_OPAQUE`) pass through casters; this ray must not, because the geometry it exists for is casters (below). So a tree's cards and impostors are in the water as their shadows are cast.

**What the structure holds for it: the mirrored caster volume** (`systems/renderer`'s `water_reflect.h`; [renderer](renderer.md#shadows)). A reflection's volume is the **mirrored frustum**: what a level surface shows is what a camera reflected in its plane sees, and the frame's cut does not hold it — a tree over the eye's shoulder, a mountain above the frame's top edge. A screen-space reflection would lose exactly those, which is why it was not the design. Every view's cull block carries one more caster volume behind the lights' — the view's closed frustum reflected in the water's level, cut by the level (only what stands above the water is reflected) and held within 4 km of the eye — so a pair the view's frustum rejects and that volume holds is a **caster**: the camera's LOD, built into the frame's structures non-opaque, counted in `Stats::shadow_casters` and the chain's capacity, dropped first when the capacity runs short, never drawn. **Why a volume and not a run of its own**, as the cascades have: a pair the view's frustum keeps is drawn or a cone caster already, so a mirrored run would put it in the structures twice and break the drawn/caster partition the chain's index space rests on; the volume costs the frustum-rejected pairs one more plane test each and needed no change to the cull shader. What that gives up: the cull counts the mirrored casters with the shadows', so the frame cannot say how many the water asked for — `Stats::water_reflect_views` says which views carried the volume and `water_reflect_level_m` its plane, and a measurement takes the difference of `shadow_casters` with the reflection cycling (below).

**One plane a frame** (`GpuScene::water_reflect_level`): the open body's level when the scene has one (the sea is the largest water there is and is everywhere), else the level of the level body **nearest the eye** — the distance to its depth map's square, or to its instance's origin without a map; a channel, whose surface slopes along its flow, is never the plane. Nearest rather than "the largest drawn last frame" because it needs nothing read back from the GPU, and the body the eye stands by is the one whose reflection fills the picture. A body at another level still traces: it reflects everything the structures hold, and loses only what stands outside every view and outside the chosen plane's mirrored frustum.

**The hit** (`shade_hit`, gi_update.slang's bounce copied rather than shared, the cache's files being R69's). Decoded as the bounce and the reference path tracer decode one — `hit_visible_entry`, `hit_pair`, `fetch_triangle` (a deformed caster's pool block included), `material_of` — and shaded as: its emission; its base colour at the mip the ray's footprint selects (this view's pixel angle times the eye-to-surface-to-hit path, times the triangle's UV per metre), or, for a **terrain** hit (`k_material_terrain_layers`), [the ground's own material at the hit](#a-hit-on-the-ground) — the masks' blend of the layers' mean colours and roughness, not the stochastic sampling the ripples would hide; lit by the sun through `brdf_direct` under **one shadow ray from the hit at half rate**; and the ambient the resolve would give it (the sky's harmonics, or the stand-in's hemisphere, through `scene_ambient`, so the world-space cache where `renderer.gi.mode` is on). No normal map, no ground detail, no point lights: the reflection is broken by the waves and seen at a Fresnel of a few percent over most of the water.

**The half rate.** The hit's shadow ray is traced at the pixels where `(x ^ y) & 1` is 0 — two of every 2×2 block, a checkerboard — and the other two take the sun unshadowed. A pixel shader cannot borrow its neighbour's answer safely here (the water's pixels are a divergent branch, and a quad read across its edge is undefined), so the unshadowed half is the estimate; it halves the contrast of a shadow seen in the water (a shaded side under a canopy reads lighter by half its darkness), which the ripples and the Fresnel blur further. `renderer.water.reflect_shadow` 2 traces every pixel's, 0 none.

**The switches.** `renderer.water.reflect` (0 off, 1 on — the default wherever the resolve traces: `--shadows rt` or the hybrid on a device with ray queries; 2 on in even frames and off in odd ones, so one flight measures both; 3 a cycle of four frames — off, then on with no hit shadow, at half rate and at every pixel), `renderer.water.reflect_volume` (true; false reflects only what the frame's cut holds, which is the test's way to show what the volume adds), `renderer.water.reflect_shadow` (1; **3 is the diagnostic**, a measurement switch: each water pixel a colour saying what its rays met — red where the rippled ray met nothing, green where it met a surface, blue added where the ray a flat mirror would send from the same point met one — scaled past any exposure so a capture's channels read as bits; both rate bits at once, which no rate sets, so it costs no bit of its own). The resolve reads them as `ResolveParams::shadow_flags` bits (`gfx::k_shadow_water_reflect`, `_full`, `_unshadowed`), so the block keeps its 544 bytes. Where the device has no ray queries, or shadows are the cascaded maps or off, the resolve draws with a module without the ray (the plain water module keeps the sky) and the volume is never fit: the water reflects the sky alone, as it did.

**The modules.** Only the ray-traced water modules (`visibility_resolve_rt_water` and its `_terrain`, `_stochastic` variants) include `water_reflect.slang`; every other resolve module — the plain ones the two surround budget scenes draw with, the plain water modules, the half pass, the cache's passes, the reference path tracer — compiles to the bytes it did at 58288431 (slangc's output hashed against the base's sources: `visibility_resolve` `DF72DB95…`, `visibility_resolve_rt` `532437D9…`, `visibility_resolve_water` `7095F66E…`, `_terrain` `221E0C07…`, `_rt_terrain` `C03363C1…`, `_water_terrain` `4B4B299E…`, `_stochastic` `91F4AC33…`, `_rt_stochastic` `2A409046…`, `gi_update` `E59C2D23…`, `resolve_half_sun` `1871CD15…`, `path_trace` `3E1097D6…`), so a scene without water draws with the bytes it did. R129's second step (the ground's material at a hit, the diagnostic) changed the four ray-traced water modules alone: the other 33 of `domain/gfx`'s modules, the terrain resolve modules, `gi_update` and `path_trace_terrain` among them, are the bytes they were at 2d867dd2 (both builds' SPIR-V hashed, 2026-11-09), because `terrain_hit_material` is a function nothing else calls. The oasis pool, whose ground has no layers, captured from the same pose with the binaries before and after, is the same PNG to the byte: a non-terrain hit is shaded as it was. The shading test's blocks set none of the bits and draw what they did.

**What holds it** (`systems/water/tests/reflect_scene_tests.cpp`, on a device with ray queries; a pool filling a basin 30 m across of the renderer's ground and a red box 8 m tall standing on the far shore). From the south-west shore across the pool: with the reflection on, the box's red is in the water's pixels — counted as water pixels whose red rises four codes more than the others — and every pixel that changes is the pool's, no id changes, the same frame twice is the same bytes. Half a metre over the water looking down 31° towards the box, at a 60° field of view, the box stands wholly above the frame's top edge, and with the sun's off-frustum caster volume off (`RenderSettings::off_frustum_casters`, which would otherwise build the box as a shadow caster when it stands in the sun's sweep): the volume (`reflect_volume` on against off) reddens more than a hundred water pixels with the box's red over the picture without it (on 2026-11-08, against the sky alone, 4,015 water pixels reddened with the volume and 242 — the reflected ground — without it), changes no pixel but the water's, and adds its casters to the frame's (21 → 31) — the one picture that proves the volume earns its keep.

### A hit on the ground

R129's second step (2026-11-09; the owner on v37, and the POC's item 24 on v36: the lake's far bank is tan sand and its reflection was uniformly green, under `renderer.gi.mode=sky` as under `bounce`, so the hit's shading and not the cache). Until then a terrain hit was shaded by the record's **first** layer's mean colour and roughness, and the first layer of the forest's ground is its meadow. The cost argument behind the shortcut was right and the shortcut one step too short: the layers' **means** are cheap — the layer record carries them — and what was skipped was the **weights**.

**What a terrain hit reads now** (`terrain_hit_material`, `terrain_material.slang`, called by `shade_hit`): the masks' weights at the hit (`terrain_mask_sample`, the tile's words through the same record the resolve reads, so a hit on a world tile, a far ring's chunk or the scene's own ground finds its tile's masks alike), at the mip the ray's footprint selects (`log2(footprint / spacing)`, the resolve's rule with the ray's width for the pixel's), blending the layers' mean colours and roughness by them; the height blend at the layers' mean heights; the root under a cover short of one; snow's albedo by its grain and the beach's own wetness on their record words (R99); porous ground's wetness (Lagarde) at the mask's wetness; a painted (`Map`) layer read from its map at the footprint, its mean being the whole map's; and **the shore's wet band** (S99) — `water_ground_wetness`, the same records and the same call the resolve makes for a ground pixel, at the hit's point — so the dark strip where a bank meets the water is in its reflection. W68's layers (no masks) are read the same way: each layer's weight times its coverage map at the footprint. What it leaves out, and why: the stochastic lattice, the detail and normal maps, the normal-variance roughness (R97), the formation's bands (W85) and the glints (R99) — the ripples hide them, and each is a fetch or more a layer for a share of the ground a reflection does not resolve. The formation's bands are the one a reflection of a desert's cliffs would show; they cost `formation_band`'s box filter over the beds, a dozen reads a hit, and no water this engine draws stands under one yet.

**A function a second caller can use.** `terrain_hit_material(geo, root, point, footprint_m, out sampled, shore_s, shore_film)` takes nothing of the resolve's block — the scene's tables, the hit's frame-local point and a footprint — and returns false for a root with no layers, so a caller keeps its own read for that case. The GI bounce (`gi_update.slang`, renderer.md "Indirect light", stage 1b) reads the material's base colour at level 0, so sunlight bounced off sand is not sand-coloured either; it would call this with the cache cell's width at the hit as the footprint and no shore (the bounce has no water records), in a module compiled with `MATERIAL_TERRAIN` and `terrain_material.slang` included.

### The stripes

The POC's item 17 (v35, still at the owner's mark 7 on v37): the forest across the lake reflected as radial bands of alternating reflection and sky, like corduroy. **Diagnosed 2026-11-09 with the diagnostic** (`renderer.water.reflect_shadow` 3, v37's copy, `msvc-release` engine-view at 1920 × 1080 with the owner's engine-only flags, at `lake-bank`, `shore-open` and mark 7's eye and back): the stripes are **the waves**, not the reflection's machinery. Over most of the lake both rays meet the scene (cyan); the stripes are confined to the band where the reflected view crosses the far treeline, and there they are magenta and green streaks along the wave crests — the rippled ray sent over the trees into the sky where the flat mirror's ray from the same point meets the forest, and the reverse. Below that band, near the eye, both rays miss (red): a steep reflection passes over the treeline, and the sky stands there as it should. So:

- **Not dropped casters**: the flat mirror's ray meets the forest across the whole band the stripes cross, and the chain built everything it wanted on every frame measured (`rt_wanted` = `rt_built`: 3,874 at `lake-bank` and 5,292 at mark 7's eye at 1080p, 4,784 and 6,542 at 4K; `shadow_casters` 152,643 and 304,521 at 1080p); a caster the capacity or the pair budget withheld would be a miss of both rays, red inside the forest's reflection, and there is none.
- **Not the half rate**: it shades a hit and moves no ray, and would be a checkerboard, not streaks along crests.
- **Not the reach or the volume**: the misses past the treeline are the flat mirror's too, the sky above the forest.
- **The wave normal**: the lake's four sines (wavelength 5 m, amplitude 0.035 m, chop 0.25: crests turned 0°, +12°, −18° and +8°, nearly parallel) each tilt the normal by a·k ≈ 0.033–0.044 rad and together by up to 0.15, so the reflected ray swings by up to 17° — more than the far forest's height subtends from the water a few hundred metres off. Where the reflection meets the treeline, each crest sends it above the trees and each trough below, in the crests' own regular pattern. A real lake does the same with an irregular field, which reads as the treeline's reflection broken; four near-parallel sines read as corduroy.

The fix is the waves' (S100's `water.slang`): an irregular field with a spread of directions — the spectrum the open sea already draws from (JONSWAP with Donelan-Banner spreading, [The spectrum](#the-spectrum)) for a closed body too, or the four sines turned much further apart — not the reflection, which reflects the normal it is given. Not changed here.

### What it does not do

One plane a frame (above). Everything a ray needs a device to trace; a device without ray queries reflects the sky. The hit's shadow at half rate; no point lights, normal maps or ground detail on the hit. No second bounce: a reflected surface is lit by the sun, the sky and the cache, and a reflection of the water itself (another body's surface, met from above) is that material shaded as a plain dielectric. The ray leaves the level surface: what the waves would hide behind a crest, and the reflection's own distortion by a wave's height (the waves are slopes on a flat mesh), are not drawn. A water pixel farther than 4 km from what it would reflect, or a mirrored object past 4 km of the eye, takes the sky. Under the surface, what the volume tier's refracted view meets is [What is under the water](#what-is-under-the-water)'s (S86); the reflection is not refracted again.

## The shore

Roadmap S97 (2026-11-07); the grounding and the numbers are [the shore page](../experiments/shore.md).

**The waterline per pixel.** Every body with a depth map carries `gfx::k_material_water_shore` (`set_water_shore`, written by the GPU scene after the map). With it the branch takes the distance it fades the shore by, and draws the foam by, from **where the map's depth is zero** — the depth here over the map's slope, the larger one-sided difference either way along each axis, so at the waterline, where the map is clamped at zero on the bank, the water's side gives the slope (`water_shore_distance`, four more reads) — rather than from the mesh's edge (UV.x). `shore_m` keeps its meaning, metres in from the edge, but the edge is the ground's. A water pixel where the map says the ground is at or above the level has a distance of 0: the surface's terms (the reflection, the glitter, the foam's line) are faded out and the pixel is the bottom alone — in the volume tier the terrain's own colour under no water, at the low tier the shallow colour. **What "discarded" means in a visibility buffer**: the buffer holds the water's triangle and nothing behind it, so a water pixel cannot be removed for the ground to show; where the drawn ground stands above the level it is nearer than the flat water and wins the depth test anyway, so the water's mesh overhanging the shore is hidden by the ground wherever the rasterized ground agrees with the map, and where it does not (a coarse LOD of the ground, a mesh that overhangs onto a lower drawn ground) the branch draws the bottom alone there. **An authored body whose polygon falls short of the shore** shows what it always did: the mesh ends first, in the polygon's line, now with the reflection reaching that line (the fade measured from the true waterline beyond it), where before it faded to the bottom along it. One whose polygon overhangs now fades where the map's depth reaches zero, inside the polygon, instead of at the polygon. An open body's fade (by depth over the waves' calm) is replaced by the same distance, which is still zero at its sea's coast. The shading test's blocks set no shore flag and draw what they did (`water_reference.h` does not mirror the shore; the scene tests count it).

**The wet band** (`wet_m`, default 0.3 m: the capillary fringe of sand). The GPU scene writes one `gfx::WaterShore` record a body with a map and a `wet_m` (or, since S94, a [swash](#the-swash)) — its instance, `wet_m`, and the map's square, body-local, grown by 25 `wet_m` + 1 m (where a 1:25 bank rises `wet_m`) — into a buffer the resolve's water modules read through `ResolveParams::water_shores` and `water_shore_count` (a new 16-byte row: the block is 544 bytes, R69's two rows before it, and only the water modules declare it, so the plain modules are the SPIR-V they were). In the water stage, a pixel of a terrain's material (`k_material_ground_detail`, `k_material_terrain_layers` or `k_material_terrain_map`) whose height above a body's level — its point less the body's instance's place in the frame, the instance standing at the level — is in [0, `wet_m`) and whose body-local (x, z) is inside the record's square has a **saturation** eased from 1 at the waterline to none at `wet_m` (`water_wet_saturation`, the capillary fringe's smoothstep), which the ground's material takes before any light sees it — **since S99 wet ground is a material, not a tint** ([terrain](terrain.md#wet-ground), `wet_ground.slang`): Lekner and Dorf's darkening of its albedo scaled by its porosity, its roughness lowered, and a film once the pores are full, so the sun's highlight, the sky's ambient and the shadows all see the wet surface. Until S99 this was a multiplier on the shaded colour (`water_wet_factor`), which darkened the highlight with the rest. Any ground in the square at that height is darkened, including a rise inside another hollow below the level. A body with a `wet_m` of 0 writes no record. **Its cost** (S99, v35, msvc-release, 2026-11-08): a pixel that is not ground pays nothing, a ground pixel one bounds test a body's record plus the banks' tree walk ([The banks](#the-banks)), which put the resolve's median up 0.35 ms at 1080p at shore-open and 1.30 ms at the stream ([the table](../experiments/shore.md#what-it-costs-and-what-it-looks-like)).

**The foam line** (`foam_m`, default 0.6 m: a lake's swash). With the shore flag, the branch draws foam `water_foam` over the surface: a line a tenth of `foam_m` wide running up and back between 0.3 and 1 of `foam_m` from the waterline at the largest wave's phase at the pixel, a thinner trail of the backwash between it and the waterline, broken by value noise at a quarter of `foam_m`, strength the waves' amplitude over 2 cm (a mirror has none), fading to nothing at `foam_m`; a line narrower than the footprint is widened to it and dimmed by the same share. Foam's albedo is 0.55 (fresh foam, Koepke 1984), lit as a level Lambertian surface by the sun at the surface (its shadow included) and the sky. The reach is the next entry's `normal_scale`. The open sea's plane draws no foam (only the mesh's pixels ask).

**What it looks like** (2026-11-07, `engine-view` msvc-debug, 1920 × 1080, `--raster hw --shadows csm`, 15:00, under the GPU lock). A basin of the renderer's dunes filled from its middle: the water ends on the basin's contour, a thin darker band of wet sand lies just outside it, and on the lit side a broken foam line runs a few decimetres in from the edge as a line, not a stripe (at foam albedo 0.4 it was a grey-blue thread darker than the sand under it, which is why 0.55 is pinned). The v31 terrain-only scene's `v28-lake-inlet-backwater` made a fill from a seed in its channel: its 13-point polygon enclosed dry ground (its centroid's ground is above the level, which the flood refused with its sentence), and the level at −2 m connects the inlet to the lake east of it, so the flood took a 1 km bound and drew the channel and the lake as one body meeting at the contour; the wet band darkens the banks as a band along the waterline and, on the flat beach a few decimetres above the level, a broad wet flat, which is what a 0.3 m fringe over a 1:100 beach is. Its load in msvc-debug took about a minute more than the polygon's (the flood at spacings grown to fit the vertex budget, the 1,024-texel map and the new mesh's cluster build).

**What holds it** (`shore_scene_tests.cpp`, on a GPU, a body that fills a basin of the renderer's ground): the wet band changes no id and darkens pixels, none of them water, more at 0.6 m than at 0.3 m and none at 0 (no record). **Lighter is the film's, and only by the film's light** (S99, 2026-11-08): until S99 the band was a darkening alone and "no pixel it changes is lighter" was exact; wet ground now carries a film where it is saturated, and a film reflects the sky — brighter than the dark ground under it, which is what water on dark ground looks like (12 pixels in a line at the waterline, among the darkest 2 % of the ground, +1 to +7 codes, mostly blue). So the check is two: with the film off (`renderer.water.wet_film` false, **a measurement switch**, `gfx::k_shadow_wet_film_off`: the darkening and the damp roughness with no film roughness and no film reflection) no pixel the band changes is lighter — the darkening alone, exact as before; with it on, every pixel lighter than the dry one is a pixel the film changed (set membership against the film-off shot), and no pixel the film changed gains more, in any channel, than the film's own reflection of the sky can give there — a bound derived per pixel (`film_code_bound`): the film adds at most `k_sky` × water's environment Fresnel (`brdf_env_specular` at F0 0.0201) at the shader's least roughness and the least n·v the pixel's 8-bit normal and the eye ray allow, through the concave encode, the dither's step and the store's rounding. The case runs with the water's traced reflection off, so the light the film reflects is the stand-in sky the bound knows; what the film does with the traced scene is `reflect_scene_tests.cpp`'s, whose "the reflection changes only the water" is now exact with no band (`wet_m` 0) and, with the schema's 0.3 m band, holds every pixel off the water that the reflection changes to the set the band itself changes with the reflection off, all of them ground (16 pixels in one row at the waterline). The 2026-11-08 run: the film changes 1,086 of the basin's pixels, the same 12 of them lighter than dry ground (what the old check refused, so the film-on shot would still fail it), every one inside the bound. The foam line changes only the water's pixels, a share of them, and no id; the same frame twice is the same bytes. These are a body with no wind and no tide — version 4's shore, which the swash leaves as it was.

### The swash

Roadmap S94 (2026-11-08), continued by S100 the same day; the models, the derivation and the numbers are [the shore page](../experiments/shore.md#the-swash). **Since S100 the swash is a train and the water has height**: a lifted body's record carries its surface (`gfx::WaterShore::surface`, 80 bytes now), and the place's phase is the wave's **arrival** at it (the arrival field, flat across the bank, so a place on the beach takes its shoreline's: neighbouring places are in sequence and the front is one connected line that advances and retreats), its reach R times the group's shape times a smooth along-shore variation in [0.85, 1.15] over two peak wavelengths (the crest's length under a spread sea) times the shore's facing — no per-place phase drift and no jitter, which were what made S94's front a field of independent oscillators whose level set folded into loops (the diagnosis is on [the shore page](../experiments/shore.md#the-wave-as-height)). The water pixel's depth is the lifted surface's height over the ground. The paragraphs below describe the closed form, which holds unchanged on the train's phase. **What it is**: with a wind (a closed body's own `wind_m_s`; an open body's the wind its spectrum takes) or an open body's `tide_m`, the waterline is no longer the still level's contour: it runs up the shore with every wave and back, some waves further than others, raggedly along the beach, and the sand it leaves is wet and dries from the top down between sheets. A body with neither draws version 4's shore exactly (the static band and the foam line of the waves' phase), and the S97 tests above hold it.

**Since S102 the swash is its stretch of shore's, and the sheet's time is the slope's** (roadmap S102, 2026-11-12; the audit, the models and the design are [the shore-mechanics page](../experiments/shore-mechanics.md)). Until then a body had one run-up and one slope, and every sheet took exactly one period on any beach: up in 0.4 T, back by T. That is a clock, and it is why a gentle beach and a steep pocket of one sea moved alike and no bore ever met the backwash of the one before. Three things changed, all on a lifted body. **Each stretch of shore has its own slope**: the field's fourth float is the ground's gradient where the level meets it, at the nearest stretch of waterline to the texel (`gfx::water_shore_slope_field`: the waterline's wet texels, averaged along the waterline within three texels so a grid's staircase is not read as a slope, carried to every texel by a 3-4 chamfer), so a pixel on the beach, and the water at its foot, know the slope *their* shore has. **Its run-up is Stockdon's on that slope** (`WaterSurface::reach_scale`, the formula with the slope taken out, evaluated per pixel), no higher than 1.97 deep-water wave heights (Van der Meer's ceiling for a rock slope, where a sandy beach's fit grows without bound) and than 0.68 of the depth map's bank range (so the front is never over ground the map cannot show); the record's own `run_up_m` is the most any stretch can have, for the bounds and the ground's band, and a ground pixel above its own stretch's reach leaves at once with the fringe's damp. **A sheet lasts as long as its slope keeps it** (`gfx::swash_span`, `water_swash_span`): a front slowed by gravity alone climbs a height E in √(2E/g)/β seconds whatever launched it (Shen and Meyer's projectile), and with the uprush 0.4 of the sheet's life the sheet stays D = √(2E/g)/(0.4 β T) periods, kept to [0.25, 5]. Under one, on a steep shore beneath a long wave, the sheet is up and back and the sand is bare until the next; over one, **the next bore arrives over the backwash**, and the waterline is the highest of the sheets still on the beach — at most five (`water_swash_front_at`, shared by the pool's lift and the resolve). The beach scene's 1.1 m, 4.7 s sea: 0.31 m up its 1:30 beach with each sheet 3.5 to 4.4 periods long, so three and four bores stand on the sand at once and the waterline never falls back to the still level; 0.68 m up its 1:8 pocket in 1.4 to 1.7. The wet sand's age is still a closed form — the least, over the last twelve waves, of the time since each one's sheet left the height (`water_swash_age`, the search ending once a wave further back cannot beat the best) — and the foam's sums run over the sheets that can still be climbing. The model in double is `water_swash.h`'s, with `SwashPlace::slope` 0 keeping S94's one-period sheet for the closed forms' own tests. **What it does not do**: (the height that reaches a stretch is the energy-flux field's since the second pass, [The surf](#the-surf);) the slope is the waterline's, not the mean over the sheet's excursion; and a sheet's life past five periods — a beach flatter than about 1:40 under a short sea — is cut there, since that beach's motion is the infragravity band's.

**On the CPU, once a body** (`GpuScene::upload_water_shores`, `domain/gfx/water_swash.h`): the wind's wave over the fetch — JONSWAP's peak period and the spectrum's significant height H_m0 = 4√m₀ integrated over [0.3, 6] ω_p, the same fetch laws [the spectrum](#the-spectrum) takes (5 m/s over 2 km: 0.13 m and 1.34 s; 10 m/s over 20 km 0.87 m and 3.6 s); a closed body's fetch the smaller of `fetch_km` and its own longest reach along its wind (`gfx::water_fetch_field`; until S100 stage B the diagonal of its depth map's square). The foreshore slope β is the map's slope across the waterline (the mean of every texel pair that straddles zero, kept to [0.01, 0.5], 0.1 where the map crosses nowhere; `gfx::water_mean_shore_slope`, which was the GPU scene's own function until S102) — the body's one number, which since S102 a lifted body's pixels replace by their own stretch of shore's. Stockdon et al.'s R₂ from H, T and β is the run-up; the period is rounded so the water's 1,024 s clock holds a whole number of groups of seven waves. Since S100 stage B the closed body's surface is the same spectrum's ([The spectrum](#the-spectrum)), and its fetch is its own reach along its wind, not the square's diagonal. The record (`gfx::WaterShore`, 64 bytes since S94) carries R, T, β, the drain, the tide, H, `foam_m`, `shore_m` and the water material's index; it is written for a body with a map and a `wet_m` or a swash, so a body with neither still writes none.

**Per pixel, a function of the clock** (`water.slang`, "the swash"; mirrored in double by `water_swash.h`): the front's height over the still level is a ballistic swash — up in the first 0.4 of the sheet's life, decelerating, and back over the rest, accelerating, both halves parabolic in time, from and to 0.2 R below the level; the sheet's life was one period until S102 and is the slope's since (the paragraph above), the waterline the highest of the sheets on the beach — whose reach is R times the group's shape (0.57 at the group's ends to 1 in its middle) times, on a lifted body, the smooth along-shore variation and the facing above with the phase the train's arrival, and on a record with no surface (a tide alone) S94's jitter in [0.7, 1.3] of value noise of the body-local point with a phase drifting by up to 1.5 waves along the shore over a scale of the larger of 4 m and three swash widths. **Stage A is not yet usable on a real scene**: on 2026-11-09 every run of the forest proof of concept's v36 with a lifted body lost the device in its first frames ([the shore page](../experiments/shore.md#stage-a-on-the-gpu-a-device-lost-on-v36-2026-11-09) has the split and the suspects). An open body's tide adds tide_m · sin(2π φ), φ the frame's world time over M2's 12.42 h computed in double on the CPU (`ResolveParams::water_tide_phase`, the old pad word), since the water's clock wraps every 1,024 s.

- **The water's pixels** (the branch, `water_pixel`): the branch finds its body's record by its material's index. Near the shore — within 1.5 R + the tide + 25 cm of depth, faded out over as much again, so deep water is the depth it was — the depth is the signed map's plus the tide and the front, and the shore distance and the fade are measured from that instantaneous waterline. A pixel whose ground the backwash or a falling tide has bared is the bottom alone, **the ground's own material at the wetness the clock gives it** (S99: `water_pixel_volume`'s `bared_s` hands the saturation to the bottom's terrain material, or to its plain albedo over the default porosity; the low tier, which draws the bottom as the body's shallow tint, darkens that tint). Until S99 it was darkened as a fixed sand of albedo 0.35.
- **The ground's pixels** (the resolve's water stage, `water_ground_wetness` → `water_swash_saturation`, **before the material**; S99): within the record's square — grown by the distance a 1:25 bank rises the larger of `wet_m` and 1.25 R + the tide — a terrain pixel under the front is under the sheet: saturation 1 under a whole film; above it its saturation is the capillary fringe's damp floor (half, smoothstepping out at `wet_m`) plus the rest decaying as exp(−age / `drain_s`), age the time since the front last stood at that height, and the film the backwash leaves weighs exp(−age / 3 s). Both go to the ground's material (below). **The last time the front stood at a height is a closed form**: within wave k it is above h for the phase interval the parabola's two roots give, and the group repeats every seven waves, so the last seven waves hold every reach there is and a height none of them reaches was never reached (`swash_age`; the derivation is on the shore page). Nothing is stored: every frame is a function of the clock, and a replay draws the same beach.
- **The foam is the foam of the waves that broke** (roadmap S100 stage B, 2026-11-10; [the shore page](../experiments/shore.md#the-break-and-the-foam) has the model and the constants). It is born where a wave of the train reaches the breaker index, G(k) H Ks(d) ≥ 0.78 d — each wave of the group at its own depth, the larger further out — and nowhere else: the wave coming in carries a roller on its face, the water behind it keeps the foam it left, and the sheet up the beach keeps what the front left as it passed, all decaying with an e-folding of 4 s as a **lace**: the foam's pattern is ridged value noise, a pixel is foam where the pattern is under the density, so a patch thins from its open cells to its ridges instead of fading (`water_bore_foam` on the water's pixels, `water_uprush_foam` on the sheet's and the ground's, `water_foam_lace`, `water_foam_cover`). The front itself is a thin line, half a wave height wide, strongest as it sets off and gone at its top, and scalloped along the shore (`water_reach_variation`'s lobes). **A function of the clock and the place, nothing kept**: the train repeats every seven waves, so which waves passed a place broken and how long ago is a sum over the last three, each a closed form; no stamp map was built, and a replay draws the same foam. **A wave that does not break makes none, and a small one little**: none under 2 cm of height or where the wave surges up the shore whole (Iribarren's number past 3.3); the density a wave leaves is its height over half a metre and its life 4 s · √H (1 to 4 s), so a lake's decimetre wavelets leave flecks and a sea's surf a raft. **The waterline is the front's, per pixel**: a water pixel whose own front has not reached its ground is bared ground, and a lifted body's water reflects to its very edge (no fade over `shore_m`, which a body with no wind keeps). `foam_m` is no longer read for a body with a wind or a tide; it is the windless body's S97 line's reach alone. Until this stage the foam rode the front as a band a quarter of `foam_m` deep with a trail, which read as a white kerb.

**What moved into the material** (roadmap S99, 2026-11-08; the model is [terrain's "Wet ground"](terrain.md#wet-ground), the sources [the shore page's](../experiments/shore.md#wet-ground)). S94 drew the swash's ground as a post-multiplier on the shaded pixel — Lekner and Dorf's darkening, the sheet's and the film's Fresnel reflection of the sky added after the lighting, a gloss that faded over 3 s — and that is gone. The water stage now finds the pixel's saturation *s* and film weight before the ground's material is sampled (`water_ground_wetness`: the bodies' static bands and swashes, then the channels' banks) and hands them to it: `sample_terrain_material`'s `shore_s`/`shore_film` for a ground with layers (`terrain_wet` over the layers' blended `porosity`), the same `wet_ground.slang` functions over porosity 0.5 for a ground without. So the sun's lobe, its shadow, the sky's ambient and the reflection all read a ground that is darker and smoother where it is wet. The one thing a single-lobe BSDF lit by a cosine-weighted hemisphere cannot give a film is the sky along the mirrored view: after the lighting the film's weight replaces its share of the hemisphere's specular (ambient × the BSDF's `brdf_env_specular`) by the radiance along the mirrored shading normal (the sky's environment, or R129's traced reflection in the ray-traced water modules) times water's F0 0.0201 through the same `brdf_env_specular` — a lighting term of the material's own roughness, not a tint. The foam stays where S94 laid it, over the lit pixel. The damp band is matte by construction: the film's weight is the larger of S94's film term and the free water standing once the pores are past 85% full, so the boundary between film and damp is as sharp as the saturation's while the damp-to-dry edge keeps the fringe's smoothstep.

**What it looks like** (2026-11-08, `engine-view` msvc-debug, 1920 × 1080, `--raster hw --shadows rt`, a camera held 1.2 m over the S97 basin's level looking across at its far bank, eight captures a second apart under the GPU lock; no sky, the stand-in's sun). With the basin made open at 6 m/s over 2 km (a 0.2 m run-up on its steep 1:2.5 bank), the band at the waterline is different in every frame: a pale, sky-coloured sheet stands over the bank at a different height each second, sometimes thin and sometimes three times as tall, with dark wet sand below it and a ragged upper edge where the jitter and the phase drift break it along the shore; between sheets the upper part of the dark band pales. Closed, at 6 m/s its 40 m reach gives a wave of a few centimetres and a run-up of a couple of centimetres, which at that distance is a pixel or two of change (the physics: a pond's wind waves do not run up). With no wind the band is S97's at every frame, the ground's pixels unchanged from one to the next. What does not look right yet: the sheet reads as a reflective grey-blue film rather than water with depth, since it has no volume; its front is smoother along the shore than a real one at the 4 m raggedness scale seen from close; and no forest sequence was taken: the v35 copy's water bodies are two pools, a wet margin, a swamp, the inlet, the lake's east extension and the open sea, none of them obviously the lake the `shore-open` camera looks at, and the GPU lock was held for most of the night.
**What it does not do, said plainly.** **A body that fills is not extended** (since S100 a ringed body with a wind grows its rim and the pool lifts it to the sheet, [The mesh](#the-mesh)): S94's first step flooded the fill to level + R and found a flat surface at the still level over ground that stands above it behind that ground and never drawn; the fill's rim (a bounded flood past the contour) is not built, so a fill body's swash over the bank is still drawn on the ground's own pixels, and its mesh draws only what lies under the still level. **The gloss was a reflection, not a roughness, until S99**: S94's stage ran after the lighting and added the film's Fresnel reflection of the sky over the shaded ground; since S99 the film is the ground material's lowered roughness (so the sun's lobe glints on it) and the sky along the mirrored view is the film's share of the indirect specular (see "What moved into the material", below). **The tide is drawn on the ground's pixels**: the mesh and the open plane stand at `level_m`, so a rising tide over the bank is the swash's sheet (saturated sand, Fresnel, foam), with no volume, no refraction and no deep-water colour, and the plane past the outline does not fall with an ebbing tide. The bared mesh pixel's darkening uses a sand albedo, not the ground's. The ground's foam footprint is an estimate (the distance over half the rows; the position's derivatives are the terrain modules'). A body that follows the ground's wind takes its direction from it but, if closed, its swash from its own `wind_m_s`. **Rivers**: nothing; a channel's record could carry a swash (the record has no channel-specific field, and a bank's wash from a boat or a wind is the same model), and S98 owns the channel section.

### One sheet

Roadmap S102, second pass (2026-11-13; the measurement and the reasoning are [the shore-mechanics page](../experiments/shore-mechanics.md#one-sheet)). **The swash's sheet is two things to the renderer and one to the eye**: its body is the body's mesh (the pool lifts it to the sheet's surface) and its last metre the ground's own pixels, since the mesh ends inside every pixel's front. Until this pass they were two materials — sand under the mesh's thin water drawn dry and seen through a level mirror, sand beside it wet-darkened under a film that mirrored along the sand's shading normal by the BSDF's environment fit — and the mesh's edge stood inside the sheet as a straight line between a dark band and a bright one, in every frame at a low eye. Three changes make them one:

- **The ground under a lifted body's sheet is that body's thin water** (`water_sheet_over_ground`, water.slang; the film's block of `fs_resolve`). `WaterWetGround` carries the sheet's share of the pixel — 1 under the front, the film's weight behind it as it drains — and the body's water material, and the resolve draws that share as `water_pixel_volume` draws the body's water at no depth, **by the same two functions** (`water_volume` over a zero-length path, `water_radiance_volume`): the level surface the mesh's normal is over the bank, Schlick's Fresnel and the sun's glitter at the body's roughness, the sky or the traced scene along the level mirror (`water_reflected`), and under it the ground's own wet albedo and shading normal lit by the sun refracted through the surface and a level surface's sky light. Either side of the mesh's edge is then the same function of the same place. The rest of the pixel keeps the ground's lit colour, so the band the sheet has left is a mirror that goes matte over the film's three seconds. The film's old term (the environment fit along the shading normal) stays for everything that is not a lifted body's sheet: a windless body's still band, a tide alone, the low tier, whose water has no volume to match.
- **The ground under a lifted body's water is wet** (`water_pixel`'s `bottom_s`): the bottom's material takes saturation 1 wherever the body's water covers it — Lekner and Dorf's darkening is a rough surface's under a layer of liquid, whatever the layer's depth — where until this pass only a pixel the backwash had bared was wet. The shallows of every body with a wind are darker for it by the factor the wet sand beside them has; a windless body's bottom is as it was.
- **The foam on the ground is drawn at the ground's own footprint** (`water_ground_wetness`): the larger screen gradient of the position, from the kept triangle, the first time a swash asks — what the water's pixel beside it takes. It was the distance over half the rows, the footprint across the view, and at a low eye the sheet's foam was a crisp lace on the ground's pixels and a grey mean on the mesh's. A traced hit keeps the footprint it gives (`hit_shade.slang`, unchanged).

- **A water pixel is held against the ground its mesh stands on** (`WaterSwashPlace::ground`, the field's depth, in `water_pixel`'s `hh`): whether the pixel's own front has reached its ground was decided against the depth map's texture, the same samples the field holds read another way and centimetres apart on a slope, and the mesh's margin inside the pixel's front is centimetres — so the mesh's last pixels were bared (the bottom alone, matte) beside ground under the whole sheet. The case below found it.

**What holds it, and where that stands**: `swash_scene_tests.cpp`, "the sheet on the sand is one surface across the mesh's edge" — under a swell that surges (no foam), at the time its sheet is on the sand, every pair of neighbouring pixels of which one is the body's water and the other ground the sheet is drawn on, from the ids, at two low eyes, each held to a step derived from the two sides' model ([the derivation](../experiments/shore-mechanics.md#one-sheet)); the same pairs with the sheet's shading off break the bound. The case's own runs found the fifth change, the one the eye paid for most: **under its front the sheet is never thinner than the sheet is** (`water_pixel`: the depth is at least the band's share of the pool's own thickness rule, half the front's height over the ground to a quarter of the run-up and 2 cm). The water's depth was the mesh's height over the depth map's ground, and over the bank the mesh stands millimetres over a ground the map knows to centimetres; where the map's ground stood over the mesh the depth was nothing and a pixel under its own front was drawn as bared — the bottom alone, matte, with no surface — in a band along the mesh's edge. The case printed it as water at wet sand's colour beside ground at the sky's. With it (2026-11-13, msvc-debug, RTX 5090): 320 pairs along the swash and 537 across it, **the largest step 3 codes and 2, a third of its bound, none over**; with the sheet's shading off 268 and 537 of them break it. **What it does not do**: a traced hit on the sheet's ground still shades it as a film; under the bounce the ground reads the cache and the water's bottom does not; point lights are on neither.

## Translucent by volume

**The tier** (roadmap S86, its first part; 2026-10-18). `RenderSettings::water_quality` — `--water-quality low|high` in engine-view, `settings.water_quality` over the protocol (`RenderSettings` version 13) — is **high by default on every device**. Low is the surface above: when the tier was added its capture of the oasis pool was byte-identical to the low tier before it at all three markers and the cost path (RTX 5090, the mesh path, traced shadows; checked by drawing the low tier once with that build's water module and once with `main`'s, loaded through the shader manifest). **Re-pinned 2026-10-19**: the low tier's fade now reads the [depth map](#the-depth-map), so its pictures are no longer those bytes; the low picture of record is the one the depth map draws. Why high everywhere rather than only where the device traces: it costs only a scene with water — the branch is in the resolve's water modules, which only such a scene draws with — and there 0.06 ms at 1080p with the pool filling the frame (below); the second shadow query it asks is the frame's own query, a ray where the device has them and the cascaded maps where it has not, so nothing in it needs ray tracing. A device for which even that is too much is the reason `low` exists.

**How it reaches the resolve: the material table, not a `ResolveParams` word.** The brief for this work asked for a field of the resolve's block beside `water_time_s`. The block has no pad word left (416 bytes since the HDR row), and the tier is a property of what the table holds anyway: at high, `GpuScene::upload_materials` writes each body's **optics** into the table entry right after its water material and sets `gfx::k_material_water_volume` on the material (`gfx::set_water_optics`); at low that entry holds only the body's [depth map](#the-depth-map) (since 2026-10-19; before it the low table had no such entry and was the table before the tier, entry for entry), and a body with no map has no entry at low at all. The setting lives in `RenderSettings`, where a change rebuilds the GPU scene, which is when the table is written. The optics entry: `albedo` the extinction (absorption + scattering, the turbidity's included) and the transmission, `emissive` the scattering, `uv_transform` the ground's UV at the body's centre and the UV a metre, `sampler` the ground's material index (`k_water_no_ground` without a terrain). No cluster names it (the water mesh has the one material), so no reader takes it for a surface.

**Which way the bottom is seen: analytically** — option (a) of the two the work weighed. The visibility buffer holds the water's triangle and nothing beneath it. The pixel's view is refracted at the wave normal by Snell at 1.33 and **marched down to the ground as a height field** (`water_path_map`, since 2026-10-19). It takes six fixed steps along the ray, out to three times the flat answer (the depth here over the ray's descent), against the bilinear [depth map](#the-depth-map). The first step that passes under the sampled ground brackets the hit, and one secant between that step's ends places it, so a level bottom lands exactly, a bank rising under the ray is met sooner and a bottom falling away later. A ray still above the ground at the end of its reach stops there, which is the cap the plane had. The bottom's normal is the map's slope at the hit (one texel's forward differences). That costs at most nine texture reads: the depth here, six steps and the two differences. **Before it, and still for a body with no map**, the view ran to the **triangle's plane**: the depth attribute at its three corners, a plane over body-local (x, z), with the run capped at four times the flat answer. That made the bottom a plane per triangle, its landing and its sunlit slope stepping at every edge of the mesh — the rings and trapezoids [the depth map](#the-depth-map) was made to remove. The ground's colour there is **the terrain's own material**: its baked base-colour map, read at the hit point's place in the map's UV frame — the body's centre's UV, which the GPU scene computes in f64 from the water instance's cell and local and the grid's millimetre frame (`terrain_uv_frame`), plus body-local metres times the UV a metre — so the sand under the water is the sand on the shore, and no position the GPU sees is a world coordinate. The bottom is lit as a Lambertian surface by the sun refracted at the level surface and by the sky's light, both dimmed on the way down; **its shadow is the sun's shadow query asked where the sun's refracted ray to the bottom leaves the surface** — at the bottom itself the query would find the water's own surface over it, which casts as every surface does — and in the shallows (under `k_water_calm_depth`, 25 cm) it blends to the surface's own, because there that exit point lies over the bank, inside the sand, and drew a dashed dark line along the mesh's edge until it did. **Option (b)**, a second visibility pass of the scene without the water over the pool's tiles, resolved and composited through the surface, was not built: (a) gives the owner's picture on the oasis, whose floor is the terrain and under whose water nothing else stands (the rocks keep 10.6 m from a 10 m pool). Its cost was not measured; its floor is this frame's own cull, raster and resolve over the pool's pixels — 0.014 + 0.027 + 0.19 ms on the cost path below, before a second Hi-Z and the composite — so it would cost several times what (a) does for what (a) cannot show, which today is nothing.

**The optical model** (`water.slang`, "the volume tier"; `water_reference.h` mirrors it in double). With σₜ the extinction and σₛ the scattering per metre (RGB), τ the transmission, the refracted view's run `s` to the bottom and the bottom's depth `d` there, the sun's angle under the water θₗ (cos θₗ by Snell from the sun's elevation), `μ = d / s`, `E` the sun's irradiance at the surface (Schlick's share of it refracted in: `E (1 − F(sun))`) and `A` the sky's light a level surface takes (the opaque path's ambient, `(1 − F₀)` of it entering):

- **the bottom**: albedo × (E · vis_bottom · max(n_b · l, 0) / π · e^(−σₜ d / cos θₗ) + A · e^(−1.25 σₜ d)) × e^(−σₜ s) × τ — Beer–Lambert down both ways the light comes and up the view; 1.25 is the sky light's mean path for a mean cosine of 0.8;
- **the water's own light**: isotropic single scattering of both, integrated along the view: σₛ × (E · vis_surface / 4π · g(σₜ(1 + μ / cos θₗ), s) + A / 4 · g(σₜ(1 + 1.25 μ), s)), with g(a, s) = (1 − e^(−a s)) / a. As `s` grows the bottom dies away and this tends to a colour the light makes — the deep is no longer painted;
- **the surface**: Fresnel (Schlick at 0.0201) between that and the sky along the reflected view, the sun's glitter and the shore fade exactly as in the low tier.

Turbidity adds `(0.9, 0.82, 0.68)` of scattering and `(0.03, 0.06, 0.14)` of absorption a metre per unit (`gfx::k_water_silt_*`): sediment that scatters the sand's light and takes the blue first. Not modelled, said so: the n² law (light leaving the water loses 1/1.77 of its radiance) and the total internal reflection of upwelling light that gives part of it back pull opposite ways and are both left out, so the bottom at the waterline is as bright as the dry sand beside it; caustics; the waves' effect on the light coming down (the sun is refracted at the level surface); the bottom seen bent by the waves (the bottom is smooth, so the refraction moves it but shows no ripple of its own); anything under the water that is not the ground (that is (b)).

**The reference holds it**: `water_shading_tests.cpp` draws three volume blocks beside the five low ones — the sharp waves over a ground of sand at 500 s, the same over a bottom that slopes from 0.5 to 1.5 m (the plane through the triangle's depths), and broad waves at the shore over no ground, silty and passing 60% — **worst 1 of 255** against the double-precision mirror on every block, low and high (RTX 5090, mesh path, 2026-10-18), and the volume block differs from its low twin in more than 100 of the compared pixels. **With the depth map** (2026-10-19) three more blocks carry a synthetic map, 64 texels a side over the quad's 10 m (`water_reference.h` mirrors the bilinear sample in double from the same 16-bit grid, and the march step for step): the sharp waves over the sand through a map of the same slope, 1 + 0.1 x; the same through a bowl, 2.3 m deep in the middle and 0.3 m at the corners; and the broad waves of the low tier fading by the bowl. All three are worst 1 of 255 against the reference (RTX 5090, mesh path), and the sloped map's march draws within 1 of 255 of the plane through the same slope, since a straight bottom is what the secant lands on exactly.

**What it costs** (`engine-view --benchmark`, `msvc-release`, 1920 × 1080, five seconds looking down on the pool from nine metres with the water about nine tenths of the frame, RTX 5090, traced shadows, two runs of each tier interleaved under the GPU lock, 2026-10-18; `machine_state`: others' CPU 6–14%, not quiet by the harness's rule, so upper bounds): `gpu_ms.resolve` median **0.189 ms low and 0.249 ms high**, both runs within 0.0001 ms of each other — **+0.060 ms**, about 32 ps a water pixel; cull and raster unchanged (0.014 and 0.027 ms). The two surround budget scenes draw with the plain modules, which are the bytes they were (`AD0A0386…` plain, `5C77B086…` rays, the same as `main`'s), and `tools/frame-budget.ps1 -WaitQuiet 120` on them (2026-10-18, a busy machine: others' CPU 23–32% and then 61–100%, GPU 4–21%) measured `erg-walk-surround3-rt` **pass**, GPU total 3.399 / 4.891 ms median / p99 against its 3.373 / 4.127 (resolve 2.327 ms median), and `endless-surround3-rt` GPU total 4.431 / 5.805 ms against 4.436 / 5.418 (resolve 1.966 ms), over only in `cpu_ms` with every core of the machine busy beside it — the inconclusive verdict the tool gives a busy run. **With the depth map** (2026-10-19): the same setup (`msvc-release`, 1920 × 1080, five seconds looking down on the pool from 8.55 m with the water nearly the whole frame, RTX 5090, traced shadows). Each run was set against `main`'s water modules, loaded through a shader manifest (`--shaders`), the two interleaved over two rounds under the GPU lock. The `machine_state` was not quiet: others' CPU was 30–44% at the start of six runs and 100% at two, with a Linux container building beside them, and the GPU at 98% at the end (the run's own). `gpu_ms.resolve` median: **high 0.244 / 0.245 ms before and 0.263 / 0.263 after, +0.018 ms**, the march's nine reads at most, about 9 ps a water pixel; **low 0.185 / 0.184 before and 0.194 / 0.193 after, +0.009 ms**, one read. Cull 0.014 ms either way. The oasis's map is 51,874 bytes on disk and a 103,684-byte image (180,224 as the device allocates it). The plain modules are still `AD0A0386…` and `5C77B086…`, so a frame with no water, and the two surround budget scenes, draw with the bytes they did.

**What it looks like** (the oasis pool, `engine-view --marker-captures` at 1920 × 1080, high, 2026-10-18). From the south-west towards the morning sun (`sun`) the pool is a lens of colour in the hollow: the sand runs on under the water at the shore, pale and only a little cooler, turns sea-green over the first metre of depth, and the 2.3 m middle is a deep blue-green that is the water's own light; the sky's paler blue and the waves' fine chop lie over all of it at grazing, brighter towards the far side. From the east shore (`east`) the same at a lower angle: a darker teal in the middle where the low tier paints a paler blue, and the near shallows sand-coloured where the low tier draws a pale turquoise rim. Low across the middle (`across`) the water in the foreground is a deep green-teal with the chop's highlights, the far shallows a band of sand seen through the water under the far shore's rocks. Looking straight down from nine metres the sand shows through a fringe a couple of metres wide and the middle is a flat deep teal with the sun's glitter on the crests. What does not look right yet: the bottom is the terrain's smooth map, so it has no texture to bend — the waves show only in the reflection and the glitter; the rocks still do not reflect; and with no caustics a sunlit shallow bottom is flatter than real water makes it.

## What is under the water

Roadmap S86, its second part (2026-11-08; the owner, 2026-11-07: "visibility through the water of whatever is under the water"). The volume tier saw the **ground** through the surface — the refracted view marched against the depth map — and nothing that stands on it: a boulder in a pool, a sunken log, the submerged base of a shore tree were cut off at the waterline, because the depth map knows only the ground. Where the device traces, the volume tier now traces what the refracted view meets.

**The ray** (`domain/gfx/shaders/water_refract.slang`, `water_refraction`, one call in `water_pixel_volume` after the ground's light is computed). After the surface point and the refracted direction, one ray along that direction from just under the surface (lifted by the receiver's own `ray_offset`, as a shadow ray leaves), against the frame's top-level structure with `trace_scene_hit` (R129's: the shadow rays' rule for a non-opaque candidate, the nearest hit kept), **out to the ground distance the march found** — and no farther than the water lets light through, ln 255 extinction lengths of its clearest channel (`gfx::k_water_refract_extinctions`), past which 1 of 255 is left. Only where that ground distance is at least `gfx::k_water_refract_min_m` (0.15 m): a pixel whose water is centimetres deep hides nothing. A hit nearer than the ground is something standing in the water, and its light replaces the ground's; where the ray meets nothing **the ground is the march's answer and the terrain material's colour, to the bit** (the identity test, below).

**The ground stays the depth map's.** The frame's structures hold the ground's own mesh too, at the frame's cut, which stands off the map's bilinear ground by its LOD's error. A hit on a terrain level's tile (`InstanceDesc::terrain`), or one within `gfx::k_water_refract_ground_m` (8 cm) plus 0.5% of the eye's distance to the surface above the map's ground under it, is the ground and is rejected: the march's answer is kept. The cost of that rule: an object's last few centimetres above the bed read as the bed. A body with no map takes the same margin off the march's distance.

**The hit's light under the water.** Its material is decoded as `shade_hit` decodes one (`hit_shade.slang`: the base colour at the mip the ray's footprint selects over the eye-to-surface-to-hit path, a terrain hit's first layer's mean), and lit by what the water lets down to it:

- **the sun**: the beam refracted at the level surface (Snell at 1.33, `water_sun_under`), Schlick's share let in at the sun's angle, and **dimmed by Beer–Lambert over the refracted path from the hit up to the surface**, e^(−σₜ d / cos θₗ) with `d` the hit's depth under the level (`water_submerged_sun`; `water_reference.h`'s `submerged_sun`). A stated approximation: the surface is level for the light coming down (the waves tilt only the view), and there are no caustics — the waves' focusing of the beam into the bright net on a sunlit shallow bed is not drawn;
- **its shadow**: the frame's own sun query asked **where the sun's refracted ray from the hit leaves the surface**, as the bottom's is. `shade_hit`'s own shadow ray from the hit would meet the water's surface over it — the water casts as every surface does — and black out the sun under the water at the half of the pixels R129's half rate traces it at; so it is not used, and the exit point's query runs at every pixel that has a hit (a shadow under the surface is softened by the waves anyway, which the hit's shading does not model). What stands under the water casts on nothing under it: the bottom's query leaves from the surface too;
- **the sky's light**: the (1 − F₀) of a level surface's that entered, dimmed over 1.25 times the depth as the bottom's is, on a face turned by its normal from a downwelling field — (1 + n.y) / 2, a uniform upper hemisphere's irradiance on a tilted face — so a log's top takes it and its underside nothing;
- **then the eye's path** in the water from the surface to the hit, exactly as the ground's: Beer–Lambert, the transmission, and the light the water scatters towards the eye along the way (`water_volume` with a black bottom). So a log on the bed comes up darkened and blued by its depth, and a deep one sinks into the water's own colour.

`shade_hit` itself is not called: its light is one sum, and the water dims its sun and its sky by different paths. Its material decode is copied into `water_refraction` (a request to R129's owner: a `shade_hit` that returns its sun and ambient terms apart, so the two share one decode). No normal map, no point lights and no world-space cache on the hit, as in the reflection.

**What the structures hold for it: the submerged caster volume** (`systems/renderer`'s `water_refract.h`; [renderer](renderer.md#shadows)). A frame that traces has no two-pass occlusion culling (the structures are built from one visible list), so what lies under the water inside the view's frustum is in the cut already — drawn, its pixels behind the surface — and in the structures. What the frame does not hold is what **the refraction bends into from outside the frustum**: Snell bends the view towards the vertical, so under the frame's bottom edge a refracted view reaches the bed nearer and deeper than the straight one would. A refracted view leaves the surface at a point the frustum holds, keeps its azimuth, and runs down no flatter than the critical angle, asin(1/1.33) = 48.75° from the vertical, so what it reaches at depth `h` lies within 1.1404 h of where it left, horizontally, and within 0.7519 of the water's reach. The volume is a vertical prism over the frustum's cross-section at the level (the convex polygon of where the frustum's twelve edges cross it), each edge pushed out by the smaller of the two spreads, between the level and the floor — the body's deepest bed less 0.5 m (`k_water_refract_bed_margin_m`), or the reach's depth where that is shallower — and within `gfx::k_water_reflect_m` of the eye; at most 11 edges, else the polygon's box. It holds the frustum's own water too, whose pairs the frustum test keeps before a volume is read, so it adds only what the refraction reaches outside. It is one more volume in the view's cull block, behind the lights' and the mirrored one (a block they fill leaves the refraction what the cut holds); its pairs are casters, at the camera's LOD, built non-opaque (the refraction ray meets them as solid, as the reflection ray does), never drawn, counted in `Stats::shadow_casters` with the rest. **One body a frame**, the one the reflection's plane is (`GpuScene::water_refract_body`, beside `water_reflect_level`), its deepest bed and its reach read at load from its depth map and its optics (`WaterBody` gains nothing).

**The switches.** `renderer.water.refract` (0 off, 1 on — the default wherever the resolve traces and the tier is high; 2 on in even frames and off in odd ones, so one flight measures both) and `renderer.water.refract_volume` (true; false refracts into only what the cut holds, which is the test's way to show what the volume adds). The resolve reads the first as `gfx::k_shadow_water_refract` in `ResolveParams::shadow_flags` (bit 12, not the next free one, which R139 may take the same night), so the block keeps its size. `Stats::water_refract`, `water_refract_views` and `water_refract_floor_m`, and `FrameRecord` version 18's fields of the same names ([apps](apps.md)), say what a frame did. Where the device has no ray queries, where shadows are the cascaded maps or off, and at the low tier, nothing changes: the ground alone, as before.

**The modules.** Only the ray-traced water modules include `water_refract.slang`; every other resolve module is the SPIR-V it was.

**What holds it** (`systems/water/tests/refract_scene_tests.cpp`; the GPU cases on a device with ray queries, over a pool that fills a basin 30 m across of the renderer's ground, 4 m deep in its middle). ## To the horizon

**Open water** (roadmap S93, stage 1; 2026-10-31; the grounding and the design are [the ocean-surface page](../experiments/ocean-surface.md)). A body with `open: true` is a sea whose outline is its near shore: past the outline the **same water goes on to the horizon** wherever the ground is below the level. The forest proof of concept's `eastern-sea` (a 928 × 3,584 m rectangle at −6 m) is the case it was made for: closed, it stops at its rectangle, and past it are the far ground and the sky.

**How: an analytic plane in the resolve**, not geometry. The sea past the outline is flat at the level, and the resolve already has, for every pixel, the ray through it and the distance to whatever the visibility buffer holds there. So in the resolve's water modules a shaded pixel whose ray meets the plane at the open body's level **before** its surface — or that holds no surface and looks down — is that body's water, shaded by the branch above at the plane's point (`open_water_pixel` in `visibility_resolve.slang`; the ray is the line shared by the two planes through the eye that the pixel's clip x and clip y name, so no inverse of the projection is needed). A pixel of any water material never asks, so the plane never draws over the body's own mesh, and wherever the mesh does not cover the plane is the same water at the same level: the two cannot crack or double. The waves are taken at the plane's point less the **body's instance's** place in the frame (`instance_from_eye`, exactly as the mesh's are), so they meet across the outline on the same phase. Its footprint for the waves' fade is the plane's points through the next pixel across and down. Its depth is the body's [depth map](#the-depth-map) within the map's square, as the mesh reads it — so the shading is continuous across the outline — and past it the level less the height of the surface the pixel would otherwise show (the ground the ray meets under the water), or 1,000 m (`k_water_open_deep`, the bottom gone) where there is none. Both tiers draw it; the volume tier's refracted view runs to a level bottom at that depth past the map. The air between the eye and the plane, the exposure and the output encode are a surface's. The GPU scene names the body to the resolve (`GpuScene::water_open_instance`, `water_open_material`, written into `ResolveParams::water_open_instance` and `water_open_material`, a new 16-byte row that only the water modules declare: the block is 480 bytes, and the plain modules, which every scene without water draws with, are the SPIR-V they were).

**The shore of an open body is where its depth is zero**, not its outline: an open polygon's sides that face the sea are not a shore, and the pond's fade from the edge would draw a band of wet sand across the water there. With `gfx::k_material_water_open` on its material, the branch fades the shore by depth over the depth the waves calm in (25 cm), on the mesh and the plane alike (`water_edge` in `water.slang`). The mesh and the depth map are the closed body's, byte for byte (`water_tests.cpp` pins the two), so making a body open builds nothing new.

**Why not a far water level of geometry** (the alternative the work weighed, laid out from the camera like the far ground, [ADR-0051](../adr/0051-the-far-ground-is-the-renderers.md)): it would put the sea in the visibility buffer, but it needs a layout that moves with the camera, instances that come and go, a seam between the body's mesh and the far tiles on two different 16-bit grids (the eastern sea's mesh steps 5.5 cm, so their shared edge would not be one set of vertices, and a flat seam that is not watertight shows the sea floor through it), a coast decided per far tile in 256 m to 8 km steps, and an end where its last square ends. The plane has none of these, reaches the eye's horizontal, draws its coast where the drawn ground crosses the level pixel by pixel, and is the same under the mesh shaders, the vertex path and `--raster rt`, since all three end in this resolve ([the page](../experiments/ocean-surface.md#stage-1-built-the-sea-to-the-horizon-an-analytic-plane-in-the-resolve) has the argument whole).

**What it does not do**, said plainly. The plane is **not in the visibility buffer**: the ids and depth channels, picking and the reference path tracer see what is under it (the far ground, or nothing). It is drawn **from above only**: an eye at or below the level sees no plane (underwater is designed on [the page](../experiments/ocean-surface.md#underwater-designed), not built). It floods **every hollow below the level the eye can see**, inland ones too — a pixel cannot know whether its ground reaches the sea; a mask is the fix if a scene needs one. It is **flat to infinity**: its last row is the eye's horizontal, a few pixels above the sky's curved planet's horizon from a hill (√(2h/R), 0.32° from 100 m), and past the aerial table's 32 km it is no hazier than at 32 km, as the far ground is. Its depth past the map is the depth under the point the ray meets, not under the plane's point, which on a steep coast seen at a slant is a few metres off. It casts no shadow. And a scene has at most one open body, because the plane is one level.

**What it costs**: one uniform test a pixel in a scene with water and no open body; with one, a ray and a plane for every shaded pixel that is not water, and the water branch on the pixels the sea covers, in the resolve's water modules only. Measured on the forest proof of concept's v23 scene with its `eastern-sea` made open in a copy (`engine-view --benchmark`, `msvc-release`, 1920 × 1080, the owner's flags — `--terrain-tiles --terrain-far 6 --raster rt --shadows rt --lod 1` — offscreen, 181 frames of a held camera, RTX 5090, 2026-10-31, under the GPU lock; the `machine_state` was **not quiet**: others' CPU 22–100% from other agents' builds, so upper bounds): on `eastern-coast` (2.5 m over the sea's west shore, the sea a fifth of the frame) `gpu_ms.resolve` median **0.606 ms closed and 0.635 ms open, +0.030 ms** (0.631 on a second run); from 60 m over the west shore looking east (the sea four tenths of the frame, the horizon its last row) **0.697 ms closed and 0.670 ms open** — the sea is cheaper than the sky's planet and the far ground it covers there. The pictures: closed, the sea stops 870 m out at its rectangle and a band of the sky's planet stands between it and the horizon; open, the water runs to the horizon and fades into the haze. The plain modules — every scene without water — are the SPIR-V they were (`visibility_resolve`, `_rt`, `_terrain` and `_rt_terrain` compiled from main's sources and from these are the same bytes), and **a closed body draws the bytes it drew**: the oasis pool's three markers at both tiers under `--raster hw` and `rt`, drawn with these water modules and with main's loaded through a shader manifest, are the same PNG bytes, twelve of twelve (`msvc-debug`, 960 × 540; the same manifest draws the oasis made open differently, so it was the one drawn with).

### The spectrum

**An open sea's waves** (roadmap S93, stage 1b; 2026-10-31; the models and their constants are [the ocean-surface page](../experiments/ocean-surface.md#the-published-models)). An open body with a wind — the ground's (`GroundProvider::wind` at the scene's time, when the body follows it) or else its own `wind_m_s` — draws **sixteen Gerstner waves from the JONSWAP spectrum** in place of the pond's four sines, on its mesh and on the plane alike (`gfx::water_spectrum`, `domain/gfx/include/domain/gfx/water_spectrum.h`; `water_normal_spectrum` in `water.slang`). The renderer's scene reader makes the table once, in double, when the scene is read: JONSWAP's peak ω_p = 22 (g² / (U₁₀ F))^(1/3) and α = 0.076 (U₁₀² / (F g))^0.22 at the wind and the fetch, γ 3.3, σ 0.07 / 0.09; one wave per band of equal log width over [0.5, 4] ω_p, at the band's geometric centre, its amplitude √(2 S Δω) (the band's variance as one sine); its direction the wind turned by Donelan–Banner's sech² spreading inverted at a hashed uniform, θ = atanh(tanh(βπ)(2u − 1)) / β; its wavenumber ω² / g (deep water); its frequency rounded to whole cycles of the 1,024 s period, so the clock still wraps with no jump; its phase hashed from the seed; and its Gerstner steepness Q k a its own k a, all scaled down alike where they sum past 0.6, so no crest loops. The GPU scene packs the sixteen (32 bytes each, `gfx::WaterWave`) raw into the five material entries after the water material's next one (`gfx::set_water_spectrum`, `k_material_water_spectrum`; that next entry is then always there, empty at the low tier without a map), and the branch sums them with the four sines' footprint fade and calm, the crests sharpening the normal by their steepness. The silhouette stays flat: only the normal is evaluated. `wave_amplitude_m`, `wave_length_m` and `chop` are not read where the spectrum draws; a body with no wind draws the four sines as before (until S100 stage B a closed body did too, whatever its wind; below). At 7 m/s over 100 km the peak is 1.14 rad/s, a 48 m wave, and the band runs from 191 m to 3.0 m; at 10 m/s over 100 km the peak is a 61 m wave.

**What holds it.** `water_tests.cpp`: the fetch laws, the peak enhancement γ at the peak, the sixteen waves' variance within 3% of JONSWAP integrated over the band (at 10 m/s over 100 km, 2026-10-31: a significant height of 2.143 m from the waves against 2.135 m from the band, 0.7% apart in variance; the energy-weighted cosine to the wind 0.89, 27°; the steepness 0.57 of its 0.6 cap), the energy-weighted direction within 37° of the wind, every frequency a whole number of cycles and on the deep-water relation, the steepness under its cap, the same table from the same seed and another from another seed, no waves without a wind, and the packing. `water_shading_tests.cpp`, on a GPU: two blocks of an open material with the spectrum's table (6 m/s over 5 km: a 5.9 m peak, the band 23 m to 0.4 m), one at 37.25 s over open water and one at the shore, held to `water_reference.h`'s `normal_spectrum` and `edge` in double: **worst 1 of 255** on both, as on the eleven blocks before them (RTX 5090, mesh path, 2026-10-31).

**What it costs**: sixteen waves where there were four, a sine and a cosine more a wave, on the sea's pixels only. On the same scene and flags with the open `eastern-sea` given `wind_m_s` 7 and `fetch_km` 100 (a 48 m peak) against the same body with the four sines (2026-10-31, `msvc-release`, RTX 5090, not quiet: others' CPU 31–100%): from 60 m over the west shore looking east, `gpu_ms.resolve` median **0.666 → 0.720 ms at 1920 × 1080 (+0.054 ms)** and **2.192 → 2.289 ms at 3840 × 2160 (+0.097 ms)**; on `eastern-coast` 0.631 → 0.645 ms (+0.014). At 1080p the sea is about 0.8 million pixels there, so about 65 ps a sea pixel; at 11,520 × 2,160 the same share of the frame would cost about +0.6 ms. **What it looks like**: the four sines' regular parallel bands across the whole sea become crossing trains of crests of many lengths, longest along the wind, fading into the haze towards the horizon as the footprint takes the short ones; still a sum of sixteen, so a patient eye finds the long trains repeating, which is what the FFT cascades are for ([the page](../experiments/ocean-surface.md#stage-2-designed-fft-cascades)).

**Every body with a wind, as narrow bands** (roadmap S100 stage B, 2026-11-10; the numbers and the sources are [the shore page](../experiments/shore.md#the-spectrum-for-every-body)). The table is no longer the open sea's alone: **a closed body with a `wind_m_s` draws it too**, over its own fetch — the longest reach of its own water along its wind, found on its depth map (`gfx::water_fetch_field`), no longer than `fetch_km` — and its material carries the same five entries. A closed body's wind is its own `wind_m_s` (the ground's wind gives it its direction, not its speed: a pool under trees does not feel the region's wind unless its block says so); a body with no wind keeps the four sines, and `wave_amplitude_m`, `wave_length_m` and `chop` are read by nothing else. The fetch laws stop at full development (g F/U² = 2.2 × 10⁴: 110 km at 7 m/s), so a `fetch_km` past it changes nothing. **Each wave is drawn as a band**: its carrier under a complex envelope of value noise four wavelengths long and 2.5 wide, travelling at the group speed (`water_wave_add`, `water_waves.slang`, which the mesh's branch and the plane's share), so crests are short, waves come in groups and no pattern lines up or repeats, and the clock still wraps with no jump (the envelope's lattice is periodic in the cells it travels a period). **A closed body has a lee**: the field's third channel is the share of the fetch the wind has blown over at each place, and a wave's amplitude there falls as the young sea's spectrum does, the long waves first, so the shore the wind blows from is ripples and then glass. **What a pixel cannot hold is drawn at the pixel's own scale** (`water_micro_normal`, `water_roughness`): 70% of the slope variance of the waves the footprint took out of the normal comes back as a ripple three footprints long travelling down the wind, and the rest is added to the GGX lobe's α², so far water under a wind is rough and streaked and glitters as wide as its wavelets are steep, where the first captures drew it as a mirror. The forest's lake, 0.9 km under 7 m/s: H_m0 0.113 m, a 1.15 s peak 2.07 m long, bands down to 13 cm, an rms slope of 0.19. **What holds it** (`water_shading_tests.cpp`, CPU cases; `deform_tests.cpp` on a GPU): the table's height within a fifth of the growth law's and its period within 3%; the bands' variance over a patch within 15% of the sines' (measured 2%); the gradient against a central difference; the wrap at 1,024 s; one band uncorrelated with itself forty wavelengths on; the fetch over a round lake, its lee, an island's shadow; and the pool's lift of a spectral body in a lee on a mesh, vertex for vertex against `water_reference.h`.

**Walking**: `depth_at` answers an open body wherever its ground is below its level, past the outline too, so the walker wades into the sea the picture draws (and into a flooded hollow, as the picture does).

**What holds it.** `water_tests.cpp`: an open body's GLB and depth map are the closed body's bytes, pinned (29,056 and 10,690 bytes); `depth_at` past the outline is the level less the ground for the open body (0.72 m two metres out of a 6 m pool over the bowl) and 0 for the closed one, and 0 where the ground stands above the level; a second open body is refused through the generator with the sentence above. `water_scene_tests.cpp`, on a GPU, at both tiers: a pool made open over the renderer's dunes, captured from 6 m up looking level along +x against the same pool closed. Every pixel's ray is known on the CPU, so the plane's distance along the view axis is set against the surface's (`znear / depth`): **the ids and the depth are the same bytes** (the plane is no geometry); every pixel clear of the coast (the two distances more than 3% apart) where the plane is nearer, or where there is no surface and the ray looks down, changes, and none where the surface is nearer; **no pixel above the horizon changes**; **no pixel of the pool's own mesh changes** (its shore is 0, so neither shore rule fades it); the rows under the horizon past the dunes' 32 m are sea; and the open frame twice is the same bytes. Measured 2026-10-31 (RTX 5090, mesh path, 480 × 320): at high 70,484 pixels of sea clear of the coast and at low 56,840, none of them unchanged, 3,840 under the horizon past the dunes; none changed over land, above the horizon or in the pool. ### The swell

Roadmap S102 (2026-11-12; the grounding is [the shore-mechanics page](../experiments/shore-mechanics.md)). **A wave comes from somewhere.** Until S102 the train near the shore had no direction: the arrival field's source was every deep texel at time zero, so crests were born along the deep water's contour, lay parallel to the shore all the way in, and reached every part of a beach at the same instant — the surf and the swash of a whole bay pulsing together, which is what read as an animation laid along the waterline. The source is now a **plane wave** (`gfx::water_arrival_field`'s `direction`): a source texel's arrival is its distance along the train's direction over the phase speed where the source ends, so the train enters the shallows at its angle and the eikonal turns it as Snell's law says (sin θ / c kept along a straight coast: 25° at 5.5 m of depth is 12° at 1 m and 7° at 0.3 m under a 4.7 s wave), the crest reaches one end of a beach before the other, and the swash runs along the sand. The direction is the body's wind's — a closed body's waves too — or a swell's own. **The bank is a wall to the eikonal** and takes the arrival of the nearest water the train reached (`gfx::water_carry_nearest`); S100 crossed it at 10 km/s, which with a direction carried the earliest arrival on a coast along the whole of it.

**An open body's swell**: `swell_height_m`, `swell_period_s` and `swell_direction_deg` (the scene's `WaterBody`, version 6; refused: a negative height, a period outside [0, 30] s, a height with no period). A swell is waves raised by a wind somewhere else: long, regular, from its own direction, there whatever the local wind does. With one, **the train that shoals, turns to the beach, breaks and runs up is the swell's** — its height, period and direction in `WaterSurface::height_m`, `period_s`, `k0`, the run-up and the sheets' lives from them — and the wind's table keeps the surface offshore, calming towards the shore where *its own* peak feels the bottom (`WaterSurface::swell` carries that wavenumber, and is what marks a swell); the swell's train is drawn over the whole body, since a swell is there offshore too, a low long undulation under the chop. The mesh's rim and its rings at the outline are sized by the wave that comes ashore (`shore_wave`, `systems/water/src/water.cpp`), and a swell alone, with no wind, lifts the body (`resolve_settings`). How periodic the waves are is then the scene's to say: at 10 s on a 1:5 shingle bank each sheet is back before the next (0.9 of a period); at 4.7 s on a 1:30 beach four sheets overlap. **What it does not do**: (since the second pass the wind's peak wave comes ashore beside the swell as a second train, [The surf](#the-surf);) the swell has one direction and no spread; a closed body reads none.

### The surf

Roadmap S102, second pass (2026-11-13; the models, the three corrections to the design and the checks are [the shore-mechanics page](../experiments/shore-mechanics.md#the-energy-flux-field)). Until this pass a place's wave was a closed form of the depth under the pixel, H₀ K_s(d) capped at 0.78 d: a headland stood in the surf the open beach has, its lee too; a wave that had broken on a bar was whole again behind it; and one regular train came ashore, every crest unbroken along the bay and every wave the last one's twin.

**The energy flux is a field** (`gfx::water_flux_field`, `domain/gfx/water_flux.h`; built once a body at load beside the arrival). Along the train's rays — the arrival's gradient — the flux E c_g is kept until breaking takes it, ∇·(E c_g ŝ) = −D, solved by one conservative sweep in the order the train arrives. Three numbers a texel come out of it, and with the second train's arrival they are the field's second four floats (**32 bytes a texel where there were 16**; `k_water_field_channels` 8; a 1,024-texel map's field is 32 MB):

- `incident`: the share of the unrefracted height that refraction, spreading and the lee leave a place (K_r; a point gathers, a bay spreads, a headland's lee is quiet), kept to [0.02, 2]; on the bank, its shoreline's.
- `kept`: the share of that which breaking left — Battjes and Janssen's bore dissipation with the fraction breaking **counted over the train's own group of seven waves**, each where its own height reaches 0.78 d, so what is dissipated is what is drawn breaking, and a wave that broke on a bar is lower across the trough behind and breaks again only where the depth asks.
- `setup`: the mean level's rise, metres, by Longuet-Higgins and Stewart's balance of the radiation stress along the ray: a set-down of centimetres to the break, a rise through the surf.

**What reads it** (`water_waves.slang`, `water.slang`): the train's height is its deep-water height times `incident` times `kept`, shoaled and capped as before (`water_height`); **foam is born where the flux is being lost** — `water_bore_foam`'s break test takes the same height, so the break line is where the wave that reaches the place reaches the limit, further out on a point and nowhere in a lee, and not at a contour; a place's run-up is Stockdon's with the height that reaches its stretch of shore (`water_place_reach`: √`incident`, the formula's √(H₀L₀)), and **the swash stands on its shore's setup** (`water_place_level`, never under the still level and kept under half the reach: the run-up's top stays the fit's), the waves' mean level the field's (`water_vertex_lift`). A field whose texels hold zeros there — a test's, a record with none — reads as 1, 1 and 0: the closed form as it was.

**Two trains come ashore** (`gfx::WaterCross`, `water_cross_of_sea`, `water_cross_of_swell`; `WaterSurface::train_m`, `cross_m`, `cross_period_s`, `cross_k0`, 648 bytes). A wind sea is split in two: its peak, and a component at 8/7 of the peak's frequency carrying JONSWAP's own ratio of the spectrum there (0.37 of the peak's energy: 0.86 and 0.52 of the sea's height) from 26° to one side (the half width at half maximum of Donelan and Banner's spreading there; the body's seed picks the side). Eight of its waves pass in the peak's seven, so the pair beats once a group and everything stays periodic in the group and on the water's clock; the two cross, so the beat's place along a crest differs from crest to crest — crests a few wavelengths long, no two alike. Beside a swell the second train is the wind's own peak wave, its period moved onto the swell's group, so the shallows keep their chop. The second train has its own arrival (it refracts by its own period) and shares the first's flux ratios; each takes its share of the breaking height, so the crest the two make together is the one that stands 0.78 d; and **a wave of the group has broken where its crest plus the second train's elevation under it reaches the limit**, so a crest breaks first on a stretch and the break runs along it. `height_m` stays the sea's whole height, which the run-up, the swash and the foam's strength are taken from.

**What holds it** (`water_tests.cpp`, no device): Snell's K_r on a plane beach; the flux kept to the break and then the balance's own solution through the surf, and the set-down's closed form, on a plane beach; a bar and a trough; a wall's lee and the scheme's conservation; the second train's split. On a GPU, `deform_tests.cpp` holds the pool's lift with a second train and a field of all three against the double reference (`water_reference.h`, mirrored step for step), and the bay's cases hold that the picture is still a function of the clock and wraps.

**What the second pass costs** (2026-11-13, msvc-release, RTX 5090, main's binaries at b7681ac9 against the pass's, both copied out of their trees; `content/test-scenes/beach`, 3840 × 2160, `--raster rt --shadows rt`, `renderer.gi.mode=bounce`, 15:00; one lease, the two alternating, two runs each, medians of 180 frames a camera from the engine's own GPU timers; others' CPU 56 to 87% — `machine_state`, not quiet, so upper bounds that agree with each other; the pass's binary was one shader line before the final one, the ground a water pixel is held against): resolve at `along` 1.876, 1.877 → 1.764, 1.762 (**−0.11**; the ground under the sheet leaves the BSDF's lights for the sheet's two functions), `seaward` 1.835, 1.836 → 1.902, 1.909 (**+0.07**), `point` 2.121, 2.121 → 2.160, 2.184 (+0.05), `above` 2.483, 2.481 → 2.542, 2.545 (+0.06); the pool pass (`deform`) 0.025 to 0.027 → 0.030 to 0.033; the frame's total within ±0.15. Inside the shore's budget of +0.5 ms at every camera. `--raster hw`, a windless pool and the forest were not paired. **At load**: a second arrival field and the flux's sweep beside the first; a whole run of the beach (load and flight) took 18 to 19 s against main's 18 s, so under a second for that body's map; the field's bytes double (32 a texel).

**Three things the pass's own flights changed** (the beach from 30 m up, 2026-11-13). The second train's crests coincide with the first's on stretches, and with the foam whole from 1.05 of the limit those stretches were ruled slabs of white: **a crest now makes its foam as it stands over the limit, none under 0.9 and all of it from 1.5** (`k_water_broke_whole` in `water_bore_foam`), so a breaking stretch thickens from its ends to its middle — and a wave barely over the limit, a lake's included, makes less foam than it did. **The mesh takes the second train only where eight of its spacings carry a wavelength** (the first train's rule is four): two crossing trains at four spans a wavelength stand up as facets; the normal, per pixel, has all of it. **The water's depth over its bottom is taken from the height function at the pixel, not from the mesh's interpolated height** (`water_surface_normal` now gives the height and the band's share; `water_pixel`'s `surface_y`), away from the swash's band. That last was aimed at the dark shards with the mesh's straight edges that the surf shows from above (main has them too) and **did not remove them**: they are neither the second train's lift nor the depth under a facet, and by elimination are most likely the sun's traced shadow of one facet of a lifted crest on the water behind it — the body's mesh is a shadow caster to its own surface and bottom — which is not this row's to change tonight and was not verified.

**What it does not do.** The second train shares the first's refraction and lee. The dissipation carries one flux for the group, so the group's small waves are lowered with its large ones. The setup's along-ray stress is the normal-incidence one. No reflection from a steep shore (it needs a third arrival). The lee is filled by the eikonal's creeping rays and the scheme's diffusion, not by diffraction's own pattern. A closed body's second train is its wind sea's too, with the lee's shelter over both.

## Channels

**Water that flows** (roadmap S96, 2026-11-07; the grounding and the numbers are [the flowing-water page](../experiments/flowing-water.md)). A scene's `water_channels` (`engine.scene.WaterChannel`, scene version 11) names channels — a stream, a river, a waterfall — each a centreline downstream with a width, a depth and a slope at every point. Each becomes a **ribbon of water**: a mesh with the water material and the channel bit, drawn like a body's and shaded by the same branch, whose ripples run downstream at the water's speed, turn rough and white where the flow is rapid, and fall as white water where the line drops at 45 degrees or more. The drainage generator that finds channels in the ground (roadmap W86) writes this description; until it lands a scene authors channels by hand.

**What the description carries besides the ribbon** (`WaterChannel` versions 4 and 5). `bank_width_widths` and `bank_width_m` (version 4, T78) and `flood_left_m` and `flood_right_m` (version 5, W93: how far the channel's flood bed reaches from the line each side, a number a point) are not drawn by the water: they are how far the placements leave the ground bare beside a channel, read by the exclusion ([scene_gen](scene_gen.md#exclusion)), and they travel here because the channels capability writes this description from the same plan it writes the terrain's cut from ([channels](channels.md#one-plan)).

**The type** (`schemas/scene.schema`; the W86 contract is the first six fields, word for word):

| Field | Default | Meaning |
|---|---|---|
| `name` | | the mesh is `water/<name>` |
| `points` | | the centreline, downstream, world positions; each point's y the **water surface** there |
| `width_m` | | the surface's width at each point, > 0 |
| `depth_m` | | the bed's depth below the surface at each point, > 0 (the deepest, on the line; the bed a parabola across) |
| `slope` | | the surface's fall per metre along the line at each point, Manning's S; not negative where the line descends |
| `seed` | 1 | the ripples' phases (u64; the material takes its two halves xor'd) |
| `manning_n` | 0.04 | the bed's roughness; Chow's gravel-bed stream, 0.030–0.050 |
| `shore_m`, `shallow`, `deep`, `depth_fade_m`, `roughness`, `absorption`, `scattering`, `transmission`, `turbidity` | as `WaterBody`'s | the optics, under a body's names with a body's defaults (not a shared sub-type: `WaterBody`'s fields are flat and append-only, and a sub-type would have moved them) |
| `reach` | empty | version 2 (W90): the reach's code per point, 0 dune-ripple to 6 colluvial ([channels](channels.md#reaches)); not read by the regimes yet |

Refused when the scene is read, with a sentence naming the channel: fewer than two points (`water channel "brook": it has fewer than two points; a channel runs from one point to another`), arrays of unequal length, a width or depth that is not positive, a slope negative where the line descends into or out of the point, a `manning_n` not positive, the optics out of a body's ranges. A build without the capability refuses a scene with any channel, as it does a body.

**How it reaches the renderer**: a second placement generator of this capability, **`"water_channel"`** (`src/scene_generator.cpp`), which the renderer's scene reader hands the list to as `{"channels": [...]}` in one call after the bodies (`read_scene_water_channels`, `scene_water.cpp`); mesh *k* and instance *k* are channel *k*. Each mesh's `SceneMeshInfo` carries a `SceneWater` whose `body` holds the channel's name and optics under a body's names (no shape, so a host that wades — engine-view's walker, through `read_body` — leaves it out) and whose `channel` is set, which the GPU scene turns into **`gfx::k_material_water_channel` (1 << 21)** on the material after `set_water_material`, as it does the open bit — a bit above every other material flag, so none of the water bits changes meaning (`gfx::WaterShading` was not given the flag: its size is pinned at 60 bytes by the size table). Everything else — the volume tier's optics entry, the depth map, the water modules — is a body's.

### The ribbon

`build_channel_mesh` (`include/systems/water/channel.h`): **sections every `spacing` metres** along each stretch between two points — `spacing = clamp(min(shore_m / 3, narrowest width / 4), 0.25, 1)`, the body's rule with at least four sections' worth across the narrowest width — each a row of `columns + 1` vertices across, `columns = clamp(ceil(widest × 1.5 / spacing), 4, 64)`. The row lies level across the line's **heading** (the mean of the two stretches' horizontal directions at a point, a mitre, interpolated along the stretch), at the surface's height interpolated between the points. Each row runs **a quarter of the width past either edge** (`k_channel_edge_extend`): where the ground rises over the bank it hides the surface by the depth test, so the shore is where the ground says (S97 owns the per-pixel shore), and the shore fade by depth (below) whitens nothing past the width. The budget is a body's 65,536 vertices: the spacing grows by a quarter until twice the rows fit. **The synthetic test channel** (six points over 87 m of line with a 10 m fall, widths 3–5 m): 0.667 m spacing, 12 columns, 140 sections written as 144 rows (four wraps), **1,872 vertices and 3,336 triangles**, 36.5 s of travel from head to foot; its GLB is 100,928 bytes and its depth map 466,610.

**What a vertex carries** — no new attribute, the body's GLB layout: the normal is the ribbon's (across × along), and the triangles face out of the water (up on a reach, downstream on a fall). **UV.y is the depth under the vertex**, a body's meaning: the parabola across the width, `depth (1 − (2a/w)²)`, zero past it. **UV.x is the flow phase**: the travel time from the head, `τ = ∫ ds / v`, seconds, constant across a section (each step the run over the mean slowness of its two ends), so a pattern drawn as a function of `τ − t` is carried downstream at the local speed whatever it is, and **the speed and direction are the phase's gradient** — its inverse length and its direction — which the resolve takes from the triangle's three corners. A glTF reader that keeps one UV set therefore carries the flow. **The phase wraps every 8 s** (`k_channel_phase_period_s`), because the cluster format stores UVs as half floats and 8 s keeps 4 to 8 ms; at a wrap the section is written twice — its first copy ending the strip above at `τ − base`, its second starting the strip below at a period less — which is a UV seam the cluster simplifier protects (`SeamRule::protect`, [geometry](geometry.md)), and every pattern the resolve draws is periodic in the phase with that period.

**The speed** at each point is Manning's, `v = (1/n) d^(2/3) S^(1/2)` with the depth for the hydraulic radius (a wide channel), floored at 0.05 m/s; interpolated linearly between points. **A stretch whose drop is at least its horizontal run (45°) is a fall** (`stretch_falls`): its speed is the free fall's from the lip, `√(v_lip² + 2 g h)`, and **below its foot the speed decays back** to the bed's over `0.4 h` (within 1 to 15 m), quadratically, so the plunge's white water is the Froude rule's. The cube root is Newton's, not the C library's, so the GLB is the same bytes from every toolchain.

**The brink** (S98): a **subcritical** reach that ends at a fall speeds up into it, as the depth falls to Rouse's brink depth 0.715 d_c (d_c = (q²/g)^(1/3), q = v d): over its last `k_channel_brink_reach` (4) d_c, quadratically, to q / (0.715 d_c), and the fall leaves the lip at that speed (`brink_speed` in `build_channel_mesh`). A supercritical reach goes over as it is — the six-point test channel's lip is one, so its GLB is the bytes S96 pinned. **The plunge stretch** (S98, `with_plunge_stretch`): a channel whose **last** stretch falls gains one more point, 0.4 h on along its heading at the foot's height (the last width and depth, slope 0), so its foot has the plunge's decay and white water a channel that continues has — unless it is **pooled**: the renderer's reader found its foot inside a water body (below, "The plunge"), names it in the generator's `"pooled"` list, and the body draws the plunge instead of a ribbon lying on the pool's own surface. The mesh and the depth map both take the channel through it.

**The depth map** (`build_channel_depth_map`): a body's map format, over the ribbon's bounding square at a quarter of its spacing, each texel the deepest of the stretches' parabolic beds at its nearest place on each stretch. **The bed is the description's, not the ground's**: W86 writes the depth from the ground's drainage, and a channel laid over an uncarved slope (the synthetic scene) still has its bed; where the ground stands above the surface the depth test hides the water, and where it lies below the description's bed the volume tier still sees the bed at the description's depth (with the terrain's colour). The files go where a body's go, `water-<hash>.glb` and `.depth` under one hash of both.

### Shading

**One call site** (`visibility_resolve.slang`, `water_pixel`): a water material with `k_material_water_channel` goes to `water_channel_pixel`, which calls the new functions of `water.slang` ("channels of flowing water") and then the tier's own surface path, low or volume, with their normal and roughness:

- **The flow** (`water_channel_flow`): the phase's gradient over the triangle from its corners' UV.x — the gradient g in the triangle's plane with g·e₁ = Δτ₁, g·e₂ = Δτ₂ — so the speed is 1/|g| and the direction g/|g|. Constant over a triangle; between neighbouring sections it changes by the speed's interpolation.
- **The lateral profile** (`water_channel_lateral`, S98): the speed across the width is the 1/6 power law's, `v(a) = 1.045718 v̄ (1 − (2a/w)²)^(1/6)` — fastest mid-channel, still at the banks, the discharge the section's — where `1 − (2a/w)²` is the depth under the pixel over the centreline's, and the centreline's depth comes from the depth map: two more bilinear samples 0.4 m either side across the flow fit the bed's parabola (its curvature by the second difference, its centre by the first). Beside a bank one probe falls dry and the three are taken inwards (a third fetch); where the bed is no parabola (a pool's bowl, an overlap at a bend, the low tier with no map) the pixel keeps the section's mean over its own depth, as S96 drew it. **The Froude number** is that speed over the **centreline's** depth (floored at 0.1 m), so the banks' shallows no longer read as critical.
- **The detail** (`water_channel_detail`, S98) in place of S96's six sines: **gradient noise in three octaves** over the body-local point, carried downstream by a **two-copy flow map** (Vlachos 2010): each copy sampled at `p − v t_k` with `t_k` running over a 1 s cycle, the two half a cycle apart and cross-faded by a triangle wave (the blend divided by √(w₀²+w₁²) to keep its contrast), each copy restarting at a new place drawn from its cycle's number — so nothing the surface shows repeats before the clock wraps at 1,024 s, the 8 s phase wrap is never seen, and nothing stretches. The largest octave is 1.5 depths across (0.2–4 m), its rms height **q²/2g** (Brocchini and Peregrine) with q the pixel's shear velocity `v n √g / d^(1/6)` at n 0.04, each smaller octave 0.47 of it with its height falling as l^(2/3): glassy where the water is slow, knobbly where it is fast. An octave finer than twice the footprint fades out and its slope's rms is added to the roughness, so the far water has no ladder.
- **Two long trains**: S96's sines carried by the phase (17 and 29 cycles a period with a static bend), at half the detail's height — the only part still periodic in the phase, and too weak to read as a ladder.
- **Standing waves** (`water_channel_standing`, S98) where the section's Froude number is in [0.8, 1.6]: stationary in the channel's frame — a function of τ alone, never of the clock — at Kennedy's wavelength 2πv²/g, drawn as the two whole numbers of cycles per 8 s either side of it cross-faded, steepness ka 0.12 at the band's peak and never above a quarter of the depth, strongest in the thalweg. In the normal only; the ribbon stays flat.
- **The roughness** rises by `0.25 min(Fr/2, 1)` and by the faded detail's slope.
- **Aeration** (S98): the foam share is S96's Froude rule — none at Fr 1, about four fifths of the surface by Fr 2 — times a fade in over 0.8–1.2 m/s of the pixel's speed (self-aeration needs about a metre a second: Chanson), so it is densest in the thalweg; its pattern is the same noise through the same two copies, **blurred along the flow over three taps** into streaks of cells half a depth across, and faded with the footprint to its share.
- **The shore** fades by depth, `shore_m × min(depth / 0.25 m, 1)`, as an open body's does, since UV.x is no distance from an edge.
- **A fall** — the triangle's geometric normal within 45° of horizontal — is a **sheet**: **glassy at the lip** (the tier's water on the face's normal, roughness 0.12, the sky's bright roll on the steep face by Fresnel) and **white water once the jet is fast enough**, a smoothstep over 4–6.5 m/s of the triangle's speed; streaks across the face (three sines across it, 1.3 to 5.1 cycles a metre along the face's own horizontal — from its plane, not from the phase's gradient, which differs a little from triangle to triangle and, times a point tens of metres out, drew S96's first captures' streaks as planks shifted at every edge — their phase carried down at the fall's speed) shade the foam and tilt the glassy part's normal a little. The lip is the crease between the last reach's triangles and the fall's.
- **The foam** is drawn as a white diffuse surface of albedo 0.8 on the ribbon's plane, lit by the sun (one more shadow query, only where there is foam) and the sky's light, blended over the water by its share.

**The clock** is the waves': `ResolveParams::water_time_s`, the world time reduced modulo 1,024 s, a multiple of the 8 s period, and each term of a phase reduced before it is added. The flow map's 1 s cycle divides it too, so the clock's wrap falls where both copies restart.

### The plunge

**Where a fall lands in a body** (S98): the renderer's reader (`find_plunges`, `scene_water.cpp`, before the channel generator runs) takes each fall's foot — the last point of a run of falling stretches — and, where it lies over water in a body's depth map (its nearest texel) and within a metre of the body's level, gives that body a **`gfx::WaterPlunge`** (`SceneWater::plunges`): the foot body-local, a radius of the fall's height over four (1–8 m) and the free fall's speed from rest, √(2gh). A channel whose last point lands so is **pooled** (the generator's `"pooled"` list, above). A body keeps **at most `gfx::k_water_plunges` = 7**, the highest falls first; the rest are dropped with a warning naming the body. The GPU scene packs them with **`gfx::set_water_plunges`** into one table entry after the body's next one — after the spectrum's five where it has a spectrum, the next entry then always written — sets **`gfx::k_material_water_plunge` (1 << 22)** on the material, and the body's branch (`water_plunge_foam`, called once in `water_pixel` beside the shore's foam) draws a disc of white water at each foot: whole to a quarter of its radius, fading to nothing at it, broken by the channel's noise carried **outwards** by the two-copy flow map at a tenth of the impact speed (at most 1.5 m/s), faded with the footprint; laid over the water by the shore foam's own path. A body no fall lands in packs nothing and draws what it drew.

### The banks

Roadmap S99 (2026-11-08). A river's banks stay wet above its surface: water rises through the bank's pores by capillarity, the **capillary fringe**, as high as the grain is fine. The reader writes one bank record a stretch (`channel_bank_records`, `scene_water.cpp`; `SceneWater::banks`): a `gfx::WaterShore` whose `stretch_a`/`stretch_b` are the stretch's two points — x, z, the surface's height, the half width — local to the channel's instance, whose `wet_m` is the fringe of the bank's material (`gfx::capillary_fringe_m`, Lane and Washburn's table: gravel 2.5 cm, coarse sand 13.5, sand 24.6, fine sand 42.8, silt 105.5; `domain/gfx/wet_ground.h`) — **a channel's description names no material, so `gfx::k_bank_default`, fine sand's 0.428 m, a loam's lower bound** — plus a **spray band** by the stretch's regime: a fall (a stretch that drops at least as far as it runs) half its drop, at most 3 m; a rapid (Froude above 1 at either end, Manning's speed for a wide channel mirrored from systems/water) 0.25 m (stated choices: no measured spray reach for small falls was found). No swash: a channel's level is static. The record grew from 64 to 96 bytes for the two points.

**Per pixel** (`water_channel_saturation`): the ground point's nearest place on the stretch, its height *h* over the surface there (linear between the points), and the saturation 1 under the surface down to 2 m and the fringe's smoothstep from 1 at *h* = 0 to 0 at `wet_m` above it, within the half width plus the run of a 1:25 bank over `wet_m` — exactly where the run alone (below) has dried the ground, so the reach and the record's square end there (until 2026-11-08 both reached a metre further, over ground no stretch could wet; `gfx::k_bank_run`). The wettest record wins. **A bank is damp, never flooded** (2026-11-08, from the v35 captures): the saturation is held at `k_wet_film_from` (0.85), below the film's threshold, so no bank carries standing water — the film is the swash's, and the channel's own surface is water — and *h* is taken as at least the point's run from the wetted edge over 25, the reach's own slope, so ground lying at or below the stage beside the channel (a floodplain, a cut's floor) dries over the reach instead of reading as saturated to its end. Without the two, v35's stream drew a standing film with a sun glint on every pebble out to 26 m from the water. A stretch's walk ends once the pixel is at 0.85, since no stretch can raise it further.

**Bounded by a tree.** The v35 forest has 60,477 stretches in 156 channels; a ground pixel cannot test them one by one. The GPU scene writes them after every body's record as a bounding-volume tree in depth-first order with escape indices (`gfx::build_bank_tree`: median splits on the longest axis of the stretches' centres; a node is a record with `stretch_a.w` = −1, its square and its heights, the lowest surface less 2 m to the highest plus its fringe, and the index to go on at in `material`), every stretch moved into the first channel's instance's frame so the tree has one. The resolve walks it depth first (`water_ground_wetness`): a node whose square or heights miss the pixel skips its subtree, so a ground pixel far from every channel tests the few nodes above it (the test's 3,200-stretch scene: under 64 of 6,399 records a far point), and one near a bank about twice the tree's depth, more where stretches' reaches overlap. **What it costs** on v35 (msvc-release, RTX 5090, 2026-11-08, upper bounds beside other agents' builds; the table is [the shore page's](../experiments/shore.md#what-it-costs-and-what-it-looks-like)): the resolve's median grew 0.35 ms at 1080p where the ground is mostly far from channels (shore-open) and **1.30 ms at 1080p, 3.76 ms at 4K at the stream**, where every ground pixel lies within a bank's reach and walks to the leaves — the largest single cost in S99. Since (2026-11-09) the reach and the squares end at 25 `wet_m` past the half width, where the run alone dries the ground (the metre beyond it was ground no stretch could wet, so the picture is the same bytes), and the walk reads a record's square and kind before the rest of it; the structure the cost wants is the banks' saturation baked per terrain tile at load, one texel read in place of the walk (the channel network is static per scene), which is not built yet (roadmap S99). `renderer.water.banks` (`on`, `off`, `cycle`; a **measurement switch**, `gfx::k_shadow_wet_banks_off`) skips the walk, or under `cycle` skips it on frames whose (f / 8) is odd, so one flight pairs the banks' cost against the same frames without them. The water pixel's lookup of its body's record stops at the first tree record, since bodies come first. Records: 2 n − 1 for n stretches, 96 bytes each — 11.6 MB resident for v35's.

### What it does not do

The surface is the ribbon's flat sections: no superelevation at a bend, no hydraulic jump in the mesh, no standing wave shape — the standing waves and the rapids are in the normal, roughness and foam on a flat surface (a displaced ribbon would need its heights in the vertices and a third attribute to say where: [the flowing-water page](../experiments/flowing-water.md#standing-waves-over-riffles)). The shear velocity is taken at Manning's n 0.04, not the channel's own, which no material slot carries. The flow map's velocity is the triangle's, so where it changes fast (a plunge's decay) its copies jump at triangle edges, under white water. No foam collects at the banks from eddies; S96's foam lines there (the depth floor's criticality) are gone with the lateral profile. No **mist** at a fall's foot: that is a participating-medium source of the volumetrics capability (R47), requested, not built. No **sound**. The walker does not wade in a channel (a channel has no outline `depth_at` knows) and the physics does not push anything along it. A channel joining a body or another channel overlaps it, with no confluence; the open sea's plane knows nothing of a river mouth. The volume tier's march treats the map's depths as below a level surface, which on a fall is not the geometry (the fall is white there anyway).

## Wading


**The depth at the feet.** `water::depth_at(bodies, ground, at)`: the deepest body whose outline holds the point's x and z, of its level less the ground's surface there, never below zero; 0 outside every body. engine-view's walker asks it at its feet before every step (`view::Walker::set_water`, attached in `main.cpp` from the bodies on the scene's mesh infos and the scene's ground at its own time, `ENGINE_VIEW_WATER`), and scales the step by **the declared curve** (`view::wade_scale`, `walk.h`): full speed to the ankle (0.3 m), falling linearly to half at the waist (1 m) and to a quarter at the chest (1.4 m). **At the chest the water is a wall**: a step whose heading leads deeper — the depth a quarter metre ahead along it greater than at the feet — is not taken (a scale of 0, counted as a stopped tick), so the walker stops chest deep and wades back out the way it came. No swimming: S86.

**The water's mesh is not a collision surface**: `scene_collision` gives no body to a mesh whose `renderer::SceneMeshInfo::water` is set (it keys meshes by their index in the scene, and this is the mark it reads beside `terrain_mesh`), so the physical walker stands on the ground under the surface, and the ground-follower on the provider's height as always.

**Determinism.** The depth is a function of the position and the scene, so a walk through water replays bit for bit (the end-to-end case replays one to the same trajectory, walker hash and wading block). A walker with no water, or at a depth of 0, scales by exactly 1 — `x * 1.0f` is `x`, contraction is off (ADR-0035) — so every walk recorded before water existed replays as it did, and a scene with no water attaches nothing. The summary's `walk` block gains `wading` — `max_depth_m`, `ticks` in water, `stopped_ticks` — only where there is water.

**What the tests hold.** `walk_tests.cpp` (no device): the curve's points; a walker over a shore that deepens half a metre a metre walks east for twenty seconds and stops at x = 4.80 (the chest's 1.4 m is at 4.8), 1.400 m deep, stopped 3,717 ticks of 4,800, and wades back west; the same walk twice is the same; no depth function and one that answers 0 walk the same floats and hash. `walk_water_view_tests.cpp` (a window on the tests' private desktop and a device): on the committed oasis pool, a walker started on the east shore facing the middle holds W for twelve seconds and stops chest deep — 1.417 m at the most, 1,184 ticks stopped, the eye at x = 5.26, short of the middle — with physics on (2026-10-17, RTX 5090); its recording replays offscreen to the same trajectory, walker hash and wading block.

## The water at a point

**What a game module asks** (`include/systems/water/query.h`, `src/query.cpp`; roadmap A43; hotload ABI 10's `water_at`, [apps](apps.md#what-a-module-can-ask-the-world)): whether a point is under water, the surface's level there, the depth, and the water's velocity in the ground plane — for an animal choosing or avoiding water, wading or drinking, and later for a player pushed by a stream. `water::WaterQuery` holds the scene's bodies with their depth maps and its channels' descriptions; `sample(at, out)` asks each and **the deepest wet answer wins** (`WaterPoint`: `wet`, `level`, `depth`, `velocity` (x, z), `source` 1 a body or 2 a channel, `index` in the order given). Dry is an answer. engine-view builds one from the scene's mesh infos (`Wading`, main.cpp: a body's `SceneWaterDepth` as the reader read it, a channel's `SceneWater::channel_source`) and hands it to the game runner.

- **A body answers from its cooked depth map** (`body_water_at`): inside the body (its outline; its flooded region for one that fills; anywhere for an open one), the map's signed depth bilinear over the four texels round the point — the same map the resolve shades the bottom from, so a module's depth is the drawn depth — wet where it is positive, the level the body's, the velocity zero (a body's waves move no water anywhere on average; their orbital motion is the surface's, not a current). Past the map's square an open body answers its level less the ground's surface, as `depth_at` does; a closed one is dry there. **Why the map and not `depth_at`'s ground**: the ground a host holds may not be the ground the body was cooked over (a streamed world's tiles, a time-lapse), and a module comparing what it reads with what it sees should find the same water.
- **A channel answers from its description, behind one function** (`channel_water_at`): the stretch of the centreline whose (x, z) is nearest the point and holds it within half its width there (the first such in the line's order on a tie), the surface's height interpolated along the stretch, the bed's parabola — `d (1 - (2a/w)^2)` at offset `a` across width `w`, as the mesher draws it — and the velocity along the stretch's heading at Manning's mean speed for the centre's depth and the slope (`manning_speed`) times the 1/6-power lateral share (`k_channel_profile_mean · r^(1/6)`, here `cube_root(sqrt(r))`, never `std::pow`). **This is the one function the channels' solved surface stands behind**: when a channel is solved from its discharge — a level, a depth, a speed and the wet reaches at every station — the solved stations replace the description inside `channel_water_at` and nothing a module calls changes.
- **Cost**: a body is a bounding test, an outline test and four texels; a channel a pass over its stretches. `query_tests.cpp` measures a thousand questions over a pond and a stream in one step (its message). No allocation.
- **Determinism**: `+ - * /`, `sqrt` and `cube_root` only, so the same bits on every toolchain; `query_tests.cpp` pins a walk of 64 questions across a pond and down a stream by a hash of their bits.

**Testing** (`tests/query_tests.cpp`, no device): the bowl of `water_tests.cpp` under a 12 m pond, its mesh and depth map built as the generator builds them: at five points the answer is wet at the level, still, its depth **equal to the map's own bilinear depth** and within the map's half step plus the bowl's curvature over a texel of the ground's depth there; past the outline and on the shore, dry. A straight stream: on its line the half-way surface, the centre's depth and Manning's speed times the profile's centre share along +x; a metre off, the parabola's share of the depth and the lateral share of the speed; past its edge and past its foot, dry. End to end, `apps/engine_view/tests/world_queries_view_tests.cpp` holds five points of the oasis pool to the `.depth` file its reader cooked.

## Capability contract (ADR-0027)

This is a capability: it was added without editing `core/`, `foundation/`, the render graph, the scheduler, or another capability, and it can be removed from the build the same way.

| Registration point | This capability | Status |
|---|---|---|
| Capabilities it requires | none | stands alone; tests link terrain, sky and scatter for the oasis scene, and tileset for an authored bowl |
| Component and event types | none | a body is scene data (`engine.scene.WaterBody`, the scene format's), not entity state |
| Tick scheduler entry | none | nothing ticks: the waves are a function of the frame's clock, drawn by the resolve |
| Render-graph passes | none | the surface is an instance; its shading is a material class of the resolve |
| Content-build derived step | the GLB per body, clustered by the renderer's cache | done |
| Scene generator | placement generator `"water"` | done |
| Protocol methods | none | not needed |
| Tunables | none | every number is the body's |
| LOD policy | the cluster DAG of its mesh | done |
| Determinism | derived: drawn, and `depth_at` a function of position | done |
| Zero cost when unused | a scene with no block calls nothing; no material carries the flag | done |
| Tests and size table | `tests/water_tests.cpp`, `tests/water_scene_tests.cpp`, `tests/tileset_ground_tests.cpp`, `tests/size_table.cpp` | done |
| Bench | none: no hot path on the CPU | |
| Removal proof | `ENGINE_WITH_WATER`, off in the minimal build | works: a block is refused with a sentence |

**Removing it.** `cmake --preset msvc-minimal` (or `-DENGINE_WITH_WATER=OFF`) drops the module and its tests; the module disappears from `build/<preset>/modules.json` and is listed there under `disabled_capabilities`. Everything else builds and passes, and a scene with a `water` block is refused.
