# world_sound (systems)

**Purpose.** The sound stage a host creates for a game (roadmap S111, the first stage of [audio](audio.md#sound-for-the-world-the-design-s110)'s design; [ADR-0079](../adr/0079-world-sound-is-synthesised-from-world-state.md), proposed). One object, `world_sound::SoundStage`, owns the clip store, the mixer, the output (a device or the null backend), the listener, the clips a scene's `sound` block declares and the voices a game module starts; a host creates it, hands it a listener and ticks it. Sound code lives here and not in an app, as rendering code lives in [renderer](renderer.md). engine-view is the one host so far ([apps](apps.md#sound-a-module-plays)): `--audio` chooses the mode and a module's `sound_clip`, `sound_play` and `sound_stop` reach the stage. **Since S112 it also hears the world's wind** — in the crowns a host's canopy table names and at the listener's ears ("The wind in the trees and at the ears", below). **Since S114 every world voice carries its path** — the air, the forest and the ground by octave band ("Distance", below). **Since S113 it hears running water and the surf** — a channel's stretches and falls from its solve, a body's shore where its train breaks, a trickle's separate bubbles ("Running water and the surf", below).

**Why this shape.** The design's reasons hold ([audio](audio.md#the-capability-systemsworld_sound)): one object a host creates, so engine-view, engine-host and the editor can each host sound without each wiring a store, a mixer and an output; a capability of its own requiring only `audio`, so the minimal build proves nothing depends on it. Three things were settled while building it:

- **The handle is the stage's count, never the mixer's slot** (ADR-0079 decision 5). `play` answers `Ok` with `1, 2, 3, …` whether or not a voice sounded — muted, the pool full of louder voices, no device — and `stop` answers `Ok` for any handle issued. Refusals are the count's too: an unknown clip, a gain outside [0, 16] or a position that is not finite is `InvalidArgument` in every mode, and nothing is issued for it. So a module that keeps what the calls answered in its state (the fixture does) holds the same state heard and not heard, which the end-to-end case checks.
- **`Off` is a stage, not an absence.** A stage opened `Off` keeps the block's names and the count and builds no store, mixer, thread or output, so a muted session answers exactly as a sounding one. A scene with no `sound` block is the other case: every call answers `Unsupported`, as the hot-load header always said.
- **The block is the scene's** (`engine.scene.Sound` in `schemas/scene.schema`), not this capability's, so a build without the capability reads the same scene and a module there hears `Unsupported` rather than a refused scene.

**Owned data.** The declared clips (name, source, gain, distances) in the block's order — the index a module holds; the store, the mixer and the output when not `Off`; the last 256 handles' voices and world positions (an older handle's one-shot has ended long since, and its stop sends nothing); the listener and the mixer's frame; the null backend's block and the WAV's one-second buffer; the counters (`StageStats`).

## The scene's `sound` block

```json
"sound": {"clips": [
  {"name": "chirp", "recipe": {"kind": "Chirp", "frequency_hz": 2500, "end_hz": 4500, "duration_s": 0.18},
   "min_m": 2, "max_m": 80},
  {"name": "door", "path": "sounds/door.wav", "gain_db": -3}
]}
```

Each clip has a unique `name`, exactly one of `path` (relative to the scene file) and `recipe`, a `gain_db` (−60 to 24) and the two distances of the mixer's tapered inverse law ([audio](audio.md#sources-are-objects)): full level inside `min_m`, silent at `max_m` (defaults 1 and 60). A block with a repeated or empty name, neither or both of a path and a recipe, or a value out of range refuses the scene with a sentence naming the clip. **Formats**: a file is read by the store's decoders, so WAV, FLAC and MP3, or a `.clip` the content build wrote ([audio](audio.md#clips)); Vorbis and Opus are not decoded (the owner's question 6 on the audio page). Clips are decoded once, inline, when the stage opens (before the module's `on_load`), under a budget of 64 MB for a game (`StageConfig::clip_budget_bytes`; the mixer's own `audio.clip_budget_mb` is 256), and a clip that does not decode refuses the session.

### Recipes

**A clip the stage generates, so a fixture or a template has a sound with no binary in the tree.** `SoundRecipe`: `kind` (`Tone`, `Chirp` — a sine swept linearly in frequency, a bird's simplest note — or `Noise`), `frequency_hz` and `end_hz` (20 Hz to 20 kHz), `duration_s` (1 ms to 10 s), a linear `attack_s` and `release_s` inside it, `level_db` (−60 to 0 dBFS peak) and a noise `seed`. Mono at 48 kHz. **The same recipe is the same samples on every toolchain**: the phase is a 32-bit integer stepped by `round(f · 2³² / 48000)` (a chirp's step interpolated in integers), the sine is the mixer's own quarter-wave polynomial (`audio::sin_quarter`), the noise is xorshift32, and the level is `gain_from_db`, which takes 10^(dB/20) as a power of two (`ldexp`, exact) times eighteen terms of e^y's series — no `pow`, `exp` or `sin` from the C library, whose last bits MSVC and glibc may disagree about ([audio](audio.md#determinism)). The chirp's samples are pinned in the tests.

## The stage

| Call | Answers | What it does when sounding |
|---|---|---|
| `open(config, block)` | false with a sentence | the clips decoded or generated, the mixer built (stereo for the null backend; the device's layout by `resolve_layout`), the output opened |
| `clip(name, out)` | `Ok`, `NotFound`, `Unsupported` (no block) | — |
| `play(clip, at or null, gain, handle)` | `Ok` with the next handle; `InvalidArgument`; `Unsupported` | a one-shot on the `sfx` bus at `gain` × the clip's gain, 3D at `at` with the clip's distances, or 2D on the listener with `at` null |
| `stop(handle)` | `Ok` for any handle issued; `InvalidArgument` for 0 or one never issued | the mixer's 10 ms fade, when the handle's voice still sounds |
| `set_listener(at, forward, up)` | — | one `SetListener` when anything changed; a move into another 64 m cell moves the mixer's frame and places every 3D voice still sounding again in it, one `SetSource` each |
| `tick()` | — | the mixer's and the output's update; under the null backend 48,000 / `tick_hz` frames pulled (the remainder carried, so a second of ticks is a second of frames) and, with `wav_out`, kept |
| `close()` | false when the WAV could not be written | the WAV's sizes written; the output closed |

**The mixer's frame** is [audio_system](audio_system.md#the-mixers-frame)'s: the mixer is handed positions less the corner of the listener's 64 m cell, so the floats it gets are metres from a corner and not world coordinates, and a listener moving inside a cell is one command. The stage keeps each 3D handle's world position in f64 to place it again when the frame moves. The test stands its listener 10,000 km out.

**`--audio-out`'s WAV** is 32-bit float (`WAVE_FORMAT_IEEE_FLOAT`, the mixer's own samples, nothing converted), interleaved at the mix's channel count: a 44-byte header written at `open` with its sizes zero, the frames appended a second at a time from a buffer made at `open`, and the header's sizes written at `close` by reading the file back. The store's own decoder reads it back bit for bit (a case).

## When the device fails

The engine's rule for every binary holds here: no failing device crashes the process, blocks the frame or the tick, or opens a dialog ([platform](platform.md#no-engine-binary-opens-a-dialog-when-it-fails)). **An output that will not open, a write that fails, and a device lost that cannot be opened again each leave the stage silent**: the output is closed, nothing is mixed or sent from then on, the reason is logged once (`audio stopped; the game's calls are answered as before`, with `why`) and kept in the summary (`stopped`, `stopped_why`, `stopped_tick`), and `clip`, `play` and `stop` answer exactly as before, handles counted. None of it fails the session; only a clip that does not decode does, since that is the content's fault and not the device's. A device lost mid-session is first `audio::Output::update`'s to reopen ([audio](audio.md#device-changes-at-run-time)); only when that falls back to the null backend does the stage stop. The tick never waits on the device: commands go through the mixer's wait-free ring, and a ring a stalled device has let fill refuses a play (counted in the mixer's `queue_full`) rather than waiting. **The two cheap paths are proven on the null backend through a fault seam** (`StageConfig::fault_refuse_open`, `fault_fail_write_at_tick`): the scripted session's answers are the same as a healthy stage's, and nothing is pulled or started after the failure. A WAV that cannot be written (`--audio-out`) is the write path's own case of the same rule.

**The device is opened the conservative way**, as `domain/audio`'s output already does: shared mode (miniaudio's default; the engine never asks for exclusive), 32-bit float handed to the platform's shared mix, which converts to the endpoint's own format, a callback the device's thread calls (miniaudio's model; no push), and a period of `audio.period_frames` (480 frames, 10 ms). Nothing of it was changed for S111.

## The wind in the trees and at the ears (S112)

Roadmap S112, the design's stage 2 ([audio](audio.md#stages)); the grounding and every source's mark are [the grounding page](../experiments/world-sound.md), whose section "Read again by S112" says what was read again when each number below was pinned. **The world is on in a stage opened with `StageConfig::world`** (engine-view sets it unless `--audio off`), whether or not the scene has a `sound` block — a module's calls still answer `Unsupported` without one — and it is made of the mixer's shaped-noise voices ([audio](audio.md#the-shaped-noise-voice)): `src/world_field.cpp`, internal to the module.

**What drives it: the frame's wind as every reader has it.** A host hands the stage a `WorldWind` before each tick: the scene's `gfx::WindDesc` (or none), W151's live state (`gfx::WindLive`: the mean, the direction and the forced gust), the sky's clock and the world's (S118: the mean and the direction are the weather's, at the sky's hour, `WorldWind::sky_time_s`; the turbulence is the air moving, on the world clock, `WorldWind::world_time_s`, as the sway's is). The stage takes the arguments the trees' sway takes (`renderer::scene_flora_wind`): under a live wind, the live mean and direction at the scene's roughness with `gfx::wind_gust`'s turbulence over it and the forced gust, `mean (G − 1) level`, added; otherwise the wind the sway uses — the hand tunable's (`renderer.flora.wind_*`) when it is set, else the scene's own (`renderer::scene_wind_in_use`, which the sway's `scene_flora_wind` and engine-view's sound both call: the review's M5) — and its gust. It asks the gust **at each source's own place** (the sway asks it at the origin, the same function), then carries the wind from 10 m to the crown's foliage height by the neutral log law over the roughness. So a key that steps the wind, a game's `wind_set` and a forced gust are heard on the tick they are drawn, and the gust that bends a crown is the gust heard. The stage holds no wind of its own. The trees' sway takes the live *mean* through a lag (W154: a tree's lean is a damped oscillator's); the sound does not, since the air moves at once and the leaves' noise is the flow's, not the lean's — the gust and the turbulence are not lagged on either side, so a gust's front reaches both on the same tick.

**What a host hands it: the canopy table** (`CanopySource`, a function pointer and a context): every crown within a reach of the listener, as a `Crown` — the foot's world place, the foliage's middle height above it, the one-sided leaf area, and a class (`Blade` for leaves struck together, the default; `Needle` with its needles' width; `Bare` for twigs). The table is walked at `audio.world.refresh_hz` (8), into an array of `audio.world.max_crowns` (8,192; past it a crown is counted in `crowns_dropped`, never allocated). engine-view's table is in `apps/engine_view/game_sound.cpp` ([apps](apps.md#sound-a-module-plays)).

**The voices** (`audio.world.*`, every count a tunable):

| Voice | How many | Level at the listener, dB SPL |
|---|---|---|
| a crown of its own | `crowns`, 6: the loudest at a refresh, a chosen one kept across 3 dB of hysteresis, a 3D source at its foliage | `L_class + 30 log₁₀(U / 5) + 10 log₁₀(A / 100) − 20 log₁₀(r / 10)`, r at least 2 m; L 50 dB for blade and needle, 45 for bare |
| a bed | `beds`, 8: a 45° sector of azimuth round the listener, everything not chosen summed by power band by band, placed 20 m out toward its power-weighted direction with a spread by how little that agrees | the same law, summed, at the gust at the bed's power-weighted place |
| the ears | 2, 2D, hard left and right, each its own seed | `84.9 + 40 log₁₀(U_rel / 4.5) + audio.world.ears_db ± audio.world.ears_side_db · side` |

U is the wind at the crown (or for the ears at 1.7 m, less the head's own velocity, `U_rel`); A the leaf area in m²; r the distance. **The laws**: a crown's level climbs 30 log U, 9 dB a doubling (Fégeant's law as Bolin's thesis gives it), and is linear in its leaf area (Bolin's source term); a point's spreading. **The anchors are excerpts, not a model's constants**: Fégeant's and Bolin's radiation constants were not reached tonight either, so 50 dB is "trees near a house, 51 to 55 dB(A) at 40 ft" read as a crown of 100 m² of leaf at 10 m in 5 m/s, and the bare tree's 45 dB is "an average of 45 dB at 5 m/s" with its distance taken as 10 m. **The spectrum** is each class's fixed octave shape (in leaf strongest below 4 kHz and broadband, bare below 1 kHz: the two sentences the excerpts give, the shapes a choice that keeps to them); a needle crown gives half its power to the voice's movable band at **f = 0.2 U / d** (the Aeolian tone, St 0.2; Q 3 for a crown's spread of needle widths and speeds), so a conifer's hiss climbs an octave a doubling of the wind; a blade crown has no movable band. **The ears**: the pressure goes as the square of the speed, 12 dB a doubling (Korhonen 2021), from 84.9 dB at 4.5 m/s (Seidman and others 2017, a cyclist's ear); flat below a corner of 300 Hz at 4.5 m/s that moves with the speed and falling `audio.world.ears_slope_db` (26) an octave above it; the downwind ear the louder (Seidman: loudest at the downwind ear side-on), by `ears_side_db` (4 dB, a choice) each way. **Their gain, `audio.world.ears_db`, is −30 dB** (the owner's "depends on wind speed, pick some sane value"): at its physical level the head's wind would be 85 dB in a moderate breeze, 30 dB over a crown overhead, which is what a microphone with no screen records and not what a listener attends to; 30 dB under puts it level with a near crown at about 5 m/s and lets it overtake the trees above, since it still climbs 12 dB a doubling to their 9. The ears are heard only where the air moves: a walker in still air hears no wind of their own making at this stage, and a step faster than 15 m/s (a teleport, a replay's cut, a camera flown by hand) adds none.

**One loudness scale: `audio.world.reference_db` is 105.** A band's level in dB SPL becomes a gain as `10^((L − 105) / 20)`, an RMS of 1.0 in full scale (the voice's bands are unit RMS) being 105 dB SPL. That is the cinema's reference, −20 dBFS RMS reproduced at 85 dB SPL (SMPTE RP 200's calibration, the scale the forest's bird-call clips are mastered to), with dBFS RMS taken against an RMS of 1.0 as the mixer's samples are: so a game's clip played at its file's level and the world's sounds sit on one scale, and a crown at 50 dB SPL is −55 dBFS. Nothing compresses the range (the owner's answer 4). A level under `audio.world.floor_db` (10 dB SPL) holds no voice.

**The world's hold** (S112-2, the first review's M3; said plainly since S112-3, the second review's N4). The scale's ceiling is 105 dB SPL of RMS, and the laws pass it: at 42 m/s 10 m up (a storm) the head's own wind is 29 m/s at 1.7 m and **117 dB SPL at a bare ear** by Seidman's anchor and the square law — 12 dB over the scale's ceiling, which is why the ears sit `ears_db` (30 dB) under their physical level and play at about 87 dB (−18 dBFS) there; a crown of 800 m² 2 m away is −3 dBFS by its law, and the beds of a dense wood out to 2 km −4 to −9 dBFS. The world is noise close to Gaussian, whose peaks run about 12 dB over its RMS (4 σ is exceeded by 6 samples in 100,000), so the mix's hard clip at ±1 would begin where the world's summed RMS reaches −12 dBFS, from about 30 m/s up. **So the world's voices summed are held at `audio.world.ceiling_db` (−12 dBFS RMS), and this is exactly what the hold does.** Under the ceiling nothing is touched, by a bit: from a calm to about 30 m/s the range is the laws' own. Over it, the hold is **an infinite-ratio limit on the summed modelled level**: every tick the field sums its voices' bands in full scale's units — crowns, beds and both ears — and when the sum is over −12 dBFS RMS (93 dB SPL on the scale) every world voice is scaled by the same factor that tick, so the sum sits exactly at the ceiling (6 dB over: every world voice down 6 dB, `held_db` −6). It acts per tick, with **no look-ahead, no attack, no release and no hold time**; the only smoothing is the mixer's field ramp (`audio.field_ramp_ms`, 50 ms) toward each new target. What follows from that, as it is: **from about 30 m/s a gale and a storm are one level**, and the scale's top 12 dB (93 to 105 dB SPL) is never reached by the world; while it holds, **one crown's gust lowers the beds and the other ear** with it, since all are scaled together (the balance between them and every spectrum stay); and it does not make the world clip-free — at the ceiling the noise's 4 σ peaks still pass full scale on about 6 samples in 100,000, **a few clipped samples a second a channel**, counted by the master's `clipped_samples`, with a game's clips adding on top of the world's and the master behind both still the counted hard clip of [audio](audio.md#the-master) (its look-ahead limiter off by default). `WorldStats::held_db` is the reduction at the last tick and `held_ticks` the ticks it acted on (the summary's `world.held_db`, `held_ticks`), so a storm that reaches the ceiling says so. **The choice is open with the owner**: this hold, a higher reference level (`audio.world.reference_db`, which moves the whole world against a game's clips), or the plain counted clip with no hold at all. The tunable that turns the hold off is `audio.world.ceiling_db` (range −40 to 0): at its top, 0 dBFS RMS, it acts only where the summed RMS is already at full scale and the samples would be clipping by the thousand, which leaves the master's counted hard clip doing the work alone — the plain clip in effect; there is no other switch. Nothing in it changed in S112-3.

**Calm holds nothing**: under `audio.world.calm_m_s` (0.5 m/s) at its place a source is silent, and a source that falls silent is stopped, so a calm world sends no command and holds no voice. **An unchanged world sends nothing**: a voice's description is sent again only when a lane's gain moves by more than 1 % (0.09 dB) or the movable band's centre by more than 0.5 %, and the beds are placed again only when the listener moves a metre. The voices ramp to each description over `audio.field_ramp_ms` (50), **a fresh one from nothing** (S112-2, the review's M2: noise has no authored attack to keep, and a step from silence to broadband noise at every crown's start was a click). A move the mixer's ring refused (a full queue) is placed again on the next tick rather than at the next cell crossing (L3; `WorldStats::place_retries`). World voices play on the `ambient` bus at priorities under a game's default (crowns 40, beds 50, ears 60), so a game's one-shot takes a crown before a bed; the design's `world` bus under `ambient` is not added (the default tree is the mixer's).

**The LOD policy**: voices by level at the listener, beds by sector, and a host's table merges far crowns — engine-view's sends every crown of a group (a 128 m cell of the loaded instances, a placement tile) whose nearest edge is within `audio.world.near_m` (96) of the listener, which is crowns out to 96 m plus the group's radius, nearest group first, and a farther group as one crown a class at its leaves' centroid, marked `merged`. Nothing past `audio.world.reach_m` (2000) is summed. **A merged crown is the beds' only** (L6): it is never chosen as a crown of its own, so a 128 m cell is never one point source. **A crown has a size** (M4): `Crown::extent_m`, its farthest leaf's horizontal distance from its foot (a mesh's measured `MeshLeaves::extent_m` times its scale; a merged group's radius), is the least distance it is heard at, so a listener inside a stand — a wood flattened into one glTF mesh, whose leaves' centroid is now its place rather than the mesh's origin — hears it at its edge's level and not as a point 2 m away. **A full table keeps the nearest** (M1): past `max_crowns` a crown takes the place of the farthest kept when it is nearer, by a total order (distance, then place, area and class) so which are kept does not depend on the heap's implementation.

**What a refresh costs** (S112-2, the review's H1): a refresh walks what changed and nothing else. engine-view's table lists a streamed world's drawn tiles by key with each tile's own placements and version (`world::PlacementTiles::tile_own`: never the tail, whose rebuild and 64.6 MiB T131 took away; and never a tile that draws nothing, since a tile the mesh room yielded was once listed with a wrapped count of about four billion and walked off the end of memory, T214, 2026-11-22), matches them to the groups it holds in one pass over two sorted runs (no search: a re-keying only when the drawn set changed), and walks a tile's placements only when its version moved — at most `audio.world.walk_instances` (4,096) placements a refresh, the rest carried to the next (the first changed tile always taken, so a tile larger than the allowance is still made) and counted. A tile's crowns are kept with it, so a near tile is sent from its table, not walked. The near groups are sent one by one, nearest first, while `audio.world.near_crowns` (1,024) lasts and merged past it; a group farther than four times `near_m` (384 m) is summed by power into its 512 m cell of a fixed 9 × 9 grid round the listener's, one merged crown a class a cell, so a refresh sends a few hundred far crowns however many tiles a world draws (the streamed forest's first smoke flight sent 1,600 merged crowns a refresh from 1,273 tiles, and its refresh frames ran to 1.3 ms at p99 before the cells). A steady walk allocates nothing (the groups' and the lists' scratch grow to a high-water mark), and the cases hold it by counts: an unchanged world walks no placement, one tile's change walks that tile's and no other's, a tile let go and another drawn walks the new one only. **Changed tiles are walked nearest the listener first** (S112-3, the second review's N2): after a load or a cut, about 861 tiles at about 495 placements each fill in over a hundred refreshes (some twelve seconds at the refresh rate), and in key order the tile under the listener could be among the last. A refresh collects only the changed tiles — a tile is changed when it is new or its version moved — with each one's distance (a made tile's leaves' centroid, a new one's first placement, within a tile of its leaves), and sorts those by distance then key before the walk; so what it sorts is at most the tiles held (861 on the staging, an `O(C log C)` sort of `C` changed tiles in a scratch that keeps its room), the first still taken whole and the allowance as it was, and a steady world collects none, sorts nothing and allocates nothing (the case's count holds). A case: a far tile with the smaller key and a near one arrive in one refresh with room for one, and the near one is walked.

**Known, not mended** (the second review's LOWs, S112-3): **the first changed tile is walked whole whatever its size**, so a refresh is bounded by the largest tile's own placements plus the allowance, not the allowance alone, and a slow frame that runs several 240 Hz ticks can run more than one refresh; **a stand flattened into one mesh** is one source at its leaves' centroid with its distance floored at its extent, so a listener inside a 1 km uniform stand hears about 10 dB too little (π ρ where the stand's law gives 2π ρ ln(R/r_min)) and from one direction; **a placement drawn in two forms is heard through its far form's measured leaf area** (`tile_own` leaves the near hand-off forms out, which is right — the tree is not counted twice — but the card's area is not the near mesh's); **the far field's 512 m bins are laid on the listener's 512 m cell**, so the far crowns' places step when the listener crosses a cell line; and **the module-less host is handed the tiles only inside `#if ENGINE_VIEW_GAME`** (`attach_world_to_game`), so a build with `world_sound` and without `game` never hears a streamed world's tiles without a module.

**A crown's class is declared** (S112-2, the review's M6 and item 3; the owner's rule that a feature keys on an asset's declared properties): a scene's mesh may say what its foliage sounds as, `"sound": {"canopy": "Blade" | "Needle" | "Bare" | "None", "needle_mm": <mm>}` (`engine.scene.MeshSound`, `Mesh` version 3, `Scene` version 13, the version that also added R86's `lamps`), and that is used when present; else what the species a generated tree's container records **declares of itself** (S112-3, the second review's N3: `geometry::FloraSpeciesInfo::canopy` — `none`, `blade`, `needle` — and `needle_um` beside the species table in `domain/geometry/flora_species.h`, held to "a conifer says its width and nothing else does" at compile time; the app maps no names): the conifers needles (1,200 µm, pine 1,700), the trees and the tall shrubs (`shrub`, `beaked_hazel`, `red_osier_dogwood`) blades, and the ground's cover, the grasses, sedges, reeds and meadow, the water plants, the alpine mats and the low shrubs (`bearberry`, `blackberry`, `big_sagebrush`) no crown — and a species added later is silent until it declares one, never a broadleaf by default; **else the mesh is silent**, so a fence, a grating, hair cards or a decal's alpha cards are never measured as leaf, and an imported tree is heard by declaring itself.

**Determinism**: presentation, as the stage is: the field reads world state and writes none; its gains go through the C library's `pow` and `log10` and the gust's `sin` and `exp`, so a world render is the same bytes run after run on one toolchain and **is not pinned across toolchains** (the voice's own bytes are: [audio](audio.md#the-shaped-noise-voice)).

## Distance (S114)

Roadmap S114, the design's stage 4 ([audio](audio.md#distance)); the sources and every number's mark are [the grounding page](../experiments/world-sound.md#read-again-by-s114). **Why it came first: the owner heard a waterfall.** On the forest at 3 m/s the beds — the far wood summed by sector with spherical spreading alone — stood 10 dB over the six nearest crowns, kept their top octave and barely moved (the forest's need 171). A uniform wood summed by spreading alone grows as the logarithm of its radius, so everything out to `audio.world.reach_m` (2 km) counted, and nothing took the top first: a steady broadband roar over everything near, which is what a waterfall is.

**Every world voice but the ears carries its path, octave band by octave band** (`path.h`, public, so a host or a case may evaluate a term): the band's power after spreading is multiplied by 10^(−A/10) with

| Term | dB | Over |
|---|---|---|
| the air | ISO 9613-1's pure-tone coefficient at the band's centre, at `audio.world.temperature_c` (20) and `audio.world.humidity` (70 %) | the whole path, foliage to ears |
| the forest | Hoover's 0.01 r f^(1/3) | the share of the path along the ground that runs under canopy |
| the ground | ISO 9613-2's source, receiver and middle regions, porous by default (`audio.world.ground_g`, 1) | the foliage's middle height, the ears' 1.7 m, the distance along the ground |

At 70 % and 200 m the air takes 15.5 dB at 8 kHz and 1.0 at 1 kHz; 100 m of forest takes 10 dB at 1 kHz and 20 at 8 kHz. **How much of a path is under canopy** is read from the refresh's own crowns: their leaf area binned round the listener by 16 sectors and 15 rings (8 m near, 512 m at the reach), a bin's cover its leaf area over a closed canopy's (a leaf area index of 3.5), capped at one, and a path's metres under canopy the cover summed along its sector out to the crown. So a crown across a clearing is heard through the wood on its own side and not through the open, and a lone tree in a field through almost none. A merged group's leaf area is spread over the bins its disc covers, shared equally by bin count rather than by each bin's ground, so near bins saturate at a cover of one and far ones thin out (a closed wood reads 0.5 to 0.7 two rings out) and a far group's run under canopy is underestimated: weighting the share by a bin's ground is open (S114's review, L1). **The ears' wind carries none**: it is made at the head.

**A crown of its own keeps the path its refresh found** (`Voice::path`), and its needles' tone takes the path at its own frequency, interpolated between the two fixed bands either side of it, every tick. **A bed is summed after the path**, band by band, so the far wood's top is gone before it is summed and the stand round the listener is what a bed mostly holds. A crown chosen as a voice of its own is taken out of its bed again by the same arithmetic it went in with (counted, so an emptied ring is exactly empty).

**A bed hears the gust where its power comes from**, so a far wood swells as the wind crosses it: each bed is three rings — the stand within 32 m, the wood to 128 m and the far wood past it — each with its power-weighted place, and every tick each ring's band powers are scaled by the cube of the gust at its own place. Since the gust is Kaimal's turbulence frozen into the flow and carried down the wind, rings at different distances along the wind hear one gust front at different times, so a bed swells as a front crosses its sector and averages more than one crown does, but does not stand on one place. On the case's wood in ten minutes of 3 m/s wind over a forest's roughness the beds' level spreads 6.6 dB from the 5th to the 95th percentile and the crowns' 11.1; the figure held is the natural ambient's spread Boersma and Etienne's 2.0 to 2.4 dB standard deviation gives (6.6 to 7.9 dB were it Gaussian), with a decibel either side — a search excerpt, said so.

**A merged group is heard over its disc.** The sum was checked first for a tree counted twice — in a crown and again in a bed, or a group's area added twice at a promotion — and none was; a merged group was heard too quietly. Spreading and the path are both convex in distance, so a group summed at its centroid was 3.7 dB under the same crowns sent one by one where engine-view promotes it (its near edge at `audio.world.near_m`). A merged crown with an extent is now the mean of seven points over its disc (the centre at a quarter, six at √(2/3) of the radius at an eighth each, exact to degree five), each at a crown's own least distance: within 0.74 dB of its crowns one by one there. **Nothing is counted twice** in engine-view's table: a group is sent either as its crowns or merged, never both, and a placement's near hand-off forms are left out of a tile (`tile_own`).

**One kind alone**: `audio.world.solo` (0 all, 1 the crowns, 2 the beds, 3 the ears) describes the other kinds as silent, so the kind left sounds exactly as it does in the whole world, with its own choice and its own beds — what the forest's listening by kind needed (it had soloed the beds by setting `audio.world.crowns` to 0, which sent the six nearest crowns into them). `audio.world.path` false takes spreading alone, S112's world, for a comparison.

**A game's clips lose their top with distance too**: the stage builds its mixer with `MixerConfig::air_db_per_m_8k` and `air_db_per_m_1k`, the air's absorption at 8 and 1 kHz at the world's air, and every 3D clip voice passes the mixer's one-pole by distance ([audio](audio.md#distance)). **Its corner is the higher of two fits** (`air_lowpass_coefficient`, `mixer.h`, for r metres and the air's α₈ and α₁ in dB a metre): fc₈ = 8000/√(10^(r α₈/10) − 1), where its loss at 8 kHz is the air's, and fc₁ = 1000/√(10^(r α₁/10) − 1), where its loss at 1 kHz is the air's. One pole falls 6 dB an octave where the air's loss rises about as f², so it cannot follow both: fitted at 8 kHz alone (as S114 landed) it took 20.8 dB at 1 kHz at 500 m against the air's 2.5, and its corner was about 1 Hz at 1 km — thunder, a shot or a bell heard far off all but silenced (S114's review, M3). At 20 °C and 70 % the two fits cross near 125 m; nearer, the 8 kHz fit binds and the top is the air's; farther, **a far clip keeps its middle** (its 1 kHz loss the air's within 0.01 dB, the case, to 5 km) and its top loses less than the air would take (16.6 dB at 8 kHz at 500 m against 38.8) — a choice, said as one on [the grounding page](../experiments/world-sound.md#read-again-by-s114). At 200 m a clip's 8 kHz octave falls 9.4 dB further under its 1 kHz one than at 5 m (the case; 11.3 with the 8 kHz fit alone), and the case derives that figure itself from the two fits (S120): the one-pole's coefficient at 5 and at 200 m from `air_lowpass_coefficient`, its loss over each band's own band-pass response for white noise in, 9.42 dB against 9.44 measured, held to a quarter decibel (a choice), where S114 had moved a pinned window by hand. The scripted session's pin did not move with the floor (its clips are all nearer than the crossing): S114 moved it once, `0x9b8ce750f9dab6e5` to `0x18a7f5169eeef2e6`, taken on MSVC. **Toolchain-identical by construction** (S120): the filter's own arithmetic is `+ - * /`, a square root and ldexp, and the two air figures it is handed are, at the default air (20 °C and 70 %, the tunables' defaults), constants (`path.h`: `k_default_air_db_per_m_8k` = 0x1.3dfc42p-4, 0.0776331 dB a metre, and `_1k` = 0x1.4639cep-8, 0.00497781), the f32 nearest ISO 9613-1's value, which a case holds to the function within an f32 step; `clip_air_db_per_m` hands them on. Until S120 they were the function's through `std::pow` and `std::exp` cast to f32, and the pin held across compilers because the rounding absorbed the C libraries' last bit: the 8 kHz figure's double lies 0.7e-8 of itself from the f32 rounding boundary, so a library that differed by a part in 10^8 would have moved it (S114's review, L4). Another air is still the function's, cast, and is not pinned. The session's pin did not move (`0x18a7f5169eeef2e6`): the constants are the bits the function gave on MSVC. `audio.world.path` off leaves the clips as they were.

**Shelter for the ears' wind** (`ShelterSource`, `SoundStage::set_shelter`): a host's table answers the height of whatever stands at a place over the ground there — a wall's top, a roof, a rock, never the ground's own rise — and at each refresh the stage asks it at 1.5, 3, 6, 12, 24 and 48 m upwind of the listener; the ears' wind at the head is the open wind times the deepest lee any of them gives, as a windbreak's: 0.3 of the open wind to 5 heights downwind of the obstacle, 0.8 at 20 heights, the open wind past 30, linear between (reductions are measurable to 30 heights in a windbreak's lee, the University of Nebraska's page [F]; 80 % of the upwind wind at 20 heights, a review's sentence through a search [S]; **the 0.3 of a solid obstacle's near lee is a choice** no source read gave). The ears' level goes as 40 log of the wind at the head, so the near lee of a wall takes 20.9 dB (the case: a 2 m wall 3 m upwind, and nothing for the same wall downwind). `WorldStats::shelter` (the summary's `world.shelter`) is the last refresh's share. The crowns and beds are not sheltered: a wall does not still the trees above it. **engine-view's table is the walker's collision** (`view::shelter_height_at`, `view::walker_shelter`, `game_sound.cpp`): a session hands the host its walker **while it walks** (`FlySession::walker` without a module, the runner's `GameSound::walker` with one; a session that flies keeps its walker attached, so both sites hand it only when `FlySession::walking`, and a flight's frames and the runner's finish clear it), and each probe is three downward casts (`Walker::cast`) a pace apart across the wind from 20 m over the walker's own feet (`Walker::feet`, crouched or standing), the **least** of what they meet: a wall or a house stands under all three and a trunk's proxy under one at most, so a stand of trees is never taken for a wall and the ears' wind does not drop 21 dB at one step and come back at the next (a case of its own world: the wall found, the trunk not, a wall along the wind not). **What a cast meets is measured over the ground at the probe, never over the feet**: a cast that meets the ground itself (`WalkCast::what` 1, the heightfield) meets no obstacle, and one that meets a placement counts its height over the collision's ground there (`Walker::collision_ground`), so a slope rising into the wind shelters nothing, a wall standing on that slope counts its own height, and a crouch changes nothing (cases: a slope of 1 in 8 and 1 in 4 with and without a wall, and a crouched walker on open ground, which lost the full 20.9 dB when the feet were the drawn eye less the standing eye height). Only where the collision holds no ground under a cast — a scene whose floor is a mesh — is a placement measured over the feet. **What relief does and does not do here**: the shelter figure is a solid obstacle's near lee, so ground — a bank, a ridge, a dune — gives none, and a ridge's own lee (the flow's separation behind a crest) is not modelled; no figure was invented for it. The edge of a roof reads as its height over the ground under it.

**Heard in engine-view, by kind** (2026-11-23; the tree's own flora oaks and firs, a scene wind of 3 m/s over a forest's roughness, a listener standing 60 s, `--audio null --audio-out` offscreen at 640 × 360, the WAV read by octave in one-second blocks on the 105 dB scale; main's binary against this row's, `audio.world.solo` on this row's and on main's the forest's way, `audio.world.crowns` 0 for the beds and `beds` 0 for the crowns): on **a wide wood** (5,625 trees on a jittered 16 m grid, 1.2 km square, 100 cells of 128 m, every sector full) main's beds were **60.0 dBA against 50.4 for the six crowns, 9.6 dB over them** — the forest's 9.8 reproduced — and this row's are **47.8 against 49.7, 1.9 dB under**, the whole world 51.9 dBA against 58.9; on **the 400-tree grove** the beds went from 6.9 dB over the crowns to 3.7. The frame's `world.sound_ms` on the wood (the null backend's mix of the frame's four ticks included, the machine busy) has a median of 0.198 ms against 0.157 (the beds' three rings ask the gust 24 times a tick, not 8) and a p99 of 1.26 against 1.24 (the WAV's flush, as before).

**Why the forest's beds stood still, found on the way: the gust stood when the sun was held** (mended by S118, below). Every reader asked `gfx::wind_gust` at the **sky's** time (`WorldWind::sky_time_s`; the sway's `scene_flora_wind` in `gpu_scene.cpp` likewise), and a session whose day does not run — `--time-rate 0`, the forest's listening runs, and any launch that holds the time of day — holds the sky's time, so the turbulence at every place, heard and drawn, is frozen at one instant: in the runs above every level's 5th to 95th percentile spread over the minute is 0.15 to 0.19 dB, crowns and beds alike, and the stage sent 16 commands in 60 s (the voices' first descriptions, then nothing that moved 1 %). With the sky's clock running the same wood swells as the case shows (beds 6.6 dB, crowns 11.1 over ten minutes). The mean wind following the sky's hour is right (the weather follows the day); its seconds-long turbulence following it is not. Mending it was the sway's and the sound's together — the gust that bends a crown is the gust heard — so it was not done in that row: S118 put the turbulence's time on the world clock (`FrameDesc::world_time_s`, ADR-0056) for both readers.

**The gust on the world clock** (S118). Both readers now ask `gfx::wind_gust` at the world's time and `gfx::wind_at` (the mean and the direction) at the sky's hour: the sway's `renderer::scene_flora_wind(wind, sky_time_s, world_time_s, ...)`, which `GpuScene::flora_frame` and `water_wind_frame` (the frame's wind statistics and the trees' lag) call with the frame's two clocks, and the stage's `WorldField::wind10_at` through `WorldWind::world_time_s`, which engine-view's sound host fills from the same clock the frame draws with: a game module's runner's world time, a flight's `world_rate * frame / 60` (`flythrough.cpp`'s), and a session's `world_rate * t` at its tick. The rule is clocks.h's: a light source is on the sky's clock, a medium that moves is on world time. The other wind readers take no gust: the water's sea is the mean's (its growth law on the world's seconds, its wind record at the sky's quantum), the still lean, the padding's ceiling and the volumetrics read the mean at the sky's hour, and the grass's field block and the poser's flutter were on the world clock already. So a held sky (`--time-rate 0`) still gusts, heard and drawn; a paused world (`--world-rate 0`) holds the gust, as it holds every other motion. **A short day** (a sky faster than the world, `--day-length`): the gust's sines, 0.004 to 0.5 Hz, ran at the sky's rate, so a 20-minute day (72 sky seconds a second) turned a 2-second gust into a 28 ms flicker the trees shook to and the crowns buzzed with; they run at the world's rate now, whatever the day does. The two cases (`flora storm: a held sky still gusts the trees`, `world sound: a held sky still gusts`) hold the sky and see the gust move by values at two world times, and an hour of the sky alone move nothing. A session's sound host still steps its own sums of the sky and the world from its tick (`set_clock`), so a key that changes the world's rate in a window is not yet followed by the ears (it never was by the sky either).

**Not built** (each owed with what it needs): the **barrier term** (`barrier_db` is ISO's form, held by a case; nothing hands the stage a height field yet, so no voice takes it — a host's table of ground heights along a path, as the canopy is a table, is what it needs); refraction (S110 left it out and so does this); and **the forest staging's walk with `--audio null`**, the budget measured on the forest (voices and beds in use, commands a tick, the audio thread's microseconds a block): owed, since on 2026-11-23 the staging's copy would not load (its ground tiles' archives were gone from its cache; not this row's).

## Running water and the surf (S113)

Roadmap S113, the design's stage 3 ([audio](audio.md#stages)); the sources and every number's mark are [the grounding page](../experiments/world-sound.md#read-again-by-s113). The water is three more kinds of world voice — **a stream's stretch, a fall and a stretch of surf** — made in `src/water_field.cpp` beside the wind's field and refreshed with it, from two more tables a host fills (`world_sound.h`), as the canopy is a table:

| Table | Sends | engine-view's (`game_sound.cpp`) |
|---|---|---|
| `FlowSource` | `Stretch`: two neighbouring stations at the water's surface, the discharge, the level given up between them, the wet width, the Froude number; a fall where a lip meets its foot, and whether the foot lands in water | the scene's solved channels (`SceneWater::channel_source`), each pair of neighbouring stations; a fall's foot lands in water where its solved depth is 0.1 m or more |
| `SurfSource` | `Surf`: where a body's train breaks at the water's level, the shore's direction and the length of it a record stands for, the wave power breaking takes there, the breaking height, the surf similarity, the train's period and its arrival there | the GPU scene's records (`GpuScene::surf_table`, the scan form of `renderer::water_surf_records`): one a 16 m square of a body's depth map where its field loses wave energy, scanned once a body mesh at the upload from the field it built for its waves, and placed by each instance after it (`attach_surf`) |

**What it reads of the water's solve**, named because the channel plan is moving under another row (a lake's outlet): of a channel's description `points` (each y the solved level), `discharge_m3s`, `depth_m`, `wet_left_m`, `wet_right_m`, `froude` and `flags` (`k_channel_fall_lip`, `k_channel_fall_foot`); of a body, the field the GPU scene draws its waves from — the depth, the first train's arrival, the flux's `incident` and `kept` and the foreshore slope (`gfx::k_water_field_channels`' 0, 1, 5, 6 and 3) — and the surface's height and period, through `renderer::water_surface_of`, the GPU scene's own function (moved out of `gpu_scene.cpp` for it). Nothing reads `slope` or `manning_n`, as the water at a point does not.

**The level is the power the water gives up.** A stretch gives up ρ g Q h (its discharge, the level it drops), a fall the same at its height, and a stretch of surf **the flux the field loses there** (M3 of the review): the sea's deep-water flux ρ g² H² T / (64 π) (`surf_power_w_m`) times `incident`² times the fall of `kept`² along the train's ray from each texel's upwind neighbours (water_flux.h: `kept` is the square root of what breaking left), summed over the cell's texels and divided by its width. `kept` falls where the field's Battjes and Janssen bore takes energy, at each wave of the group against 0.78 of the depth — the ratio the picture draws white water by (`water_bore_foam`) — so a record stands where white water is drawn, a cell that loses nothing is silent (a trough behind a bar carries its kept share level across it), and over a transect the records sum to the flux in less the flux out whatever the cell (the case holds 8, 16 and 64 m cells to a part in 10⁴ on a plane beach, and a lake's records to the same across 8, 16 and 32 m; a cell under a millionth of the deep-water flux across its width, −60 dB, is left silent). Until M3 every 16 m cell shoreward of the break carried the whole `incident`² flux, so a surf zone N cells wide was heard N times over (+6 dB at four). A share of the power is heard in the air, **`k_water_airborne_efficiency`, 1.75 × 10⁻⁷, a stated choice** anchored on Bolin and Åbom's 60 dB over 0.4 m surf (the grounding page has the arithmetic and what would replace it). **The anchor stands after M3**: its arithmetic took the surf as one line a metre of shore giving up the sea's whole flux, which is what a body's records now sum to where its train breaks out (the flux in less what reaches the waterline), so Bolin and Åbom's 0.4 m sea is still 60 dB at 20 m and their 2.0 m sea 77.0 against their 78; the efficiency was not re-derived. What moved is the surf heard: a shore's records total that one line and no longer the cells' count of it. A stretch and a stretch of surf are **lines**, a fall a point: a line of W′ watts a metre over the ground is heard at W′ θ / (2 π r), θ the angle it subtends and r the perpendicular distance to it (3 dB a doubling near, 6 far), at least the half wet width or 1 m; a fall W / (2 π r²), at least 2 m. A level in dB SPL is the intensity over 10⁻¹² W/m², on the stage's one scale (`reference_db`). **A fall is capped as a plunge pool caps**: its power is counted to a unit discharge of 0.5 m²/s over its lip's wet width and held there (a choice for a threshold the abstracts name and do not give). The width is taken as at least 0.1 m, so **a channel whose solve writes no wet widths** (`wet_left_m`, `wet_right_m` empty: engine-view's table reads 0) caps every fall at 0.05 m³/s and is heard quieter than its flow says. Then **the path**, as a crown's: the air over the whole path, the forest over its share under canopy, the ground's term from 0.2 m over a stream and 0.5 m over a fall's foot or the surf.

**The spectrum is bubbles.** Bubbles over the Hinze scale (about 1 mm) number as a^(−10/3) and under it as a^(−3/2) (Deane and Stokes); with a bubble's energy taken as its surface area (**a choice**: no source read gives a bubble's radiated energy against its radius), the power an octave of radius carries rises 1 dB an octave to the Hinze scale's ring and falls 4.5 dB an octave over it; were it the bubble's volume instead, the rise would be 4 dB an octave and the fall 1.5, each kind's level unchanged (the shape is normalised) and only its balance between the low and the high octaves moved. A stream rings at 3.26 kHz (Minnaert for 1 mm); a fall's ring is lowered as the cube root of 1 + Q (**a choice**: no source read gives a plunge's bubble sizes against its flow; were it wrong, a large fall's peak would stand an octave or so from where it is, its power unchanged) and it lands with 7.5 dB more on the 250 Hz to 2 kHz octaves on water or 5 dB more on 4 and 8 kHz on the bed (Galbrun's 5 to 10 and 5), its power kept; the surf rings at 1 kHz to a breaking height of 1 m and lower, an octave over the next metre, to 325 Hz at 2 m (Bolin's figure as Tollefsen reads it), and a surging breaker (ξ over 2) gives a quarter of the power.

**The surf sounds each wave as it breaks**: a stretch's power follows the train's phase at its break, φ = frac((t − arrival) / T) at the water's clock t, rising over the last 5 % of a period as the crest arrives and falling as e^(−φ / 0.25) through its bore, divided by its mean so a period's power is the law's. The clock is the world clock (`WorldWind::water_time_s`, which the join of S113 and S118 keeps apart from the gust's `world_time_s`, wrapped as the resolve's is, `gfx::water_clock`) and the arrival is the field's own, so **the wave heard breaking is the wave drawn breaking**: the case holds the loudest tick of each period within a tick of the crest. engine-view sets the clock from a session's ticks or a flight's frames, which is the world clock at a world rate of one; a session that changes the world's rate is heard off its picture until a row hands the stage the frame's own clock. A body with no train (no wind, no swell: `water_swash_numbers`' run-up 0) sends no record.

**A trickle is separate bubbles** (the voice's struck resonators, [audio](audio.md#the-shaped-noise-voice)): a stream's share heard as bubbles is all of it under 2 L/s and none over 20 L/s, linear between, at 15 a second for each L/s and at most 60, each a radius drawn from Deane and Stokes' two slopes between 0.25 and 5 mm by the voice's own xorshift (seeded by the stretch), ringing at Minnaert's frequency for it with van den Doel's damping, 0.043 f + 0.0014 f^1.5 a second, through the path at its frequency, and carrying an equal share of the power. Their power is counted in the voice's level, so a voice that is only bubbles sounds and a promotion keeps its power; the bubbles' clock is the stage's own ticks (they are not the picture's). The bubble's rise in pitch as it nears the surface (van den Doel's 0.075 of the damping) is not built: a resonator's pitch is fixed.

**The voices and the LOD**: `audio.world.streams` (4), `falls` (4) and `surf` (3), each kind's loudest at a refresh, a chosen one kept across 3 dB of hysteresis, keyed by place; everything not chosen goes into its sector's bed by power band by band (the surf at its mean over a period), placed and spread with the wind's, the wind not moving it; a chosen one is taken out of its bed again by the same arithmetic it went in with, so **its power is kept across a promotion** (a case: the beds and the water's voices summed with four streams chosen and with none, equal to 0.001 dB). At most `audio.world.max_water` (4,096) stretches and surf records are kept a refresh, the nearest when the table sends more (`water_dropped`, in the summary's world block, counts the sources sent past the cap: one a source whichever goes, the new one or the farthest kept that it replaces); **a stream or a stretch of surf farther than `audio.world.water_reach_m` (800 m) is not taken** (a fall is, to `reach_m`), and one whose level before its path is 20 dB under `floor_db` is left out before its path is taken. engine-view's table **joins a run of stations into one stretch up to 32 m** (`GameSoundHost::k_stretch_join_m`: neighbouring stretches that are not falls and carry the same water within a tenth, their drops summed, the wider wet width kept). Both came from the forest staging's first walk: its solve writes 39,142 stretches of a few metres, all within 2 km were costed every refresh, and every refresh frame's `sound_ms` stood at 10 to 25 ms ("Heard", below). Water voices play on `ambient` at priority 45, between a crown's and a bed's. They are appended after the ears in the stage's voice list, so the indices S112 and S114 gave stand. `audio.world.solo` 4, 5 and 6 hear the streams, the falls or the surf alone. **No flow and no sea state hold no voice**: a stretch that gives up nothing (a still pool, a film) and a record with no power are not taken. **An unchanged world sends nothing** but the surf's envelope, which moves with every wave, and a trickle's strikes.

**What the cases measured** (`tests/world_water_tests.cpp`, the path off where a law is held): a stream of 0.5 m³/s down a 2 % reach, 5 m off the middle of a 10 m stretch, **58.9 dB SPL**, the law's to a part in 10⁴, and 3.01 dB more for twice the flow; a 10 m fall of 0.2 m³/s landing in its pool, 45 m off, **54.2 dB**, 3.01 dB more at 20 m of height, and nothing more past the cap; a lake's lap of 0.1 m at 1.2 s, 5 m from 40 m of its shore, **49.0 dB** over a period against the law's 49.0; 125 bubbles in two seconds from four trickling stretches. ## The refresh off the frame's thread (S122)

Roadmap S122, S113's hand-back: with a sea in earshot a refresh frame's `world.sound_ms` on the forest staging stood at 1.46 ms at the median and 2.22 at p99, all of it on the frame's thread, against the design's 1 ms for a refresh off it ([audio](audio.md#the-budget)). **A refresh is now three parts**, in `world_field.cpp`:

| Part | Thread | What it does |
|---|---|---|
| `gather` | the tick's, at every `refresh_every`th tick (`tick_hz / audio.world.refresh_hz`: 7 at 60 a second, 30 at 240) | walks the host's three tables into **the snapshot** — the crowns kept (`take`, the nearest past `max_crowns`, as before), the stretches and the surf as sent — asks the shelter table its six probes, and copies the voices' current choices (the crowns chosen, each water voice's source) for the hysteresis; then starts `compute`, unless the snapshot is the last one's |
| `compute` | a worker of the host's job system's **Efficiency pool** (`SoundStage::set_jobs`), or the tick's at the gather with none | everything that costs: the cover, every crown's and every water source's power through its path, the beds (into a second set, `beds_next_`), the choice of each kind with its 3 dB of hysteresis, each chosen one taken out of its bed. It reads the snapshot and the field's constants and nothing the tick writes |
| `apply` | the tick's, **at the gather's tick plus `refresh_every / 2`** (3 ticks at 60 a second, 15 at 240; at least one), always that tick | puts the result on the voices (a crown kept on the voice it had, the others silenced, the new ones started), swaps the beds in, sets the shelter and the refresh's counts |

**Why a fixed tick and not "when it is ready"**: the stage's render is the same bytes run after run (the scripted session's pin; a world render is pinned within a toolchain), so when a result lands cannot depend on a thread's timing. A refresh is computed from what was true at its gather and lands at its apply, whoever computed it: the case renders 600 ticks of a walk through a grove and a channel with no job system and three times with a worker, and the four renders are the same bytes, the same commands, the same refreshes. Half a refresh's period is the lag (62.5 ms at 240 Hz): long enough for the worker to finish ahead of it at any frame rate a session runs at (a refresh's compute is a millisecond or two), short enough that a crown is chosen at most 62.5 ms later than before. `apply` always comes before the next `gather` (the lag is at most the period), so the snapshot, the result and the beds the worker writes are never the tick's while it runs. **Every job is a claimer**: a refresh is not held back for the last job to return (one `apply` ran in its place may still be queued behind the pool's page reads — the first staging flight had three frames at 72 to 77 ms on that wait), so whichever job takes the queued state first computes the snapshot of that moment, a stale one finding nothing queued returns, and `finish` waits for them all.

**A late worker is waited for and counted**: at its tick, a result not written is `refresh_late`. If the worker has not begun (the pool busy, the job queued), the tick's thread claims the refresh and computes it itself — an atomic state, queued to claimed, decides which of the two runs it, and the other does nothing — and if it has begun, the tick waits for its state to turn written (an atomic wait, so the frame's thread never runs another job of the pool). Either way the result is the one it would have been. The time the tick spent is `refresh_wait_ns`. The case holds the pool's one worker with a job of its own over the first two refreshes: both are late, the tick computes both (the second gather not waiting on the first's job, still queued behind the held one), and the render is the inline run's bytes.

**A steady world starts no refresh**: `gather` hashes the snapshot, every value `compute` reads (word by word, never a struct's padding), and when it is the last computed one's the refresh is skipped and counted (`refresh_skipped`): the result already applied is that snapshot's. The case: a listener standing in a held wind over a grove and a channel starts two refreshes (the first chooses from nothing, the second keeps what the first chose) and skips every one after, sending no command. The host's tables are still walked (they are the host's, read on its thread), so a steady refresh frame pays the gather alone.

**What the snapshot is**: the listener, the roughness, the shelter's share, the choices (32 crowns and 16 of each water kind, as keys), the crowns as kept (a `Crown` of 48 bytes, with its key and distance), the stretches (72) and the surf (56) as sent. `WorldStats::snapshot_bytes` is its size, the struct's own 720 bytes plus the tables' (a crown 64 with its key and distance): about 60 KB on the forest staging's refresh (the flight below). Its arrays are reserved at `open` (`max_crowns`, `max_water` each) and a table that sends more grows them once, to its high-water mark, so a steady walk allocates nothing (the case: 2,400 ticks with a worker allocate nothing on the tick's thread).

**The host's job system**: engine-view hands the session's sound its `page_jobs` (one Performance and two Efficiency workers, built whatever the flags say: main.cpp) for the life of each loop (`view::SessionSoundJobs`, which hands null back before the pool goes; `SoundStage::set_jobs(nullptr)`, `close` and a stopped stage each wait for a refresh in flight). No thread is the stage's own. A host that hands none — a test, the bench, engine-host — computes the refresh at its gather, on its tick, and hears the same bytes.

**What the summary says** (`world.refresh`): `started`, `on_worker`, `skipped`, `late`, the computes' own mean and longest time (`work_ms_mean`, `work_ms_max`), the tick's thread's `wait_ms` and `snapshot_bytes`.

### The surf joined into lines

The staging's sea sent 316 records in reach a refresh, of which the cull dropped 8, each paying the path. **A host joins a body's records into line sources before the path** (`world_sound::join_surf`, the stage's rule; engine-view's `attach_surf` runs it once per instance at the attach): records in one 64 m square of the world's grid (`k_surf_join_m`) whose shore runs within 22.5° (eighths of a half turn, a shore having no sign), that break alike (a surging breaker, ξ over 2, gives a quarter of its power and never shares a line with a plunging one), at one period and with crests arriving within an eighth of it, are one line. The line runs along the members' power-weighted direction through their power-weighted place, over the span their own lengths cover along it, at their power-weighted height, similarity and phase (a circular mean), and **carries their power, Σ W′ L, spread over its length**; a record alone in its group is kept bit for bit. The lines and their order are a function of the records alone (sorted by the group's key, then the record's index).

**Why a line, and what its law does with distance** ([the grounding page](../experiments/world-sound.md#read-again-by-s122)): the stage already hears a stretch of surf as a finite incoherent line, W′ θ / (2 π r) for θ the angle it subtends and r the perpendicular distance — the half-space form of the finite incoherent line source as practice writes it (Arup's `L_p = L′_W − 8 − 10 log d + 10 log[2 atan(L / 2d)]` broadside, its −8 being 10 log 1/(2π)). Near it (r ≪ L) θ is π and it falls 3 dB a doubling; far (r ≫ L) θ is L / r and it falls 6; the two asymptotes cross at **r = L / π**, where the line is 1.95 dB under the near one (a case holds all three on a 128 m line). That law is additive over collinear pieces end to end, so joining a straight shore's records changes nothing heard with spreading alone (the case: 40 records of 16 m into 10 lines, the same level to 0.01 dB at 5, 60 and 400 m). With the path, a line's terms are taken at its nearest point, so a joined line is heard a little louder than its pieces, whose far ends cross more air and ground: 0.17 dB at 5 m, 0.02 at 60 and 0.01 at 400 on that shore. A 64 m line is at most 64 m long, so its turn from 3 to 6 dB a doubling lies within 20 m of it: from the staging's walk, hundreds of metres off, every line is heard as the point its pieces were.

**What it moved**: on the forest staging's sea 3,920 records (316 in reach at the walk's last refresh) became … lines (… in reach). The flight below has the levels by kind before and after.

### The path's cost (2026-11-23, S114)

The path is taken once a crown a refresh, in dB, then one exponential a band: the ground's eight bands share their exponentials (`ground_bands_db`), Hoover's f^(1/3) and the air's coefficients are the stage's, taken at `open`, and a crown of its own keeps its path between refreshes. `world_sound.world_tick/N` against `world_sound.world_tick_spreading/N` (the same grove and walk with `audio.world.path` off, S112's world), `msvc-release`, **not quiet** (others at 83 % of the CPU, the GPU lock held by another row, the session locked; upper bounds):

| N crowns | path, median µs a tick | spreading alone | the path a refresh (× 7.5 ticks) |
|---|---|---|---|
| 100 | 122.7 | 120.1 | about 0.02 ms |
| 1,000 | 181.4 | 154.9 | about 0.2 ms |
| 8,000 | 557.7 | 341.8 | about 1.6 ms |

**The clips' low-pass** costs the audio thread a recursion a sample: `audio.mix.3d_air/N` against `audio.mix.3d/N` (the same voices with the air off), 179 against 70 µs a block at 64 clip voices and 45.6 against 18.5 at 16 (the same run, others at 16 % of the CPU, the GPU lock held by another row), about 1.7 µs a clip voice a block more — a game's dozen bird calls some 20 µs inside the 200 the audio thread is given; the world's voices pay none (they carry their path in their bands).

About 0.19 µs a crown a refresh: on the forest staging, whose refreshes send about 1,100 crowns, some 0.2 ms more a refresh frame, inside the 1 ms a refresh is given; a table that sent 8,000 would pass it, which `audio.world.near_crowns` and the far field's cells keep a host's table from doing. The first try took each term per band with its own `pow` and `exp` and cost 1.4 ms a tick at 8,000. The merged crowns' seven points cost seven crowns each; a refresh sends a few hundred.

## Capability contract (ADR-0027)

This is a capability: it was added without editing `core/`, `foundation/`, the render graph, the scheduler, or another capability, and it can be removed from the build the same way. Outside its directory it touched only registration points and hosts: the scene schema's block, engine-view's glue (`game_sound.cpp`, the runner's hooks) and the fixture. S112 added two things beside it, each the owning module's own: the shaped-noise voice is `domain/audio`'s (the mixer's voice kind, as the design places it, used by nothing until a command asks), and a mesh's leaves (`SceneData::mesh_leaves`) are the renderer's measure of its scene, which any host may read; the frame record's `FrameWorld::sound_ms` is engine-view's.

| Registration point | This capability | Status |
|---|---|---|
| Capabilities it requires | `engine_capability_requires(world_sound audio)` | declared; off when audio is off |
| Component and event types | `engine.scene.Sound` in `schemas/scene.schema` | done: the scene's, so a build without the capability reads it |
| Tick scheduler entry | none: the host ticks the stage at its session's tick | not needed; sound is presentation |
| Render-graph passes | none | sound draws nothing |
| Content-build derived step | none here; a clip's `.clip` is `audio`'s | not needed |
| Protocol methods | none | not needed yet (engine-host opens no device) |
| Tunables | `audio.world.*` (S112): `crowns`, `beds`, `max_crowns`, `near_m`, `reach_m`, `refresh_hz`, `reference_db`, `ears_db`, `ears_side_db`, `ears_slope_db`, `calm_m_s`, `floor_db`, and since S112-2 `ceiling_db`, `near_crowns`, `walk_instances`, and since S114 `temperature_c`, `humidity`, `ground_g`, `path`, `solo`, and since S113 `streams`, `falls`, `surf`, `max_water`, `water_reach_m` (and `solo` 4 to 6); the mixer's `audio.*` size the rest | done |
| LOD policy | voices by level at the listener, beds by sector, far crowns merged by group in the host's table; the mixer's pool is the budget ([audio](audio.md#the-voice-policy)) | done (S112) |
| Determinism | `world_sound::k_determinism` = `derived` | sound is presentation (ADR-0079 decision 4) |
| Zero cost when unused | `Off` (engine-view's default offscreen, and `--audio off`): no store, mixer, thread or output, no leaves measured at the load and no observer; a stage opened in `Null` or `Device` with the world on builds its mixer whether or not the scene has a `sound` block (S112) | done |
| Tests and size table | `tests/world_sound_tests.cpp`, `tests/world_field_tests.cpp`, `tests/world_path_tests.cpp`, `tests/world_water_tests.cpp`, `tests/world_refresh_tests.cpp`, `tests/size_table.cpp` (`StageStats` 88, `WorldStats` 208 since S122's refresh counts, `Stretch` 72, `Surf` 56) | done |
| Bench | `bench/world_sound_bench.cpp` | done |
| Removal proof | `ENGINE_WITH_WORLD_SOUND`, off in the minimal build | works: engine-view's module then hears `Unsupported` |

**Removing it.** `cmake --preset msvc-minimal` (or `-DENGINE_WITH_WORLD_SOUND=OFF`) drops the module, its tests, and its bench; the module disappears from `build/<preset>/modules.json` and is listed there under `disabled_capabilities`. engine-view then builds without `game_sound.cpp`, its runner has no stage, and a module's three sound calls answer `Unsupported`, as before S111.
