# doc_scene: a document's placements as a renderer scene (systems)

**Purpose.** The bridge from a `doc::Document` to what the renderer draws, and from a transaction to the instances it moved. It is what engine-editor's viewport is built on ([apps](apps.md#engine-editor-the-engines-window-on-a-document)), and what engine-host's `render.load` of a session is built on ([below](#over-the-protocol)).

**Why a module of its own, above both sides.** The renderer reads scenes and must not depend on the document model — its journal, undo and ids ([scene.schema](../../schemas/scene.schema), the header) — and the document model knows nothing of drawing. Nor is the bridge an app's: every host that draws a document needs the same mapping, and a feature only the editor's GUI could reach would be a protocol bug ([06 §6.13](../plan/06-agent-tooling.md#613-human-developer-tooling)). So it sits in `systems/`, depends on `doc` and `renderer`, and holds nothing but the mapping. It is not a capability: it is the engine's one mapping from placement records to instances, with no switch.

## The record type

`engine.scene.MeshPlacement` (`schemas/scene.schema`, `@kind(record)`): `name`, `mesh` (a glTF, GLB or `.clusters` path, relative to the document's directory or absolute), `translation` (`worldpos`, metres), `rotation` (`quat`), `yaw_deg`, `scale` (`vec3?`). It is the scene file's `Instance` as a document record — the "move to documents is an export" that file's header promised — with one difference a document forces: it has no table of meshes to index, so the mesh is named by its path. There was no record type that referred to a mesh before it; `engine.world.Node` and the capabilities' records place things but draw nothing.

**The second record type, the authored ground** (2026-10-17, [tileset](tileset.md#the-record)): `engine.terrain.Heightfield` (`schemas/heightfield.schema`, `@kind(record)`): `name`, `source` (an `engine.terrain.heightfield/1` header, relative to the document's directory or absolute), `origin` (`worldpos`: x and z added to the heightfield's own origin in whole spacings, y to every height; no turn — a heightfield is axis-aligned on the world's grid) and `vertical_scale`. **One live record is the scene's terrain**, and two are refused naming both: one ground per document, today. The header the record names is read here for its extent, before the provider checks the rest, so its sizes are held first to the tile set's own bounds (T190: at most 65,536 points a side, 1,000,000 mm apart, `tileset::k_max_heightfield_side` and `k_max_spacing_mm` repeated because this bridge may not link the capability): a header past them is refused naming both, where `(width - 1) * spacing` used to overflow `i64` first.

## The mapping

**Native ground materials (W68).** `engine.terrain.Heightfield` version 2 adds optional
`materials`, the scene's `TerrainMaterials` block ([renderer](renderer.md#native-authored-terrain-materials)).
Its image paths resolve against the document directory and it passes through to the renderer's
native ground. A material edit rebuilds the scene just as a source edit does; renaming the record
still changes no drawing. Old records without the block keep the existing palette.

- **One live placement is one instance.** `read_document_scene` walks `Document::objects()`, which is sorted by id, so the instance order — and with it every pair and every visibility id — is a function of the document's content alone, never of the order records were made in.
- **One distinct path is one mesh**, in the order the records first name it; every record naming it shares it, so a hundred crates are one mesh's clusters.
- **Placed exactly as a scene file's `Instance`** (`renderer/src/scene.cpp`): the world position whole in `SceneInstance::origin` (ADR-0053: no float on the way to the cell), `yaw_deg` about +y after `rotation`, `scale` when given. A record's unknown properties are left alone — the document validates its records against their types (`Document::validate`), and a viewport that refused to draw a record over a property it does not read would hide the record, not the problem. A placement whose properties do not read as the type is refused with the record's id; one that names no mesh, or an empty one, names no file and is left out and counted in `left_out`, as a placement whose path is refused is ([below](#paths-the-records-hold)).
- **A heightfield record is the scene's terrain**: `DocumentScene::terrain` is the entry it maps to — provider `tiles`, its `tiles` block naming the heightfield resolved against the document's directory, the record's origin and scale — and `desc.terrain` mirrors it in the renderer's fields (enabled, provider, a grid covering the heightfield round the origin at its spacing). `read_document_scene` makes the provider through the scene-generator registry, which **builds the set into the derived-data cache when it is not there** (the content step as a library call, as a mesh's clusters are built on a miss; the cache is the host's, "The ground's root" below) and a hit after; a build without the tile-set capability refuses the record with the registry's sentence, as it refuses a scene naming the provider. This module names no capability: it reaches the set only through the registry. **What the editor draws of it today**: the renderer's terrain description does not carry the entry's `tiles` block into the provider it makes ([tileset](tileset.md#what-the-seam-lacks)), so a viewport loading this scene is refused with the provider's sentence until it does; with it, the editor draws the authored ground with nothing in the editor changed.
- **A document with no placements** is described as the procedural ground alone, whose instance is no record's (`records[i]` null): the viewport still draws, and a pick finds nothing.

## Changes

`changes_since` reads the document's change feed (`Document::changed_since`) from the revision the scene was read at and advances it:

| Change | What the viewport does |
|---|---|
| a placement's `translation`, `rotation`, `yaw_deg` or `scale` | **move** the instance in place (`SceneRenderer::move_instances`): its pairs, mesh and material stay, the next frame draws it where it now stands |
| a placement created, deleted, retyped, or given another `mesh` | **rebuild**: the mesh table or the instance set changed, and with it the pairs |
| the heightfield record's `source`, `origin` or `vertical_scale`, or the record created or deleted | **rebuild**: the scene's terrain and its set |
| the heightfield record's `name` | nothing: it is not drawn |
| a record of any other type | nothing |
| the feed no longer reaches back that far | rebuild |

A rebuild reloads through the derived-data cache, so its cost is the GPU scene's upload, not a content build.

## The ground's root

**The heightfield's set is built and found under the host's derived-data root** (T104, T119; [scene_gen](scene_gen.md#the-derived-data-root)). `read_document_scene` takes the root as a parameter, hands it to the `tiles` provider's `Context` and writes it into the entry's `tiles.ddc`, so the load's own sampler, made later from `desc.terrain`, reads the set the read built. **engine-host's `render.load {"session"}`** passes its `ddc` when the client named one, and otherwise `protocol::derived_data_root`: **the host's own `ddc` root** (the repository's above its executable, named at start), else the session's `<document>/out/ddc` — never `<document>/ddc` or a repository found above the document, which are inside an open document outside its `out/` or under no root at all (T174; [protocol](protocol.md#where-derived-data-goes)); "listen: a session load writes only under out/" holds that end to end. **engine-editor's viewport** passes `scene_gen::document_derived_root(<its --ddc>, <the document's directory>)`, the operator's own process. With none named that is **the document's own**: the repository's `ddc/` above the document's directory, else `<document dir>/ddc` — so a host run from an SDK outside any checkout is never left without a root, where until the night of 2026-11-12 it looked from the executable and, outside a checkout, found nothing; and before T104 the set went to the repository found from the heightfield's directory whatever the host named. The document store reads only its layers' own directories, so a `ddc/` in the document's directory is not taken for one. Only a document with no directory looks from the executable. `heightfield_record_tests.cpp`'s last case holds the named root (the set is a hit there, the document's repository has no `ddc/`); and `scene_gen`'s `derived_root_tests.cpp` every branch.

## Paths the records hold

**Read under a host's roots, a record whose path is refused is left out and counted** (T174; [protocol](protocol.md#paths-a-documents-records-hold)). `read_document_scene`'s last parameter is the host's `const io::Roots*`: engine-host's `render.load {"session"}` passes its `Context::roots`, and the editor's viewport its listener's roots when it serves clients. Every path a record holds that the reader would open — a placement's `mesh`, the ground's `source`, and each ground material layer's `base_color`, `normal`, `roughness`, `mask` and `height` — goes through `io::admit_stored_path` from the document's directory first: portable (`<root>://<relative>` or relative to the document, never absolute) and under a root. **A path named inside a file the record names** is not the record's, and no root says where it leads: the ground's header names its grid in `data`, which is held to the header's own directory lexically — relative, no `..` component, not absolute, no `<root>://`, by the roots' text rules — before the provider opens anything, and a header that names its grid elsewhere has the ground left out and counted like a refused source (T174; written by `tileset::write_heightfield` as a plain name beside the header, so no header this engine writes is refused). **Still open**, read as their file says: a `.gltf` mesh's buffer and image URIs (`assets::load_gltf`), and a `.clusters` container's image paths, which the renderer resolves against the source path the container recorded (`load_cluster_mesh`'s `image_dir` and the image read in `systems/renderer/src/scene.cpp`), so a container from another machine names images wherever its build left them (roadmap T189). The scene names the native path the roots admitted. A placement whose mesh is refused is no instance and nothing opens it; a ground whose source or any image is refused is left out whole, so the scene stands on no terrain; each is one in `DocumentScene::left_out`, which `render.load` answers as `left_out`. The admission is the reader's rather than its caller's because only the reader knows which fields it opens; `domain/protocol/record_paths.h` names the same fields for the write side, which refuses such a path as the record lands. **Without roots** (engine-view, the tools, an editor that serves no client: `--offscreen`, or a window with `--no-shell` and no `--listen`) every path is resolved as written against the document's directory, an absolute one kept: the operator's own reading. A layer's `height` image was left as written until 2026-11-18, read against the process's directory; it is resolved as its four siblings are.

## Testing

`tests/heightfield_record_tests.cpp`, where the tile-set capability is linked: a heightfield record read into the scene's terrain with its set built into the document's cache on the first read and a hit after, its name changed for nothing, its source, origin and scale each a rebuild, deleted and created a rebuild, two refused naming both, a missing source and an origin between its points refused with a sentence; under a host's roots, a header whose `data` is absolute or climbs with `..` has the ground left out and counted, and one naming its grid beside itself is read. `tests/authored_ground_gpu_tests.cpp`, where the tile-set and terrain capabilities are linked, is the authored ground's pixel test ([tileset](tileset.md#the-pixel-test)): offscreen, on the device the GPU lock gives. `systems/doc_scene/tests/doc_scene_tests.cpp`, CPU only, on a document built in memory: placements in id order with a `Node` between them ignored, meshes shared by path and resolved against the document's directory (an absolute path kept), placement as `Instance` (the origin in f64 420 km out, the yaw, the scale); a translation is a move and the description follows it, another type's edit is nothing, a new mesh, a new placement and a deletion are rebuilds; a document with no placements is the stand-in ground with nothing to pick; a placement with no mesh, or an empty one, is left out and counted in `left_out` as a refused path is, and the rest drawn (it failed the whole document's load for every viewer until 2026-11-20); with a host's roots, a placement whose mesh is absolute or outside every root and a ground whose source is outside are left out and counted, the kept mesh named by its admitted native path. The GPU half — picking and moving through a real frame — is engine-editor's test.

## Over the protocol

engine-host's `render.load {"session": <id>}` (2026-10-10, [apps](apps.md#engine-host---listen-the-protocol-over-a-loopback-websocket)) reads a session's document through this module, with the document's directory as the base — the gap this page's "Not yet" named, closed. The host keeps the `DocumentScene` beside the scene it loaded, and a later `render.load` of the same session calls `changes_since` on it: moves become placements written into the host's `SceneData` and, when the GPU scene exists, `SceneRenderer::move_instances`; a rebuild reads the document again into the same scene id. `render.capture` on that scene answers `records` (this module's `DocumentScene::records`, instance to id), so a remote client — the [engine shell](engine_shell.md) first — picks a record from the ids channel exactly as engine-editor's `Viewport::pick` does in process. The editor's viewport is therefore no longer the only thing that can draw a document: anything that speaks the protocol can.
## Not yet

- **Records that place other things**: a scatter and a ruin as document records are the rest of the scene file's types; a placed mesh and an authored heightfield are records today.
- **Sculpting the heightfield in the editor** (roadmap W66's second half): a brush that edits the grid and writes the source back, with undo through the document ([tileset](tileset.md#the-editors-brush-next)).
- **More than one ground**, and a heightfield turned off the world's axes.
- **Hierarchy**: a placement's document parent does not transform it (as `Transform` does not propagate through `ChildOf`, [world.schema](../../schemas/world.schema)); positions are world positions.
- **A dynamic scene's tail.** Moves go through `move_instances`, which moves a scene's loaded instances (in a dynamic scene through the next table flip, since 2026-10-19; in a scene read whole through the next frame's record upload, since 2026-10-22 — neither waits for the device) but refuses a tail slot; a streamed world's instances would move through `set_dynamic_instances` instead.
