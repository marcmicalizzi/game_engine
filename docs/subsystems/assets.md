# assets (domain)

**Purpose.** Source-asset import (docs/plan/07-content-pipeline.md §7.2). glTF 2.0 is the interchange format the plan names for meshes and PBR materials, because every DCC tool, generator, and agent already speaks it. This module turns one glTF file into one plain `MeshData` — positions, normals, UVs, indices, primitive ranges, materials, and undecoded image references — which is exactly the input `geometry::build_clusters` and `geometry::build_cluster_lod` take. It is the front door of the content build; nothing in it touches the GPU.

**What one file becomes.** The default scene (`scene`, or scene 0 when there is none) is traversed recursively. Every primitive of every node's mesh is appended to a single vertex and index space with the node's world transform baked into the positions and the inverse transpose baked into the normals, which are renormalized per vertex because that matrix is not orthonormal under non-uniform scale. Primitives keep their identity as a `Primitive` range into `indices` plus a material index, so a merged mesh can still be drawn or clustered per material. Two primitives that share one POSITION accessor get one vertex block each: the merge is by range, not by deduplication, and the cluster builder's own vertex reuse makes that cheap. `u8`, `u16`, and `u32` index accessors are all widened to `u32`; a primitive with no index accessor gets `0..count-1`. Only triangle topology is accepted — strips, fans, lines, and points fail with an error rather than being converted, because the whole renderer is a triangle cluster pipeline.

**Attributes.** `normals` and `uvs` are either empty or the same length as `positions`, which is what `geometry::AttributeSource` requires; `attribute_source(mesh)` builds one. Empty means no primitive in the file carried that attribute, and the cluster builders then compute smooth normals and leave UVs at zero. A primitive that lacks an attribute other primitives have contributes zeros rather than shortening the stream. TEXCOORD_0 is the only UV set read.

**Materials and images.** `Material` is the metallic-roughness core: base color factor, metallic, roughness, and slots for the base-color and normal images. Images are *not* decoded here. `ImageRef` carries the encoded bytes for GLB buffer views and base64 data URIs and the (percent-decoded) URI for external files, with the media type when the file states one; `foundation/image` and the texture pipeline own decoding. This keeps the import step free of codecs and lets the content build decide what to decode and when.

**Not yet.** Tangents, vertex colors, second UV sets, skins, morph targets, animations, cameras, lights, KHR material extensions beyond metallic-roughness, Draco and meshopt-compressed buffer views (such files are rejected rather than silently wrong), and splitting the merged mesh back into per-node or per-material meshes. A file with no scene is an error, not an implicit "use every mesh".

**Public API.** `domain/assets/gltf.h`: `Material`, `ImageRef`, `Primitive`, `MeshData`, `load_gltf(path, out, error)`, `load_gltf_memory(bytes, base_dir, out, error)`, `attribute_source(mesh)`. Failures return false and fill `error` with a sentence naming the cause; `out` is left empty. There are no exceptions and no logging: a loader reports to its caller.

**Depends on.** `base`, `containers`, `math`, `io`, `geometry`; cgltf v1.15 (MIT, third_party/LICENSES.md), whose implementation is compiled once in `src/gltf.cpp` and whose file reads are routed through `io::read_file` so the module has one way to touch the disk.

**Testing.** `tools/dev.ps1 test -Filter assets`: the fixtures are generated at test time in a temporary directory rather than committed, because a binary in the tree is something no one can review. A unit cube (24 vertices, 36 `u16` indices, per-face normals and UVs, two primitives with two materials, under a child node with a translation and a quarter turn) is written as a `.gltf` plus a `.bin`, as a `.gltf` with a base64 buffer, and as a `.glb` built byte by byte (12-byte header, JSON chunk, BIN chunk), and all three must produce the same mesh: 48 vertices in two blocks, the expected rotated and translated positions, unit-length normals that rotated with the node, UVs inside [0, 1], the materials' factors and image slots, an embedded data-URI image arriving as bytes with its media type, and an external image arriving as a percent-decoded URI. The loaded mesh is then fed to `geometry::build_clusters` with its `AttributeSource`. Negative tests: a missing file, corrupt JSON, a missing external buffer, a triangle-strip primitive, and empty input all fail with a non-empty error and an empty mesh. The size table pins `Primitive` exactly and `Material` around its `std::string`.

**Performance notes.** Import is a content-build step, not a frame-loop one, so it favors clarity: one scratch buffer per accessor reused across primitives, `reserve` before every append, and no attempt to stream. The one number worth watching is that the merged vertex space is capped at `u32`, which the loader checks rather than wrapping.
