# assets (domain)

**Purpose.** Source-asset import (docs/plan/07-content-pipeline.md §7.2). glTF 2.0 is the interchange format the plan names for meshes and PBR materials, because every DCC tool, generator, and agent already speaks it. This module turns one glTF file into one plain `MeshData` — positions, normals, UVs, indices, primitive ranges, materials, and undecoded image references — which is exactly the input `geometry::build_clusters` and `geometry::build_cluster_lod` take. It is the front door of the content build; nothing in it touches the GPU.

**What one file becomes.** The default scene (`scene`, or scene 0 when there is none) is traversed recursively. Every primitive of every node's mesh is appended to a single vertex and index space with the node's world transform baked into the positions and the inverse transpose baked into the normals, which are renormalized per vertex because that matrix is not orthonormal under non-uniform scale. Primitives keep their identity as a `Primitive` range into `indices` plus a material index, so a merged mesh can still be drawn or clustered per material. Two primitives that share one POSITION accessor get one vertex block each: the merge is by range, not by deduplication, and the cluster builder's own vertex reuse makes that cheap. `u8`, `u16`, and `u32` index accessors are all widened to `u32`; a primitive with no index accessor gets `0..count-1`. Only triangle topology is accepted — strips, fans, lines, and points fail with an error rather than being converted, because the whole renderer is a triangle cluster pipeline.

**Attributes.** `normals` and `uvs` are either empty or the same length as `positions`, which is what `geometry::AttributeSource` requires; `attribute_source(mesh)` builds one. Empty means no primitive in the file carried that attribute, and the cluster builders then compute smooth normals and leave UVs at zero. A primitive that lacks an attribute other primitives have contributes zeros rather than shortening the stream. TEXCOORD_0 is the only UV set read.

**Materials and images.** `Material` is the whole metallic-roughness core of glTF 2.0: the base color factor, metallic and roughness, the emissive factor, `normal_scale` from `normalTexture.scale`, `alpha_mode` (`k_alpha_opaque`, `k_alpha_mask`, `k_alpha_blend`) with `alpha_cutoff`, `double_sided`, and five image slots — base color, metallic-roughness (glTF packs roughness in G and metallic in B of one texture), normal, occlusion, and emissive — each an index into `MeshData::images` or −1. **Only `TEXCOORD_0` is read**: a texture bound to any other UV set arrives as −1 rather than being sampled by the one UV set the merged mesh carries, and a material with no normal texture keeps `normal_scale` at 1 instead of the zero cgltf leaves in an unparsed texture view. Images are *not* decoded here. `ImageRef` carries the encoded bytes for GLB buffer views and base64 data URIs and the (percent-decoded) URI for external files, with the media type when the file states one; `foundation/image` and the texture pipeline own decoding. This keeps the import step free of codecs and lets the content build decide what to decode and when.

**Not yet.** Tangents (the material resolve solves a tangent frame per pixel from the triangle's own positions and UVs instead), vertex colors, second UV sets and the textures that name them, texture transforms and per-texture samplers, cameras, lights, KHR material extensions beyond metallic-roughness, Draco and meshopt-compressed buffer views (such files are rejected rather than silently wrong), and splitting the merged mesh back into per-node or per-material meshes. A file with no scene is an error, not an implicit "use every mesh". Skins and animations *are* read — see "Skins and animations" below — but never evaluated here.

**Source hash.** `source_mesh_hash(path, out, error)` is the identity of a source mesh for a content-addressed cache of what is built from it (docs/plan/07-content-pipeline.md §7.3): the file's own bytes through `core/hash`'s `hash_bytes`, mixed with the bytes of every external buffer a `.gltf` names in `buffers[].uri`. A `.glb` carries its buffer inside and a data URI is already part of the text, so neither adds anything; an external buffer that cannot be read contributes an empty one rather than failing, since the load that follows reports it properly and the hash has changed with the glTF that names it anyway. **External** images are deliberately not hashed: a container stores their paths and the renderer reads those files every time, so a repainted texture shows up without a rebuild and would only cost one if the key covered it. An image the file **embeds** needs no special case and gets none — it is part of the file's own bytes, so the hash already covers it, which is what makes the cache key sound now that the container carries those bytes ([geometry](geometry.md), "Embedded images"): change the texture inside a GLB and the entry misses, as it must. It parses but does not load buffers, so it costs one read of the text and one of each `.bin`. `geometry::cluster_cache_key` is what turns it into a cache entry's name.

**Public API.** `domain/assets/gltf.h`: `Material`, `k_alpha_opaque`, `k_alpha_mask`, `k_alpha_blend`, `ImageRef`, `Primitive`, `Node`, `Skin`, `AnimationSampler`, `AnimationChannel`, `Animation`, `k_interp_linear`, `k_interp_step`, `k_interp_cubic`, `k_path_translation`, `k_path_rotation`, `k_path_scale`, `MeshData`, `load_gltf(path, out, error)`, `load_gltf_memory(bytes, base_dir, out, error)`, `source_mesh_hash(path, out, error)`, `attribute_source(mesh)`, `repair_uv_degenerate_triangles(mesh, report, error)`, `weld_vertices(mesh)`. Failures return false and fill `error` with a sentence naming the cause; `out` is left empty. There are no exceptions and no logging: a loader reports to its caller.

**Depends on.** `base`, `containers`, `math`, `hash`, `io`, `geometry`; cgltf v1.15 (MIT, third_party/LICENSES.md), whose implementation is compiled once in `src/gltf.cpp` and whose file reads are routed through `io::read_file` so the module has one way to touch the disk.

**Testing.** `tools/dev.ps1 test -Filter assets`: the fixtures are generated at test time in a temporary directory rather than committed, because a binary in the tree is something no one can review. A unit cube (24 vertices, 36 `u16` indices, per-face normals and UVs, two primitives with two materials, under a child node with a translation and a quarter turn) is written as a `.gltf` plus a `.bin`, as a `.gltf` with a base64 buffer, and as a `.glb` built byte by byte (12-byte header, JSON chunk, BIN chunk), and all three must produce the same mesh: 48 vertices in two blocks, the expected rotated and translated positions, unit-length normals that rotated with the node, UVs inside [0, 1], the materials' factors and all five image slots (one image in two roles keeping one slot, as the usual ORM packing does), the emissive factor, the normal scale, the alpha mode and cutoff, double-sidedness, a texture bound to `TEXCOORD_1` refused as −1, an embedded data-URI image arriving as bytes with its media type, and external images arriving as percent-decoded URIs. The loaded mesh is then fed to `geometry::build_clusters` with its `AttributeSource`. Negative tests: a missing file, corrupt JSON, a missing external buffer, a triangle-strip primitive, and empty input all fail with a non-empty error and an empty mesh. `source_mesh_hash` is pinned against the same fixtures: it is stable across calls, moves when the `.bin` changes although the glTF text does not, moves when the text changes although the buffer does not, differs between the `.gltf` and the `.glb` forms, survives a buffer that is not there, and fails with an untouched output on a missing file and on one that is not a glTF. The size table pins `Primitive` exactly and `Material` around its `std::string`.

**Performance notes.** Import is a content-build step, not a frame-loop one, so it favors clarity: one scratch buffer per accessor reused across primitives, `reserve` before every append, and no attempt to stream. The one number worth watching is that the merged vertex space is capped at `u32`, which the loader checks rather than wrapping.

## Skins and animations

A character is a mesh, a skeleton, and a set of clips, and glTF carries all three. The importer reads them without evaluating anything: `domain/anim` turns what comes out into a `Skeleton`, a `Pose`, and a `Clip`, and the deform pass turns the result into vertices ([04 §4.3](../plan/04-renderer.md#43-geometry), [05 §5.11](../plan/05-simulation.md#511-integration-notes)).

**A skinned primitive stays in bind space.** This is the one place a skinned import is not the rigid one plus extra arrays, and it has to be: glTF places a skinned mesh entirely through its joints, and the spec says the mesh node's own transform is *not* applied. Baking it into the positions — which is what the flattening does for every rigid primitive — would place the mesh twice, once here and once through the joints' model matrices, and the error would be invisible on a rig whose mesh node happens to sit at the origin and obvious on one that does not. So a primitive whose node has a skin keeps its positions and normals exactly as the accessor holds them, and `Primitive::skin` says which primitives those are. The transform that was *not* applied is recorded on `Skin::node_transform` by the first node that instances the skin, because it is otherwise the only thing about a skinned mesh this import would lose, and a tool that wants to plant a character where its author put it needs it.

**The hierarchy.** `MeshData::nodes` is the file's node list with each node's own transform as a `Transform3` and its parent's index — **reordered so a parent always comes before its child**. glTF puts no order on `nodes`, and everything downstream (composing model transforms, retargeting, blending) wants one forward pass rather than a recursive walk, so the topological sort is paid once at import. It is a stable sort by depth, so the result is a function of the file alone. The TRS form is kept rather than a matrix because a joint's node transform *is* its bind pose and every consumer of a bind pose wants rotations and translations; a node written as a matrix is decomposed here (column lengths are the scales, normalized columns the rotation, a negative determinant putting the mirror on x), once, instead of at every pose.

`nodes`, `skins`, and `animations` are populated **only for a file that has a skin or an animation**. A static mesh therefore imports exactly as it did before any of this existed, down to the allocations, which is what the unskinned tests assert.

**The skin.** `Skin::joints` is the palette a vertex's indices name, as node indices; `inverse_bind` is parallel to it and is filled with the identity when the file omits `inverseBindMatrices`, so a consumer never has to ask which form it got; `skeleton_root` is the file's `skeleton` node or −1. A skin is refused when it binds more joints than `geometry::k_max_skin_joints` (256), because that is what a `u8` per-vertex index can name: clamping would attach a limb to the wrong bone and the mesh would look right until it moved.

**The influences.** `JOINTS_0` and `WEIGHTS_0` become one `geometry::SkinBinding` per vertex in `MeshData::skin_bindings`, parallel to `positions`. Joint indices come through `cgltf_accessor_read_uint`, which widens both the `u8` and the `u16` forms exporters write; weights come through the float unpacker, which handles the float and the normalized-integer forms; and `geometry::make_skin_binding` renormalizes the four of them to sum to exactly 255. Four influences is the format's whole budget, and `TEXCOORD`-style second sets (`JOINTS_1`/`WEIGHTS_1`) are not read. A joint index outside the skin's palette fails the load.

A file with several skins keeps each vertex's indices **in its own primitive's skin's palette**: the merge gives every primitive its own vertex block, so a vertex belongs to exactly one primitive and therefore to exactly one skin, and `Primitive::skin` says which. `attribute_source` reports the widest skin as the joint count, which is the bound `geometry::validate_clusters` needs; the content build's per-primitive cluster DAGs keep the palettes apart in practice. A rigid primitive in a file that also has skinned ones contributes the default binding (all weight on joint 0), which is what keeps the stream parallel to the positions.

**The clips.** One `Animation` per glTF animation, holding its samplers and its channels as the file wrote them: `times` in seconds, `values` with three or four floats per key (and three times that for `CUBICSPLINE`, which stores in-tangent, value, and out-tangent), `interpolation` as `k_interp_linear`/`step`/`cubic`, and a `duration` that is the largest keyframe time of any sampler. A channel names a node, a sampler, and one of translation, rotation, scale, or **weights**. Nothing is resampled, retimed, or converted: a curve that was authored at 24 Hz arrives at 24 Hz, and the decision about what to do with it belongs to `domain/anim`.

## Morph targets

One `geometry::MorphChannelSource` per **(mesh, target index)** pair in `MeshData::morph`, holding the POSITION and NORMAL deltas of every primitive of that mesh in the flattened vertex space. Per mesh and not per primitive, because that is what glTF means: within one mesh, target *k* of every primitive is driven by the same entry of the mesh's `weights` array. Per mesh and not globally, because two *different* meshes' targets are unrelated even where they share a name — a head's "smile" and a jacket's are different channels — and the flatten must not merge them; a mesh instanced by two nodes does share one set of channels, and both instances then play the same weights, which is what the format can express today (per-instance `node.weights` overriding the mesh's is a follow-up). Names come from `extras.targetNames` when the file says and are `<mesh>.<k>` when it does not; default weights come from the node's own `weights` if it has them and the mesh's otherwise, which is the order the specification gives. TANGENT deltas are ignored, because nothing downstream carries a tangent — the material resolve solves one per pixel.

**The deltas are transformed, and a normal delta is not a direction.** A rigid primitive's positions are baked into world space, so its position deltas go through the node transform's **linear part** alone. A normal delta, though, is the difference of two unit vectors, and transforming that difference gives the wrong answer under any non-uniform scale: it is recomputed as `normalize(N·(n + dn)) − normalize(N·n)`, which is why the importer keeps the primitive's own untransformed normals beside it while it reads the targets. A skinned primitive's vertices stay in bind space, and so do its deltas.

**Sparsity is lossless.** A delta is kept only when some component survives the stream's own 16-bit quantization — at least half the channel's step, which is its peak over 32767 — so what is dropped is exactly what would have been stored as zero anyway. That is deliberately not a second, invisible tolerance on top of the one [geometry](geometry.md) documents: the sparsity a build reports is then a property of the asset.

**What the Khronos morph samples confirmed** (the four `tools/fetch-samples.ps1` fetches; [apps](apps.md), "The morph samples, end to end"). Default weights come from the **mesh's** `weights` when the node has none — MorphPrimitivesTest's 0.5 and SimpleMorph's two 0.5s arrive as `default_weight` — and a name-less target set is named `<mesh>.<k>` (`mesh.0` for a mesh with no name, `Cube.0` for AnimatedMorphCube). AnimatedMorphCube's targets carry TANGENT deltas, which are ignored as they should be, under a node scaled by 100, which reaches the deltas through the linear part; MorphPrimitivesTest's carry **no NORMAL**, so its channel has no normal array; SimpleMorph has no NORMAL attribute at all and packs its targets as accessors into one buffer view at byte offsets; MorphStressTest names its eight targets in `extras.targetNames` and has three clips. Every one of the three animated files drives `weights` through a channel whose target is the **node**, which is the only place glTF puts it, and `collect_animations` resolved each to the right channel run. None of the four uses a **sparse** accessor, so that path — `cgltf_accessor_unpack_floats` applies the sparse substitution — is still exercised by no real file here. Reading the importer while they went through it found one latent bug no sample has the shape for: a channel's normal deltas are **one array parallel to its vertices or none, across every primitive of the mesh**, and the drop that enforced it only ran for a primitive *lacking* target normals, so a mesh whose first primitive's target had no NORMAL and whose second one's did came out with the array shorter than `vertices`. A primitive's normal deltas now join the channel only when every entry already in it has one; `gltf morph targets: normal deltas stay parallel whichever primitive lacks them` writes both orders. What they did **not** show at the time was the builders' weld, which left every channel in the pre-weld numbering: every container built before cluster cache version 11 carried MorphStressTest's deltas on the wrong vertices at 1,124 of its 1,528 ("The weld" below).
**An animation's `weights` channels** arrive as `k_path_weights` with a **SCALAR** sampler whose output holds one float per morph target per key. The target count is not in the accessor, so it is recovered as `output.count / (input.count × per_key)` and stored in `AnimationSampler::components` — which is why a scalar sampler is now accepted where only three and four components were before. `AnimationChannel::morph_channel` says which entry of the flattened `morph` array the curve's first value per key drives, and that is the one reason `collect_animations` runs **after** the scene walk rather than before it: only the walk knows where each mesh's channels landed. A weights channel whose mesh the default scene never instanced is dropped rather than left pointing at another mesh's rig.

**Testing (skins).** `tools/dev.ps1 test -Filter assets`, `skin_tests.cpp` over the fixture in `skinned_glb.h`: a two-bone bar of six vertices in three rows, its mesh node at x = +5 and its joints at the origin, written as a GLB at test time. The positions come back where the accessor put them rather than five units along x — the bind-space rule as an assertion — with the +5 on `Skin::node_transform`; the node array comes back parent-before-child although the file deliberately writes the mesh node before the deepest joint; the joint palette, the two inverse bind matrices, and the middle row's 127/128 split are checked exactly; the `u16`-joint and normalized-`u8`-weight forms give byte-identical bindings to the float form; the one animation's three samplers come back as LINEAR rotation, STEP translation, and CUBICSPLINE scale with the right value counts and the right target nodes; and the loaded mesh feeds `geometry::build_clusters`, which validates with its binding stream. Two failures are pinned: a `JOINTS_0` index outside the skin's palette, and a skin of 302 joints.

**The UV repair over an imported mesh.** `repair_uv_degenerate_triangles(mesh, report, error)` runs `geometry::repair_uv_degenerate_triangles` ([geometry](geometry.md#uv-degenerate-triangles-the-repair)) over a `MeshData`: one run per primitive, in index order whatever order the file listed them in, a run counted as sampled when its material names any of the five image slots (an untextured primitive is left exactly as the file had it), the normals passed so a folded corner can take its neighbour's, and every primitive's `first_index` and `index_count` rewritten when a triangle is dropped. It lives here rather than in either caller because it has **two** callers that must agree byte for byte — `engine-content build` and the renderer's glTF path behind `engine-view --mesh`, which share derived-data cache entries — and both call it after the load and before the weld. It returns false only for primitives out of order or overlapping, which the importer never produces. **Testing:** `uv_repair_tests.cpp` builds two primitives by hand, one textured and one not, each a quad beside a sliver of no UV area thinner than the grid: only the textured one's sliver is dropped and the second primitive's range moves down by three; and a mesh whose primitives are listed out of index order gets each primitive's own range back.

## The weld

`weld_vertices(mesh)` is `geometry::weld_vertices` over **every per-vertex stream a `MeshData` owns** — positions, normals, UVs, skin bindings and morph channels — and it is the weld both builders of a cluster container run, after the UV repair and before clustering: `engine-content build` and the renderer's glTF path behind `engine-view --mesh`, which share derived-data cache entries and so must build the same bytes. Two vertices merge only when they agree on every stream, so two coincident vertices whose skin weights or morph deltas differ stay two vertices (a morph seam stays a seam, [geometry](geometry.md#morph-channels-the-second-per-vertex-deformation-stream)); unreferenced vertices are dropped; the indices are rewritten in place, so the primitive ranges do not move; and each morph channel's vertex list is renumbered to match. It returns the new vertex count.

**Why it is one function over the struct, and not each builder spelling out the streams.** The weld numbers vertices by first use in the index buffer, so it renumbers nearly every indexed file even when it merges nothing, and a stream it is not handed is left **in the old numbering** while the others move. That has now happened twice. The skin bindings were a parameter neither builder passed for one release (cache version 5 fixed it); the morph channels were one neither builder passed for three (versions 8 to 10), and every container built in that time put a morphed source's deltas on whichever vertices took the old numbers and silently dropped those whose old number was past the welded count — MorphStressTest's on 1,124 of its 1,528 vertices, AnimatedMorphCube's on 10 of 24 ([geometry](geometry.md#morph-channels-the-second-per-vertex-deformation-stream), "The builders' half, which was missing", has the table and why no test saw it). Both times the call site was one line from right and looked right. The builders now hold a `MeshData` and call this, so neither chooses which streams take part, and a stream `MeshData` gains is added here once. Passing an absent stream costs nothing: the weld keys on the skin bindings only when they are parallel to the positions and on the morph channels only when there are some.

**Testing.** `weld_tests.cpp`. A strip of four quads written as a triangle soup in two primitives, after one vertex nothing references, with skin bindings and two channels — one its coincident copies agree on, one they disagree on across the primitive boundary — welds to 12 vertices (the agreeing copies merged, the seam kept, the unreferenced vertex gone), renumbers both channels onto vertices at the right places, and, built into one DAG per primitive exactly as the builders build it, every one of the 24 corners' cluster copies carries its own source vertex's deltas (18 of them non-zero) and its own binding. The comparison is against the mesh **before** the weld, through the map the weld's own index rewrite gives, so nothing of the weld's bookkeeping sits between the two sides. With the builders' old call this case failed 24 assertions — 10 vertices instead of 12, and 33 wrong comparisons on 18 of the 25 source vertices. The second case runs the same check, after the load and the UV repair as both builders run them, over the four Khronos morph samples when `tools/fetch-samples.ps1` has fetched them (it says so and passes when it has not, as CI does; a bundle made with `-WithSamples` carries them): zero wrong on all four, where the old call gave geometry.md's table. `engine-content: a morph delta lands on its own vertex when the weld renumbers` ([apps](apps.md)) holds the engine-content call site itself to the same property, end to end through the container.
