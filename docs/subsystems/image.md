# image (foundation)

**Purpose.** Images in and out of the engine on the CPU. Encoding is dependency-free, for captures, test fixtures, and the screenshots agents look at: `encode_png` writes a PNG whose image data is a zlib stream of stored (uncompressed) deflate blocks, so every decoder reads it and nothing has to be linked, and output is the raw size plus about 1/64. `write_png` does the same to a file through `io::write_file`. Decoding goes the other way through stb_image: `decode_image` turns PNG, JPEG, TGA, or BMP bytes into 8-bit-per-channel pixels in an engine `Vector`, `probe_image` reads only the header, and `read_image` reads a file through `io::read_file` and decodes it. `crc32` and `adler32` are exposed for tests and other containers.

**Why stored blocks.** A 4K RGBA capture becomes a 33 MB PNG in the time of a memcpy and two checksums, which is what a capture path wants; disk size does not matter for a screenshot a test or an agent reads once. Decoding is the other side of that trade: source textures are authored elsewhere and have to be read as they come, so the decoder is a third-party one (stb_image, one translation unit, `STBI_NO_STDIO`) rather than a hand-written parser per format.

**Public API.**

- `foundation/image/png.h`: `encode_png(width, height, channels, pixels, out)` for 1 to 4 channels at 8 bits, `write_png(path, ...)`, `crc32`, `adler32`. `io::Status::InvalidArgument` is returned when the dimensions and byte count disagree.
- `foundation/image/decode.h`: `ImageInfo{width, height, channels}` and `Image{width, height, channels, Vector<u8> pixels}`; `probe_image(bytes, out, error)`, `decode_image(bytes, out, desired_channels = 4, error)`, `read_image(native_path, out, desired_channels = 4, error)`. `desired_channels` of 0 keeps the file's channel count and 1 to 4 converts (gray replicates into RGB, a missing alpha becomes 255). Pixels are always 8 bits per channel, rows top first, tightly packed: a 16-bit PNG is reduced by keeping the high byte, so a sample of 0xABCD decodes to 0xAB. Failures leave `out` empty and fill the error string; `read_image` returns the read's own `io::Status`, `IoError` for bytes that are not a supported image, and `InvalidArgument` for a `desired_channels` above 4 (the file is not touched). stb's buffer is copied into the `Vector` and freed inside the call; nothing of stb's leaks into the API or the include path of other modules.

**Depends on.** `base`, `containers`, `io`; stb_image (pinned by commit in `cmake/EngineImage.cmake`, licensed in `third_party/LICENSES.md`), compiled into `src/decode.cpp` only.

**Testing.** `tools/dev.ps1 test -Filter image`: reference checksum values, a small RGBA image walked chunk by chunk with every CRC verified and the stored stream inflated by hand, a 300×300 gray image spanning several blocks, RGB, argument rejection, and a file round trip; then RGBA, RGB, and gray images encoded and decoded back byte for byte at `desired_channels` 0 and expanded correctly at 4, luminance reduction to one channel, `probe_image` against an encoded PNG, a baseline JPEG written to memory with stb_image_write (a test-only dependency) and decoded back within tolerance, a hand-built 16-bit PNG reduced to its high bytes, `read_image` over a file from `write_png`, and the failures: an empty span, junk bytes, a truncated PNG, an impossible bit depth, a missing file, and an impossible `desired_channels`, each with a non-empty message and an empty `out`. `domain/gfx`'s capture test encodes a GPU capture and `engine-view --capture` writes real frames.

**Not yet.** A real deflate compressor for `encode_png` (the encoder is a memcpy today; shipping assets want a compressor, and the decoder already reads whatever a real one produces). KTX2 containers with the block-compressed formats the GPU actually samples (BC1/BC3/BC5/BC7 on desktop, ASTC later) and the transcoder or offline compressor that fills them, which is where a texture pipeline belongs rather than in a decode-on-load path. EXR and the HDR/float formats for HDR captures. Mipmap generation and resizing (stb_image_resize2 is in the same checkout when that day comes). Animated formats and 16-bit output are out of scope: callers that need more than 8 bits per channel want the texture pipeline, not this module.
